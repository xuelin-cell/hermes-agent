# 云端网盘迁移方案

日期：2026-10-27

状态：页面管理、文件传输和主动对话的 MCP 接入已实现，尚未部署；实现调整与验收见第 14 节。原始方案基于 `cloud-adaptation @ 9a919c0e3d`，包括已同步的 `release @ 16737d22a0`；桌面代码契约已核查，生产网盘接口未实测。

## 1. 推荐结论

沿用分享迁移的路线：复用桌面 React 资料库页面，在浏览器垫片实现已有接口，入口承担账号鉴权、网盘 token 管理和固定业务代调，实例负责自身文件读取、落盘与 agent 执行。

分三期交付：

1. 页面文件管理：目录、容量、搜索、建目录、重命名、移动、回收站。
2. 文件传输与预览：浏览器上传下载、实例产物上传、云端预览。
3. Agent 网盘工具：本轮授权、实例文件传输、加入会话及权限开关。

三期共用同一入口网盘业务层。前两期可独立交付，但只有第三期完成后，才能宣称“agent 可以使用个人网盘”。

继续遵守已确定的凭据方案：完整 MaaS token 保存在浏览器 localStorage，不新增 PG MaaS token 或 token 哈希字段。网盘专用 token 第一版只在入口有界内存中缓存，不返回浏览器或模型。

首期支持个人 MaaS 账号、单入口、每用户一个默认实例。企业平台 token 是否能调用这些服务，需要独立确认，不能按个人 token 默认放行。无人值守定时任务不在本方案首期范围内。

## 2. 已经具备什么，还缺什么

| 部分 | 当前实现 | 本轮要补的内容 |
| --- | --- | --- |

## 3. 桌面版真实契约

### 3.1 页面调用的 bridge

| 接口 | 当前职责 | 云端实现 |
| --- | --- | --- |
| `cloudDriveRequest` | JSON 文件管理和查询 | 垫片请求入口固定 drive 业务接口 |
| `onCloudDriveMutationProgress` | 写操作进入结果核验阶段 | 入口操作状态查询映射为同一通知 |
| `cloudDriveTransfer` | 上传、下载、多文件下载、预览 | 按浏览器文件或实例文件选择不同传输链 |
| `cancelCloudDriveTransfer` | 取消指定传输 | 取消归属于当前登录的操作；结果以服务端最终状态为准 |
| `onCloudDriveProgress` | 传输进度、转换和核验阶段 | 垫片将入口任务状态转换为现有事件 |
| `cloudDriveAgentReady` | 当前 Profile 的 MCP 是否可用 | 第三期探测对应云端工具和授权接入能力 |

现有协议 `uniwork.drive-result.v1` 区分 `failed`、`partial_success`、`outcome_unknown`。云端必须保留，不能把所有超时都变成“失败，请重试”。

### 3.2 实际服务与认证

来源：`apps/desktop/electron/login/cloud-drive.ts`。

| 用途 | 当前固定地址/参数 |
| --- | --- |
| 网盘专用 token | `POST https://www.yjworker.10010.com/app/gateway/uniwork-yunpan/access-token` |
| 换 token 请求体 | `{ phone, appVersion: '0.17.0' }`；桌面当前没有给这一跳添加 MaaS Bearer |
| 网盘业务网关 | `https://maas.ai-yuanjing.com/app/uniwork/general_uniclaw/clouddrive/v1` |
| 业务请求头 | `Authorization: Bearer <MaaS token>` 和 `X-Drive-Access-Token: <网盘 token>` |
| 分片上传 | `/drive/upload-part`，二进制和 `X-Drive-Upload-Metadata` |
| 文件下载 | 查 FileDetails，再取 download plan，只接受固定服务下的 `/drive/content?fid=...` |

这说明“网盘 token 由 MaaS token 换取”只是功能概括，不是当前接口的准确参数描述。入口必须从可信登录上下文取得手机号，不能允许浏览器在网盘请求中任填手机号。

桌面凭据模块本地按七天缓存网盘 token；这是客户端策略，不足以证明上游保证七天有效。云端优先使用上游明确有效期；没有时沿用本地上限策略，并受当前登录有效期限制，遇明确失效按规则恢复。

桌面已支持的业务包括：spaces、usage、capabilities、目录分页、异步搜索及取消、文件详情、建目录、重命名、移动、移入回收站、查询/恢复/彻底删除/清空回收站。清空和批量操作的参数约束应保持一致。

## 4. 凭据与手机号方案

### 4.1 复用登录绑定证明，补手机号

当前 `BrowserIdentity` 只有用户、登录代次、期限、token 和 session 信息；PG 中 `users.masked_phone` 不能还原手机号。

实现采用兼容扩展现有认证加密证明的方式，新增可选手机号字段：

1. 仅在可信短信登录成功后，取这一跳验证过的规范化手机号。
2. 沿用现有 `CredentialCipher`，把手机号与用户、session/token 摘要、登录代次、截止时间一起认证加密进 HttpOnly 证明 cookie。
3. `BrowserAuth.require` 返回服务端内部使用的手机号字段，字段禁止出现在 repr、日志和普通状态响应中。
4. 网盘请求不接收手机号、用户 ID、认证头或任意上游地址。
5. 旧版证明继续支持已有分享；缺手机号时仅网盘提示重新登录，不让整个 app 强制退出。

完整手机号不新增到 localStorage，也不新增 PG 明文字段。证明 cookie 可以跨入口重启验证，避免入口重启后因只剩脱敏手机号而无法重新获得网盘 token。Fernet 加密并不防同源恶意脚本发起操作；沿用的 localStorage token 方案仍要求做好同源内容隔离。

### 4.2 网盘 token 缓存

入口按 `(user_id, session 摘要, login_id)` 分区缓存，设置容量、有效期和并发限制；只在用户实际使用网盘时获取。相同分区并发获取合并成一次，旧登录迟到的响应不能写入新登录缓存。

- 退出、session 失效：清理对应分区，撤销关联传输和 agent 授权。
- 入口重启：缓存丢失；下一次有效请求从证明取手机号，重新获取。
- `DRIVE_AUTH_EXPIRED` 或已核实的供应商失效码：合并恢复一次，有失败冷却。
- 明确 MaaS 登录失效：返回结构化认证错误；网络故障、普通 403、500 或网盘 token 失效不能一律清空 MaaS 登录。
- 写操作即使已经刷新 token，也不能因为响应不确定就重放。先查远端状态核验。

浏览器通用请求函数目前会把入口 401 当作 MaaS 登录失效。实现 drive 时须先规范错误映射：只有当前账号登录失效才用该语义；网盘独立失效、权限不足或服务故障用可区分的业务码。

## 5. 页面文件管理

推荐增加以下固定入口接口，均为设计中的路径，尚未实现：

| 入口路径 | 用途 |
| --- | --- |
| `POST /__entry/drive/request` | 接收现有 `CloudDriveRequest`，验证固定 method/route/body/query 组合 |
| `POST /__entry/drive/operations` | 创建需追踪、核验或耗时较长的操作 |
| `POST /__entry/drive/status` | 按登录归属查询操作进度和最终结果 |
| `POST /__entry/drive/cancel` | 取消本登录操作 |

既有 bridge 的 route 字段只是受限业务选择器：入口固定拼接已知网盘服务，校验解码和规范化后的路径、查询字段、空间和 body，不允许绝对 URL、路径穿越、任意 headers 或通用代理。

界面调整以复用为主：

- 在 browser bridge 增加对应方法，复用列表、搜索、选择、面包屑、回收站和现有通知。
- `CloudDriveTab` 按业务能力呈现；P1/P2 功能未接完时仅禁用缺失动作，不能露出点了必失败的按钮。
- 缓存归属纳入登录代次，切账号清理旧结果并停止旧轮询。
- 网络异常保留现有页面恢复交互；明确权限不足与登录过期的区别。
- 全盘搜索现有工具描述允许约 11 分钟，必须走后台操作与状态查询，不能塞进 nginx 默认 60 秒的单个请求。

## 6. 文件传输：明确三类来源和去向

| 场景 | 数据路径 | 成功条件 |
| --- | --- | --- |
| 电脑文件上传网盘 | 浏览器 File → 入口分片转发 → 网盘 | 上游最终确认，必要时查目录/文件详情核验 |
| 云端产物上传网盘 | 用户实例文件 → 入口分片转发 → 网盘 | 校验源版本与归属，并确认远端对象 |
| 下载到电脑 | 网盘 → 入口 → 浏览器下载 | 区分文件流交付与用户真正保存到磁盘 |
| 加入会话/供 agent 处理 | 网盘 → 入口 → 当前用户实例 | 临时文件完整校验后原子落盘，返回实例路径 |
| 页面预览 | 网盘 → 当前用户实例临时文件 → 现有预览服务 | 内容校验完成，Office 转换等实际成功 |

不能把服务器上的路径返回给浏览器，当作已保存到用户电脑；也不能把浏览器 Blob URL 返回给 agent，当作它可读取的实例文件。

### 6.1 浏览器上传

浏览器使用原生文件选择器，取消不创建远端写入。沿用桌面的 8 MiB 分片作为初始方案，文件大小与类型上限以业务 capabilities 为准，每片与总量同时校验。

拟增加 `drive/upload-start`、`drive/upload-part`、`drive/upload-finish`，以及现有 status/cancel。入口签发操作 ID，绑定用户、登录代次、目标目录和固定文件元信息；浏览器不能自行更改 partIndex/totalPart 等元数据绕过状态检查。

不把完整文件编码为 base64 塞进 JSON，不使用分享的 2 MiB HTML 限额。分片传输需背压、断开取消和大小边界。8 MiB 分片可避开当前 nginx 50 MiB 请求体上限，但 drive 路由仍需关闭请求缓冲并设置适当超时；入口现有 64 MiB 请求体上限不是整文件缓存的理由。

写入超时保留 `outcome_unknown`，核验未完成前不重新创建相同上传。不承诺断网后任意续传；上游缺少幂等键或分片查询契约时，第一版采用明确中止/核验流程。

### 6.2 实例产物上传

沿用当前会话文件读取的归属和路径策略。由实例解析允许的源路径，验证 realpath、符号链接、文件类型、大小和版本，保护凭据目录。入口只拿受限传输句柄，不接收“服务器任意路径”。

分享来源资格与网盘上传资格不同：用户明确选择的普通工作区文件或附件可以上传；不能为了复用分享 API 而把所有非模型生成文件都拦掉。两者共用路径边界，不共用模型生成来源限制。

读取期间校验文件变化，只有快照或稳定版本的完整字节才可确认上传。实例临时快照放在受控目录，取消/完成后清理，不复制整份用户工作区。

### 6.3 下载到浏览器

浏览器导航不能任意添加 Authorization；不把 MaaS token 或网盘 token 塞进 URL。

建议先用带 token 的 POST 创建短期下载操作，再通过同源 POST 表单提交一次性交付票据；入口同时校验原 session、Origin、登录代次、操作归属和票据。票据只绑定固定 asset，不接受下载 URL，消费后不可重放。原生流下载返回安全文件名的 `Content-Disposition`，浏览器不获得上游凭据或 URL。

页面刷新、退出、账号变更应失效未消费票据。小文件可以用 fetch/Blob 兜底，大文件不能整份驻留浏览器或入口内存。

浏览器通常无法证明用户最后保存到了磁盘。现有桌面 `succeeded` 文案是“已保存”，云端应补充明确的交付状态（如 `handed_off`）和“已交给浏览器下载”的文案，并适配共享结果类型/历史列表；不能直接复用“已保存到本机”。批量原生下载逐项记录交付结果，不承诺获得每个文件的磁盘保存结果。若使用可用的文件系统写入 API，才在实际写入完成后报告保存成功，不能依赖该 API 在内网 HTTP 地址上始终可用。

### 6.4 下载到实例与预览

只有固定网盘中转地址可携带两类账号 token；下载 plan 返回的路径按桌面规则严格校验，不跟随任意 CDN 重定向。字节流由入口转给实例的受限接收端，接收端核验实际大小及可用摘要，完成后原子改名，失败删除半成品。

预览文件存入当前用户实例受控临时目录，浏览器通过已有文件/Office 预览 API 查看，预览内容继续使用现有沙箱策略，不能作为可执行 HTML 注入 app 同源页面。建议沿用当前 20 MiB 预览上限，Office 预览继续依赖 Cube 镜像中的 LibreOffice；本机基础 Docker 镜像不具备同等能力。

传输 ID 必须由服务端绑定原始 asset/内容版本，文件路径与句柄不可跨用户使用。实例换代时未完成传输返回失效或未知结果，不默默写到另一实例代次。

## 7. Agent 网盘工具

### 7.1 复用语义，不复制桌面运行环境

保留 `UniWork-Drive` 服务与工具业务语义：`list_files`、`filesearch`、`make_dir`、`rename_file`、`move_files`、`delete_files`、`get_file_info`、`list_recycle_bin`、`restore_files`、`get_capacity`、`download`、`upload`。

桌面 `CloudDriveMcp` 监听 Electron 所在机器的 127.0.0.1，下载工具描述也明确只适用于同机 Hermes，不能把其地址写进云实例配置后宣称可用。云端下载返回实例内路径，上传读取当前实例工作区；工具描述在新会话开始前确定，运行中不更新提示或 schema。

优先使用云端受管 MCP，工具定义复用或抽出纯契约；不新增永久 core tools，也不将 MaaS token 写入 MCP 配置、模型工具参数、终端环境、用户消息或会话数据库。

### 7.2 每轮授权

```text
浏览器带 MaaS token 创建一次性交接票据
  → prompt.submit 的私有传输元数据携带票据
  → 实例在启动该轮前，经受控通道完成原子兑换
  → 绑定用户 / 原登录session / loginId / 实例代次 / profile / 会话 / turn
  → 本轮云盘调用通过实例本地适配器到入口
  → 入口重新核验授权与权限，执行固定网盘操作
```

入口只在有界内存持有当前授权所需 token，授权截止不晚于登录期限；长任务采用仍有效的原登录授权续租，不能借新登录替换原任务身份。原登录到期后要求重新认证并显式恢复。

交接票据不是模型参数，必须在写入历史、调用日志和构建提示之前剥离。普通不使用网盘的聊天不因授权服务故障而失败；用户明确附带网盘引用却无法授权时，应在发送前提示或返回可见的授权错误，不能假装文件已可读取。

首轮没有会话 ID 时由服务端创建后绑定；排队提交、忙碌重试、会话恢复都必须保持同一逻辑提交的授权归属。仅拿传输票据不等于兑换成功；提交被拒绝时不留下可无限使用的授权。

### 7.3 当前 MCP 缺口与实施闸门

代码核查：`tools/mcp_tool_handlers.py` 当前向 `session.call_tool` 提交工具名与 arguments；`tools/mcp_tool_transport.py` 的 headers 主要来自连接配置。已有线程 ContextVar 传播机制不等于已经具备逐轮 MCP 授权传递。

第三期先做两个会话并发的技术验证：让同一用户实例上的 A/B 会话分别携带不同 turn 授权，证明云端 MCP 请求能够准确取得调用者的服务端上下文。不得把“最近一次聊天的授权”放入进程全局或静态 MCP headers。

推荐采用服务端注入的私有调用元数据：从真实工具执行上下文取得授权句柄，传入云端本地 MCP，再由本地适配器去入口；不在 tool inputSchema 中加 token/turn 参数。需要验证当前锁定 MCP SDK 是否支持此元数据通道、跨线程/共享事件循环的上下文行为及日志脱敏。若现有接口不能承载，只增加有实际云端消费者的最小通用传输能力，并先阅读 tools/tui_gateway 对应 AGENTS；不在通用 MCP 代码里按 `UniWork-Drive` 名字写特殊认证分支。

这一项目前没有实现，不以简单添加 ContextVar 作为验收。技术验证失败时先停在前两期可交付范围，修正授权接法后再开启 agent 功能。

### 7.4 实例与入口如何连通

Cube 默认可能拦截实例向入口内网 IP 发起的连接。已有入口访问实例的路径，不能被误认为反向调用也天然可达。

推荐由入口主动建立到实例转发器的认证双向控制通道，复用现有入口到数据面的网络方向；实例工具通过该通道发起受限业务操作，二进制传输使用独立流，避免大文件堵塞授权/取消消息。通道绑定租户、实例代次与独立服务凭据，不向浏览器开放。Docker 与 Cube 都需验证。

如果改用实例主动回调入口，必须额外落实私网放行、可信服务地址、TLS 与实例认证；不能让模型决定入口地址。现有入站实例 token 不自动成为反向身份认证，日志、子进程或持久配置也不能泄露回调凭据。

服务凭据建议由受控转发进程持有，启动 Hermes 时不继承；终端可执行任意代码且与其同权限时，进程隔离不能被夸大为绝对保密，需用实际部署权限验证。授权始终限制操作和生命周期，不能给实例长期整个账号权限。

## 8. 权限开关与会话缓存

沿用当前 Profile 的 `mcp_servers.UniWork-Drive.enabled`，不新增平行开关；保留已有关闭值、tools 过滤和自定义同名服务。服务名和受管标记必须同时匹配，初期云端沿用现有标记需明确这是产品受管身份，不代表依赖桌面运行时。

- 设置仍在“设置 → 安全 → 审批”，名称“允许智能体操控资料库”。
- 关闭后每次 agent 操作在发送上游前实时拒绝，旧会话缓存工具也不能调用成功。
- 长传输/搜索同时监听权限变化，尽力取消后续动作；已被远端接受的写入不能伪称回滚。
- 页面手动网盘操作不受 agent 开关影响；但不能让 agent 利用无授权的手动 API 绕过限制。
- 开启后的工具发现遵循原有新会话生效规则，不中途重建长会话工具 schema 或系统提示；旧会话已有工具时可恢复调用。
- 子 agent 仅继承同租户、允许会话范围和剩余期限；独立定时任务、其他 Profile/实例不继承。
- “加入会话”第三期才开放。保留只加入 asset ID/名称元数据、不立即下载和自动发送的交互；修正当前 `drive-chat-reference.ts` 对 local connection 的硬限制。

## 9. 模块落点与改动范围

以下是实施时的建议拆分，文件名可按最终代码调整，不为本方案先建空模块：

| 位置 | 职责 |
| --- | --- |
| `apps/desktop/src/dev/browser-drive.ts` | bridge 请求、进度、取消、账号代次 |
| `apps/desktop/src/app/artifacts/*` | 复用资料库页面，补能力判断和浏览器文件交付文案 |
| `apps/shared` | 必要的纯业务契约，供 renderer 使用；避免导入 Node/Electron |
| `deploy/hermes-mt/entry/entry/drive_routes.py` | 固定路由、输入与登录归属 |
| `entry/entry/drive_client.py` / `drive_credentials.py` | 固定网关、token、错误与恢复 |
| `entry/entry/drive_transfers.py` | 分片、操作状态、取消和结果核验 |
| 实例侧云端插件 | 工作区文件授权、临时落盘、云端 MCP 适配 |
| `seed/forward.py` 的专题模块 | 受控通道与启动配置，避免继续堆大函数 |
| `tui_gateway` / MCP 调用边界 | 第三期必要的私有元数据与运行上下文传递 |
| `nginx/hermes-mt.conf` | 仅 drive 传输路径的缓冲、超时与大小设置 |

入口继续使用 Python/aiohttp 提供 HTTP 服务。实施时选择将不依赖 Electron 的桌面 TypeScript 协议模块打包为单个私有 Node stdio worker，以复用已有的 token 恢复、写入核验和分片逻辑；不增加另一套 HTTP 服务。Node 仅在入口容器中运行，由入口管理，账号凭据只经私有 stdin 传入。

已有文件的权限处理优先复用；若必须增加实例流式读写端点，只提供当前会话范围的传输句柄，不建设任意路径通用文件代理。

PG 不新增 MaaS 凭据。非敏感传输记录（归属、操作 ID、asset、源版本、结果未知/核验状态）可持久化以支持重启后查询；它们不能恢复授权，也不得保存 token、临时交付票据或上游下载签名链接。入口重启后在途写操作应保持“结果未知/待核验”，用户重新授权后先核验，不自动再上传一份。

## 10. 分期与验收

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| P0：契约确认 | 测试账号实测手机号换 token、业务码、上传/下载协议、token 期限、集群连通 | 确认真实可调用契约；不依赖文档猜测 |
| P1：页面管理 | 扩展登录证明、入口 token 缓存、业务白名单、现有资料库页面 | 两用户隔离；完整文件管理；普通服务故障不清登录 |
| P2：传输预览 | 电脑上传下载、实例产物上传、临时预览、取消/核验 | 二进制有界；来源去向正确；大文件/部分成功/未知结果准确 |
| P3a：授权验证 | 真实 HTTP→WS→任务→MCP→入口通道 | 同用户多会话、A→B→A、队列/恢复/取消不串授权 |
| P3b：Agent 功能 | 云端 MCP、下载到实例、上传产物、加入会话、权限设置 | 模型不见凭据；关闭立即拦旧工具；新会话工具稳定 |

建议下一轮先实施 P0/P1，同时做 P3a 的最小验证以暴露关键风险；P1 可单独部署验证，之后再完成 P2 和 P3b。

P0 的真实测试必须使用明确授权的测试账号与临时文件。未实际调用前，所有服务可用性和响应格式结论都只基于当前桌面源码。

## 11. 验证与部署

必要测试：

- 真实 HTTP、临时 PG 和两个独立实例，覆盖 A→B→A、cookie/token 错配、旧登录迟到响应。
- 旧证明仍可分享；旧账号网盘引导重新登录；新证明中的手机号不能被浏览器替换。
- 网盘 token 过期与 MaaS 失效分别处理，并发只刷新一次，入口重启后可重新获取。
- 目录/回收站分页不能因短页错误结束；重复页、搜索未完和查询失败不声称“文件不存在”。
- 所有写操作只发送一次；丢响应、核验失败、部分完成、取消与重启均不误报成功或盲目重放。
- 实例符号链接越界、跨用户句柄、变化的源文件、半成品、凭据路径均拒绝。
- 大文件传输实测背压、取消和资源占用；浏览器下载不误报已落盘。
- Agent 不携授权、错误实例/turn/profile、重放或到期票据、关闭权限、子 agent 越权均拒绝。
- 真实队列、线程池和共享 MCP loop 上的两会话并发验证；不能只测 ContextVar 单元函数。
- 验证 MaaS/token/手机号不出现在普通状态、模型输入输出、URL、日志、终端环境或 PG 操作记录。
- 前端用 Vitest 与类型检查；Python 一律 `scripts/run_tests.sh`。真实网盘另做发布前小文件上传、下载、删除验收，协议替身不能代替它。

前端、入口、实例插件/转发器应配套发布。P1 仅触及登录/入口/页面时按实际差异构建；P2/P3 改实例文件或种子时更新 overlay 与 Cube 模板，用 `deploy.sh all`。现有实例引导配置须保留网盘权限关闭值，不能换代时默认重新打开。

本机 Docker 可验证大部分管理、传输及授权；Office 转换和 Cube 私网/换代行为需要 Cube 测试环境。部署后记录具体提交和模板 ID，再验真实账号链路。

## 12. 首期明确不承诺的能力

- 不持久化 MaaS token，因此没有用户在线授权时，不保证定时任务和入口重启后的无人值守账号操作。
- 不保证上游缺乏相关契约时的断点续传、任意写请求幂等、精确回滚。
- 不将第三方网盘、企业空间、企业登录凭据默认纳入个人云盘适配。
- 不为赶进度跳过权限开关、并发身份绑定或结果核验。

## 14. 本轮实现与部署要求

2026-10-27，本轮已完成：

- 复用 `CloudLibrary`、产物上传弹窗、传输记录和加入会话交互；生产浏览器 bridge 安装云盘接口，桌面桥不替换。
- 登录关联证明认证加密完整手机号，浏览器不新增手机号存储，PG 不新增 MaaS token 或 token 哈希。
- 入口通过一个私有 Node worker 复用 `CloudDriveClient`、`CloudDriveTransfers`、`executeDriveMcpAction` 和工具参数校验。按登录分区缓存网盘 token，有界容量与空闲淘汰；不采用桌面磁盘凭据存储。
- Python 入口提供固定业务路由、非敏感操作回执、进度查询、取消、浏览器上传分片和一次性文件交付。回执以用户和操作 ID 联合主键隔离，七天保留；入口重启后不会盲目重放写请求。
- 本机文件先分片暂存入口，再由共用桌面客户端上传；实例源经归属、路径与版本校验后导出。下载先落入口受控临时文件，再交浏览器或传入用户实例。采用有界磁盘暂存，没有承诺任意断点续传。
- 单文件暂定最多 512 MiB、预览 20 MiB、浏览器分片 8 MiB；入口传输磁盘预留总额最多 2 GiB，实例文件导出预留最多 512 MiB。上游 capabilities 更小时遵从更小上限。
- 实例 MCP 集成在已有 Hermes HTTP 后端的内部插件中，不为每个用户另起 Node 守护进程，也不开放新的公网端口。入口主动轮询实例的受限请求队列，解决 Cube 实例反向访问入口私网的问题；大型字节不放进控制队列。
- `prompt.submit.execution_metadata` 是新增的可选私有元数据：独立于消息正文，沿排队信封进入真实工作线程；结束后撤销，自动续跑不继承。MCP 配置显式启用此元数据传递，其他 MCP/桌面调用保持原状。
- Grant 同时依赖原登录 session、登录代次、实例进程中的注册、运行会话和真实执行 scope。当前每份最多 15 分钟、每登录最多 8 份。尚未实现长任务自动续租；排队超过期限需重新发起。
- 默认只支持默认 Profile、个人 MaaS 登录、单入口。独立 compute-host 执行不接受本轮授权元数据；无人值守定时任务无授权。
- 权限关闭会拒绝旧工具调用并尽力取消在途传输；可能已提交的写入仍返回结果未知，不伪称撤销。下载到实例的外来文件会保守标记会话上传来源，不能绕过既有分享来源限制。
- 普通实例代理禁止访问内部云盘控制/MCP 路径，并处理多层编码与目录归一化；MaaS token 不转发到实例。
- Docker 旧用户配置同步也会检查平台策略与云盘配置变更，不再只依赖模型端点变化；用户已有的关闭状态和同名自定义服务保留。

构建与部署：

1. `node apps/desktop/scripts/build-cloud-drive.mjs` 生成入口 worker 和实例工具契约；生成物随代码提交，保证入口独立构建可用。服务器 `build-frontend.sh` 已自动执行此步骤。
2. 入口镜像增加 Node 22 运行时及对应共享库；实际 HTTP 入口仍为 aiohttp。
3. 前端、入口、实例模板一起更新。`deploy.sh all` 会按新源码/overlay 构建；新增文件需要先提交并推送到部署分支。
4. 旧登录没有可信手机号字段，首次使用云盘需要重新短信登录；已有分享不因此失效。开发免密登录不能验证真实网盘。
5. 部署后以真实测试账号验目录、上传、下载、预览和 agent 读写，并验证关闭开关后旧会话拒绝访问。

验证覆盖实际 PG、Node 协议 worker、HTTP 实例文件、MCP SDK 握手/调用和真实任务工作线程；上游使用本地协议替身。真实 MaaS/网盘服务及 Cube 环境尚未验收，不把这些本地结果当作生产联调完成。
