# 云端套餐与用量适配（2026-10-27）

## 原有缺口

- 浏览器 bridge 缺少 `getPlanUsage`、`refreshPlanUsage`、`subscribeMaasPlan`，套餐卡片隐藏。
- 入口登录时会读取 `my-plan` 来配置模型，但没有按当前浏览器账号查询套餐展示信息的接口。
- 桌面客户端默认依赖 Electron `net.fetch`，无法直接在入口的 Node 进程加载。
- 订阅依赖可信手机号及一次性市场票据；浏览器异步开窗会被拦截，不能照搬系统浏览器调用。
- 需要处理入口 session 与 MaaS token 不同的到期时间、账号切换和退出后的迟到响应。

## 本轮实现

页面继续复用桌面套餐卡片，不建立第二套用量归一化规则。桌面 `PlanUsageClient`、
`PlanSubscriptionClient` 改为显式注入网络函数；桌面 IPC 仍注入 `net.fetch`，云端入口的既有
私有 Node worker 注入 Node fetch，无需 Electron，不增加用户实例服务。

固定业务接口：

| 接口（POST） | 行为 |
| --- | --- |
| `/hermes/__entry/plan/usage` | 查询套餐；成功结果按登录在内存缓存 30 秒，并合并并发请求 |
| `/hermes/__entry/plan/refresh` | 绕过成功缓存重新查询 |
| `/hermes/__entry/plan/subscribe` | 每次获取新的市场票据，并返回固定市场域名的临时跳转地址 |

所有接口使用现有 cookie session + MaaS Bearer + 加密关联证明；请求前后重新检查 session。
页面不提供上游 URL、手机号、用户 ID 或市场票据。完整手机号从登录时的加密证明取出，
旧证明没有手机号时仍可查用量，订阅要求重新短信登录。

`my-plan` 返回的模型 Key、模型配置、agent 绑定密钥不回到页面，只返回桌面已有的展示白名单。
MaaS token 仍由浏览器 localStorage 保存，不新增数据库 token、token 哈希或套餐缓存表。
Node 缓存只存在入口内存，按登录代次隔离、数量有界；退出清除，同入口网盘共用生命周期管理。
页面匹配的账号到期时间来自 Entry session，而非拿 MaaS token 的到期时间冒充。

浏览器点击订阅时先同步开空白页、断开 opener，再请求票据并跳转。
弹窗被拦截时提示允许弹窗，不获取票据；重复在途点击不重复发起。
跨账号迟到结果及错误市场地址不会跳转；失败关闭空白页。URL 包含市场协议要求的手机号编码
和一次性签名参数，不含 MaaS Bearer，入口不把票据持久化。

返回页面时复用现有聚焦/定时刷新，用户也可手动强制刷新。
“订阅页已打开”不表示支付或订阅成功，结果仍由后续权威套餐查询决定。

## 仍需联调或后续处理的部分

- 本地测试使用协议替身，尚未使用真实 MaaS 账号、真实市场支付或公司集群验收。
- 订阅购买、退款、订单查询等由市场负责，本轮不实现支付后台，也不直接发起购买。
- 套餐展示刷新不等于模型配置同步。模型 Key、模型列表、额度配置变化时，仍通过重新登录
  走既有套餐配置流程。自动刷新并协调活跃实例属于后续工作。
- 独立部署域名的 HTTPS、弹窗策略及市场返回后的实际用量变化需在部署环境验收。
- 无有效浏览器 MaaS 授权时不提供套餐查询；开发免密登录不能替代真实账号验收。

## 发布

配套更新前端、入口镜像和生成的 `cloud-drive-worker.mjs`、`browser-auth.js`。
`build-frontend.sh` 会生成这两项，继续使用 `deploy.sh all --branch cloud-adaptation`。
本轮不新增数据库迁移，不改变用户实例模板。尚未提交或推送的本地修改不会进入服务器部署。
