# 云端技能市场安装与保存确认（2026-10-27）

## 复用与缺口

市场分类、推荐列表、技能详情、实例侧 ZIP 下载/隔离/安全扫描/安装接口原本已存在，
本轮不重做市场，也不放宽包来源、解压或安全扫描规则。
补齐的是浏览器安装入口及“安装成功之前确认保存”的云端链路。

生产浏览器提供 `cloudSkillOperations`，普通开发占位桥仍提示开发中。
资料按当前用户实例查询；卡片继续根据安装记录中的市场 ID 和实际技能名识别已安装，
不拿市场显示名猜安装目录。桌面版不经过新的入口路由。

## 变更与持久化

固定的市场安装、Hub 安装/卸载/更新、技能启停请求转入 Entry 的
`/__entry/skills/start`、`status`、`retry-save`。使用原有 HttpOnly cookie session，
不需要 MaaS token，也不向实例转发浏览器 cookie 或 Bearer。
仅支持当前用户的默认 Profile，不接受任意 URL、实例 ID 或卷路径。
普通后端代理禁止绕过这条链路执行同样的技能变更。

1. Entry 创建有界的后台操作，并向已经选定的用户实例发送原有 REST 请求。
2. ZIP 安装等待原接口完成；Hub 操作等待现有 action 状态结束，保留原返回契约。
3. Cube 后端立即调用已有 `__mt/sync`，核对实例归属、归档名及哈希，然后记下归档摘要。
4. 确认保存后才把原有成功响应交给页面；Hub 原来的 action 状态和失败日志仍决定操作结果。
   Docker 后端整个用户 home 已在持久命名卷中，不额外建立 Cube 归档。

安装、等待和保存期间该用户被排除出入口的空闲暂停回收；页面关闭后已开始的后台操作仍尽力完成。
单用户串行操作，入口同时最多 32 个活跃用户操作；记录最多 128 份、常规保留一小时。
重复的操作 ID 不再次执行写请求。保存失败单独显示，按钮只重试保存，不重新安装。
不确定写入结果时不自动重放，需先刷新检查实例状态。

归档沿用现有 StateManager，包含技能正文、引用文件、安装锁记录及 config.yaml。
成功后实例升级/重建从持久卷恢复；持久卷被删除、损坏或恢复失败不在实例重建保证内。
已有会话不重建提示词，技能按现有规则在新会话生效。

## 边界与验收

- 操作记录在入口内存中，入口重启或记录过期后不能继续查询/重试该记录；此时先检查技能现状，
  不假报成功、不自动重新安装。已经确认的归档不依赖这份操作记录继续存在。
- 保存未确认前实例突发丢失，不承诺这次未确认的安装已持久化；保存成功后以持久卷归档为恢复依据。
- 本轮验证了真实扫描/安装、真实 PG、Entry 与实例 HTTP、文件归档和全新 home 恢复，
  覆盖两个用户 A→B→A、保存失败后仅重试保存、卸载及禁用配置恢复。
  技能包网络边界使用本地测试替身，真实市场下载及 Cube/S3 挂载环境仍需部署后验收。
- 保存重试按钮位于当前页面通知中；刷新页面、退出或入口重启后，先检查现状再操作。

不新增数据库迁移或实例业务接口，适配本身更新前端和入口即可。
与本地 PDF 导出变更一起发布时需要同时更新实例模板，统一用 `deploy.sh all` 按指纹构建。
部署前必须提交推送新增文件；目前运行中的旧版本不会自动获得本地修改。
