# Hermes 云端：沿用 UniClaw 的浏览器 token 方案

日期：2026-10-26

状态：原始实施设计；登录基础能力与页面分享已实现，网盘待接入，尚未部署。
目标：完整 MaaS 登录 token 保存于浏览器 localStorage，支持页面分享，以及用户发起对话后 agent 调用网盘工具；不将完整 MaaS token 加密持久化到 PG，也不新增 PG token 哈希字段。

## 1. 方案结论

采用“浏览器持有 MaaS token，入口按请求使用，本轮 agent 通过受限授权调用入口”的方案。

- 浏览器：登录后保存 token；调用指定入口接口时携带 token。
- 入口：沿用 HttpOnly session cookie，确定当前用户；核验 token 与当前登录的关联，代调固定业务服务。
- 用户实例：负责会话快照、产物来源验证、agent 执行和实例文件操作。
- agent 工具：通过本轮授权请求入口执行网盘操作；模型不接触 MaaS token。
- PG：继续存入口 session、用户、分享记录与操作状态，不新增 MaaS token 或 MaaS token 哈希持久化。

这保留 UniClaw 的凭据持有方式，但不照搬它同一后端进程内的上下文传递。Hermes 的入口与 agent 实例是两个进程，必须补一条受限的跨进程调用链。

首期以用户主动发起的操作为范围。定时任务、入口重启后的无人值守恢复、退出后的账号操作，不默认获得 MaaS 授权。

## 2. UniClaw 已有实现与 Hermes 的差别

核查参考：UniClaw 本地 `cloud-vm-dev @ eed444b2`；Hermes 此轮设计基于当前入口和 bridge 代码，生产部署状态未验证。

UniClaw 已有实现：

1. `useAuth.ts` 将 MaaS 登录 token 存到 `localStorage.auth_token`。
2. HTTP 请求携带 Bearer token。
3. 后端通过请求上下文绑定分享 token 和云盘身份，agent 子任务能继承该上下文。
4. `CloudDriveTool.execute` 读取当前身份并校验工具所属用户。
5. 云盘连接器使用本轮身份和云盘专用访问 token 执行操作。
6. MaaS token 的分享清理缓存仅在内存；云盘专用 token 则有 SQLite 加密存储。不能把两者都描述成只在 localStorage。

Hermes 当前：

- 登录由入口 `static/login.html` 发起，成功后跳进共用前端。
- 入口保存 HttpOnly session cookie，MaaS token 登录后没有继续保存。
- 聊天采用 WebSocket/JSON-RPC，入口转发到用户实例。
- 浏览器 WebSocket API 不能像 fetch 一样任意设置 Authorization 请求头。
- ContextVar 不能跨入口与实例自动传递，也不会自动跨任意线程或进程继承。

因此页面功能可以较直接适配，agent 工具需要独立完成授权传递。不能只在 bridge 的 fetch 中添加请求头，就宣称所有工具已经能使用 token。

## 3. 凭据和状态放在哪里

| 数据 | 位置 | 生命周期 |
|---|---|---|
| MaaS 登录 token | 浏览器 localStorage | 登录时写入，退出/过期清除 |
| MaaS token 的临时副本 | 入口请求内存；agent 执行时为有界授权缓存 | 请求结束或授权到期释放 |
| 入口 session | HttpOnly cookie + 现有 PG session 哈希 | 沿用入口会话机制 |
| token 与登录的关联证明 | 建议新增签名 HttpOnly cookie，见下一节 | 不超过入口 session 与 MaaS token 的有效期 |
| 本轮工具授权 | 入口有界内存；实例受信任运行上下文 | 一轮任务结束、取消、退出或到期失效 |
| 分享归属、期限、发布状态 | PG | 持久化，便于撤销及失败重试 |
| 产物来源记录 | 用户实例的持久状态 | 随实例备份/恢复，不能丢失后自动认定可信 |
| 云盘专用 token | 首期入口按身份分区的有界内存缓存 | 到期、退出或服务端失效时清除 |

云盘专用 token 若以后需要持久化，可单独评估并复用凭据存储；这不等于决定把 MaaS token 存 PG。本方案第一版不引入该持久化。

## 4. 登录与身份绑定：不新增 PG token 哈希字段

### 4.1 登录流程

1. 浏览器向入口提交短信登录请求。
2. 入口调用 MaaS 登录，取得用户 ID、token 和有效期。
3. 入口沿用现有事务创建 session，返回 token 和有效期；响应禁止缓存，不记录 token 或完整响应体。
4. 登录页写入一个版本化的 localStorage 对象，例如 `hermes.cloud.auth.v1`，包含 token、expiresAt 和用于前端竞态控制的登录代次。
5. 入口原有 HttpOnly session cookie 保持不变，成功后跳进 app。

原始响应、套餐 key 等不因为这次改造一起塞进浏览器。开发登录没有真实 MaaS token，相关业务明确不可用。

### 4.2 为什么需要额外关联检查

Cookie 确定“访问哪个用户实例”，Bearer token 决定“向哪个 MaaS 账号执行操作”。二者不一致时可能出现从 A 的实例读取内容、却发布到 B 的账号。

只检查 token 非空或只解码 JWT 不验签不足以确认这个关联。UniClaw 整条认证链还包含条件性的身份验证，不能仅凭 gateway_auth.py 的解码操作判断所有部署的安全性。

### 4.3 建议：登录时签发关联证明，存签名 cookie

为了不新增 PG 字段，建议入口在完成可信的 MaaS 登录后签发一个 HttpOnly 的关联证明 cookie。证明内容包括版本、MaaS 用户 ID、入口 session 的摘要、MaaS token 的 SHA-256 摘要和截止时间，并由入口密钥认证签名。

业务请求同时携带：已有 session cookie、关联证明 cookie、Bearer token。入口验证：

- session 在 PG 中仍有效；
- 证明签名与截止时间有效；
- 证明中的用户和 session 与当前请求一致；
- Bearer token 的摘要与证明匹配。

证明不含完整 token，也不新增 PG token 哈希列；token 摘要仍用于绑定，但存在客户端不可修改的签名证明里。这是 Hermes 适配建议，不是 UniClaw 现有实现。证明不能替代 session，也不能单独用于调用 MaaS。

签名密钥只在入口服务端保存，多副本一致；从现有部署密钥管理扩展，采用标准签名实现，不手写密码算法。Cookie 的 Secure、SameSite、Path 与现有入口的 HTTPS、反代和 base_path 配置一致。没有有效 session 的旧证明一律拒绝。

备选：如果 MaaS 已有正式的 token 身份校验接口，可以校验后比较用户归属，避免新增证明 cookie。但该接口当前未确认，不能先假定存在。若选择此备选，单独评估调用延迟和短期缓存。

## 5. 页面业务：指定接口携带 token

在浏览器侧增加一个小型凭据模块，由登录页和 app 遵循同一存储格式。登录页不是同一构建入口时，确保格式契约有测试覆盖。

共享能力：读取、有效期检查、写入、清理，以及向固定入口业务路径发送请求。不要扩展为给所有 fetch 自动添加 token。

请求例子，均为拟新增接口：

- `/__entry/conversation-shares/*`
- `/__entry/artifact-shares/*`
- `/__entry/drive/*`
- `/__entry/turn-authorizations/*`

规则：

- 仅向固定同源路径发送 Bearer token，同时带现有 cookie。
- 避免认证头随重定向流向其他地址；上游代调也使用固定地址并拒绝非预期重定向。
- 入口依据 session 确定用户，不允许页面指定任意用户或目标 URL。
- 401 或明确认证失效才清理相应登录状态；普通超时和 500 不视为 token 失效。MaaS 部分接口历史上存在用 500 表示认证错误的情况，需要确认业务错误契约。
- 调用前后检查登录代次；旧账号的迟到结果不得清除新账号凭据或写进新账号页面。
- 多标签页监听 storage 变化；账号变更时取消旧操作并重新建立连接。
- 新增业务路径沿用并验证 Origin/CSRF 检查，不只依赖 localStorage 的 token。

当前入口通用 REST 代理复制大部分请求头。实现时应检查并阻止 MaaS Authorization 意外进入通用实例代理；需要实例原有认证的其他路径不能被盲目全局删除，必须按入口路径与认证职责区分。

## 6. 会话分享

保留现有语义和页面渲染器：

1. 页面调用 prepare，入口验证身份与会话归属。
2. 入口向当前用户实例的会话分享插件读取结构化快照，创建短期准备票据。
3. 页面使用现有渲染器生成 HTML；图片通过票据读取，只允许快照登记的资源并校验摘要。
4. 页面携带 token、票据和 HTML 调 publish。
5. 入口再次读取快照，确认版本未变，检查大小与静态 HTML 约束，再向分享网关上传。
6. PG 保存用户归属、稳定分享 ID、待确认/发布/撤销状态；重试保持同一对象和原始内容。

HTML 是页面渲染的；结构化快照来自实例。票据不允许跨用户使用，不能只凭浏览器提交的 HTML 或 sessionId 发布。保留现有 2 MB 上限和不可变会话快照语义。

入口重启导致准备票据失效时，让用户重新准备；已经上传但结果不确定的对象依赖持久记录恢复，而不是创建重复对象。

## 7. 产物分享

- 复用现有分享弹窗与 HTML/Markdown 处理。
- 实例插件记录模型生成来源、上传标记、父子会话关系和文件摘要。
- 入口发布前向对应实例校验来源与版本，结果绑定本次内容；不接受浏览器自报的“可发布”。
- 保留现有上传文件、派生产物、来源不明和内容变化时的限制。
- 入口统一执行上传、更新、撤销和期限状态管理，PG 保存归属与恢复记录。

模型调用 publish_artifact 与页面点击分享可共用发布服务，但模型调用必须走下一节的本轮授权。不要为了跑通第一版而跳过来源插件。

### 已落地的 Agent 发布链路

云端 `conversation_share` 插件复用桌面 `publish_artifact` 工具、Markdown 渲染和来源钩子，工具仍归属 `desktop_ui`，不加入核心工具集。

1. 浏览器在提交回合前，携带现有 cookie 和 MaaS Bearer 请求 `artifact-shares/grant`。
2. 入口把短期随机授权绑定到登录会话、用户实例和运行时会话；浏览器仅将 `cloud_share` 授权放进 `execution_metadata`，不写入提示词或历史。
3. 工具在实例中核验产物来源并冻结 HTML/Markdown 内容，通过实例内队列提交发布请求。入口主动拉取队列，复用页面分享的发布服务，再次核验来源、上传到固定分享网关并保存 PG 分享记录。
4. 工具收到正式 URL、版本和有效期后返回。完整 MaaS token 只在浏览器和入口之间使用，不进入用户实例；分享授权独立于网盘权限。

授权最长 15 分钟且不超过登录 token 有效期，回合结束、退出登录或入口停止后失效。失败或结果不确定时应检查分享面板，不改走 OSS 绕过来源校验。入口重启后需重新发起回合。

升级需要同时更新入口、前端和实例模板；仅刷新前端不能给旧实例补上 Agent 工具。工具集在新会话生效，验证时创建新会话，生成 HTML/Markdown 后再请求“帮我分享为公网链接”。HTTP 内网页面的分享摘要计算兼容没有 `crypto.subtle` 的浏览器环境。

## 8. agent 网盘工具：如何跨入口与实例传递身份

### 8.1 推荐：入口持 token，实例只持本轮受限授权

不把 MaaS token 放进用户消息、模型上下文、工具参数、会话数据库、命令行或实例通用环境变量。

建议链路：

```text
浏览器携带 MaaS token 请求本轮授权
    → 入口验证 session 与 token 的关联
    → 入口创建短期授权，内存持有本轮 token
    → 实例在服务端接收并绑定授权到确定的一轮任务
    → agent 工具经受控通道调用入口
    → 入口确认实例、用户、任务和允许操作
    → 入口使用本轮 MaaS 身份与云盘专用 token 调连接器
    → 工具把业务结果返回模型
```

授权绑定用户、入口登录会话、实例身份、profile、会话和本轮执行标识，限制业务操作集合与截止时间。不是“某个用户最新登录的 token”全局槽位。

### 8.2 WebSocket/JSON-RPC 的接法

浏览器不能随意设置 WebSocket Authorization 头，不将 MaaS token 放到 WS URL 查询参数。

实施时在发送 prompt 前，通过同源 HTTP 创建一次性的本轮授权交接票据。浏览器只把交接票据作为受控传输元数据提交；实例在正式创建任务时凭自身服务认证兑换授权，再绑定本轮执行 ID。兑换必须原子消费，校验用户/实例/会话并防止重放。

真正供工具调用的内部授权只交付受信任实例执行上下文。交接票据和授权均不进入消息历史、模型输入、日志或终端子进程环境。首轮新会话尚无 sessionId 时，要在服务端会话创建后绑定，再开始具有该授权的工具执行。

具体落点需要沿现有 prompt.submit、session.create 和任务调度链确认，必要时增加最小的私有传输元数据字段；不是新增模型工具或通用认证框架。不修改长会话工具集或系统提示来刷新 token。

后台 asyncio 子任务、线程池、子 agent 和进程边界必须显式测试传播规则。只有同一用户与允许会话范围内的委派任务可以继承；不能只添加一个 ContextVar 就假定所有执行路径都生效。

### 8.3 实例如何认证调用入口

实例出站调用入口需要明确的服务认证；现有“入口访问实例”的 token 不自动证明反方向请求。

实施前核实已有机器间认证是否适用；没有则提供仅限工具回调路径的实例凭据，绑定实例代次与租户并可撤销。入口不得信任实例请求自报的 user_id。工具回调同时验证实例身份和本轮授权，禁止浏览器直接使用回调接口。

同一实例内能执行任意代码的 agent 也是信任边界：服务凭据和本轮 token 不应成为终端可读文件或环境变量。优先由已有受控转发进程/服务持有，工具通过限制操作的本地接口调用；若环境无法隔离，需在实施前明确这一限制，不能声称凭据对任意实例代码不可见。

### 8.4 生命周期与故障

- 当前页关闭：已经接收的本轮任务可在授权期限内继续，页面关闭不等于撤销登录。
- 显式退出、账号禁用：入口失效该会话下的本轮授权，后续账号操作拒绝。
- MaaS token 到期：本轮不能继续调用相关业务，返回重新认证要求。
- 本轮结束/取消：释放授权与 token；清理走服务端任务生命周期回调，并有到期兜底，不能只靠浏览器通知。
- 入口重启：内存授权丢失，相关工具返回授权失效；用户重新发起或明确续接。不能换用其他用户凭据。
- 多副本：首期要明确单入口限制。扩容前选择持有授权的副本路由，或专门的短期共享凭据缓存；单纯粘性浏览器会话不能解决实例回调路由。
- 多轮聊天：每轮绑定自己的授权，不把登录身份永久缓存在长寿命 agent 上。

## 9. 云盘操作与文件传输

复用 UniClaw 的分层思路，不假定 HTTP 契约完全相同：

- MaaS 登录身份用于确认调用者和连接器所需的用户授权。
- 云盘专用 token 通过真实云盘授权接口取得，按用户、登录上下文、服务隔离缓存。
- 连接器只允许明确的 netdrive 操作，不允许模型指定 headers、任意连接账号、任意目标服务或 token。
- 列目录、搜索、建目录等由入口/连接器处理。
- 上传从实例拥有的文件读取；下载写入当前会话允许的实例目录。服务端校验路径、会话归属与实际完成状态。
- 大文件走有界流式传输或经授权的短期传输地址，不把整个文件塞进普通工具 JSON。
- 传输具备取消、超时与失败恢复；只有落盘完成或远端上传确认后才向模型返回成功。

UniClaw 当前换云盘 token 的代码使用服务端授权流程，不能未经核对就描述成“直接把 MaaS Bearer 传到换 token 接口”。迁移前确认手机号/用户身份来源、授权接口、连接器请求头和返回有效期。

## 10. 分享到期清理：第一版的明确限制

推荐先做“持久分享记录 + 用户下次带有效 token 访问时触发有界清理”。已记录的待清理任务能跨入口重启保留；但没有有效用户凭据时不能执行网关删除。

可以附加按用户隔离的有界内存 token 缓存，让在线入口在浏览器关闭后继续尝试清理。该缓存有过期、容量和退出清除规则；同用户多会话不要退出一个就误删其他会话的状态。

两种方式都不保证到期瞬间公网对象失效。token 到期、入口重启或用户长期不回来，都可能延迟删除。产品表述应准确；若要求硬性期限，需要分享服务原生 TTL 或独立受限删除授权。

## 11. 分阶段实施

| 阶段 | 内容 | 验收结果 |
|---|---|---|
| 1：浏览器凭据链 | 登录返回、localStorage、统一请求函数、关联证明、退出与多标签页 | 正确用户可调业务；错配凭据拒绝；不新增 PG token/hash 字段 |
| 2：页面会话分享 | 快照、图片、渲染、发布、列表、撤销、恢复记录 | 分享在实例暂停后仍可访问；撤销失败能重试 |
| 3：页面产物分享 | 实例来源插件、资格校验、发布/更新、期限和访问触发清理 | 未知或上传来源不能绕过；发布内容与校验内容一致 |
| 4：本轮授权通道 | HTTP 交接票据、JSON-RPC 元数据、实例认证、任务上下文 | 模型看不到 token；并发会话和委派不串身份；重启正确报授权失效 |
| 5：agent 网盘工具 | 授权接口、连接器、实例文件传输、取消和恢复 | 对话中能列网盘、上传产物、下载到实例并继续使用 |

阶段 4 的传输/实例隔离验证应尽早做小规模技术验证，避免页面功能完成后才发现环境无法支持。阶段 1～3 可以先交付；不要将阶段 4～5 说成只加几个请求头。

范围外：无人值守定时任务的长期账号授权、入口重启后自动恢复所有业务凭据、浏览器退出后的无限期操作，以及尚未得到服务支持的硬性分享到期保证。

## 12. 验收清单

- 两个真实隔离用户 A→B→A；A cookie+B token、旧证明+新 session 均拒绝。
- 旧标签页不能清除新账号 token 或展示旧账号迟到结果。
- token 不进入浏览器 URL、应用日志、模型输入、工具输出、PG、实例终端环境。
- 并发两个用户、同用户不同会话，工具始终使用本轮身份。
- WebSocket 断线、页面关闭、显式退出、入口重启分别符合既定行为。
- 交接票据一次性使用、超时不可用；任意实例不能兑换其他实例的票据。
- 分享重复点击、上传响应丢失、删除失败保持可恢复状态。
- 网盘来源路径越界、会话不匹配、token 失效和上传未完成不能返回成功。
- Python 用 scripts/run_tests.sh；前端用已有 Vitest；涉及 HTTP/WS、数据库和实例文件的链路需真实集成验证，不能只依赖 mock。
- 发布记录前端、入口与实例镜像版本；旧客户端/旧 session 行为有明确兼容方案。

## 14. 本轮已实现的基础能力（2026-10-26）

本轮完成阶段 1 的登录凭据链，分享和网盘业务留到下一轮：

- 登录响应新增 `maas_auth: {token, expiresAt, loginId}`，禁止缓存；开发登录不返回 MaaS 凭据。
- 登录页和浏览器 bundle 共用 `apps/shared/src/browser-maas-auth.js`，部署构建生成入口 static 副本，localStorage key 为 `hermes.cloud.auth.v1:<base_path>`，部署前缀隔离。
- 复用现有 `CredentialCipher` 签发认证加密的 `<session_cookie_name>_maas` HttpOnly cookie。只包含 session/token 摘要、用户、期限和登录代次，不包含完整 token，不增加数据库字段。
- 新增 `POST /__entry/maas-auth`，校验 cookie session、关联证明、Bearer token 和有效期，只返回授权状态，不返回 token。
- 后续入口业务处理函数可调用 `await self._require_maas(request)`，取得本次 `BrowserIdentity`。该身份的 repr 隐藏 token，仍须禁止记录字段/完整请求头。
- 浏览器业务请求调用 `requestEntryMaas(basePath, path, options)`；只允许固定业务路径，阻止任意 URL 和重定向。接口 401 清理对应登录代次；网络错误或 500 不清理。旧请求不能清除新账号凭据。
- App 读取账号时验证已保存凭据；退出时清浏览器状态和两份 cookie，直接访问 `/logout` 也在登录页清理。其他标签页发生凭据变更时重新加载，避免继续使用旧账号的界面状态。
- 通用实例 REST 代理移除 Authorization，实例仍由已有 `X-Hermes-Session-Token` 认证。MaaS token 不随普通实例请求透传。
- 前端构建指纹纳入共用的 browser-auth.js，避免只更新登录服务却继续部署旧前端 bundle。

旧 session 保持原本聊天能力；使用新账号业务前需要重新登录以取得浏览器凭据及绑定 cookie。入口和浏览器前端需要配套更新。

验证：浏览器凭据/请求行为和现有 bridge 共 38 项通过，TypeScript 检查与生产浏览器构建通过；Python HTTP 登录、A→B→A、错配/篡改/过期、退出和代理隔离测试及现有相关测试共 15 项通过。上一轮真实 PostgreSQL 登录测试曾因数据库未运行而跳过；本轮已用临时 PostgreSQL 补跑通过。

尚未实现：分享/云盘业务接口、上游 token 主动撤销探测、后台 token 缓存、agent 本轮交接票据及实例工具回调。`maas-auth` 校验的是登录绑定与本地有效期，不证明上游 token 尚未被撤销；下一轮业务调用仍需处理上游认证失败。
