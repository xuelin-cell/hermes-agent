# Hermes Guardrail 插件开发计划

更新日期为 2026-11-09。本文按本会话最新确认的四阶段方案修订，供实施和验收使用。

**目标**是先用一条真实规则证明 Hermes 插件链路，再完整迁入 UniClaw 的 guardrail 目录，逐项验证和修正适配问题，最终交付在约定环境中实际生效的 Hermes 插件。插件内部预留跨 Agent 的输入、上下文和决策边界，首个宿主适配器为 Hermes。

**依据**包括本会话需求、附件《Hermes 插件机制调研》、Hermes 开发人员关于优先 plugin 外挂和通用 hook/ctx 的要求，以及实际源码。当前核对 Hermes 为 e83a1e87f2，UniClaw 为 c6a66bbf。与上一版 ac5d0ef895 相比，本次核对的插件分发、工具执行、文件补丁和终端相关实现未变。实施开始时再次固定提交和运行环境。

**源码范围**为 D:/liantong/projects/python/UniClaw/UniClaw/libs/hexagent/hexagent/harness/guardrail。当前含 60 个 Python 文件，并有 sensitive_protection/assets 下的规则数据和来源许可。模块外的 UniClaw 后端安全中心、审计服务、审批页面和 VM 管理按宿主需要重新对接，不能由“目录迁入”自动算作交付。

## 可行性评估与四阶段边界

四阶段方案可行。原目录已有独立决策入口、结构化操作模型、规则注册表和明确返回值。Hermes 提供执行前 pre_tool_call，支持 block 和 approve。主要工作集中在工具参数、真实执行上下文、产品规则以及审批语义的适配。

| 阶段 | 要证明的事实 | 交付与退出条件 |
|---|---|---|
| 一，简单真实插件 | 插件被发现、加载、启用，一条规则在工具执行前命中 | 临时保护目录内的文件未被创建或改写，普通路径正常写入，完整证据可复现 |
| 二，完整模块接入 | 原目录的规则、决策、规范化、资源和依赖均已纳入插件，可以通过 Hermes 适配入口调用 | 文件与规则清单闭合，保留原规则 ID，真实 hook 能调用迁入模块并返回合法决策，未验证能力处于受控测试状态 |
| 三，适配测试与修正 | 每项能力在约定工具、OS、后端及策略下是否有效，有可复现结果 | 逐项归类，适配问题已修正并回归，宿主缺口或不适用项有依据和处置，形成可发布覆盖清单 |
| 四，应用与交付验收 | 已验证能力在实际目标客户端和安装方式下正常生效 | 真实执行、审批、隔离配置、安装升级及业务回归通过，交付验收报告和运行说明 |

阶段二允许建立完整调用骨架并逐步消除耦合。阶段二的“接入通过”仅证明工程和调用关系成立。对实际防护的承诺在阶段三、四形成，避免未验证的豁免或环境假设影响正式任务。

## 全局约束

- 插件以独立仓库 hermes-guardrail 交付，安装到当前 HERMES_HOME 下的插件目录。本文保存在 Hermes 仓库。实现仓库位置在阶段一确定，不把第三方产品代码直接合入 Hermes/plugins。
- 使用原生 plugin.yaml 和 register(ctx)。优先已有公开 hook 或 ctx，缺口必须带真实调用场景，再提交通用扩展。插件运行时不导入 Hermes 私有函数，不新增 Guardrail 专属 core 分支，不替换内置工具。
- 保留完整迁移清单和源文件、原规则 ID、资源许可的溯源关系。阶段二不以删除“难迁移规则”解决兼容问题。去留和等价替换在阶段三逐项登记。
- 行为设置使用 plugins.entries.<id>.settings。配置、缓存、策略和会话授权按当前 Hermes profile 隔离。当前模型工具参数不能声明自己的可信来源、OS 或保护目录。
- 保持会话系统提示词和历史稳定。审批复用 Hermes 原生流程。规则的 ALLOW 仅允许继续宿主流程，Hermes 自身仍执行原有检查。
- 依赖通过 Hermes PM 管理，声明符合仓库约束，避免整包拉入 LangChain 或 UniClaw 产品后端。资源加载改为插件自身命名空间。
- 测试通过 scripts/run_tests.sh，涉及平台差异在真实目标 OS 上验证。使用临时 HERMES_HOME，profile 测试采用 A→B→A。
- 附件以 d8c79e4b6b 为基线。本地 pre_llm_call 当前用于上下文补充，本地未找到附件所述 plugins.isolation: host 实现。执行前阻断以已核实的工具 hook 为入口。

## 通用适配预留

本次在插件内部保留以下三处边界，不增加第二个宿主、网络服务或独立通用 SDK 发布任务。

| 边界 | 负责内容 | 初始实现 |
|---|---|---|
| 操作输入 | 原工具名、参数、调用 ID，以及已转换的操作和全部目标 | Hermes 适配器生成内部请求，复用 RuntimeAction 和既有解析逻辑 |
| 执行上下文与策略 | 执行端 OS、Shell、最终 cwd、工作区、保护目录、规则集合、可信来源、审批策略 | 从宿主可信接口和 profile 配置构造显式快照，缺失值保留为未知 |
| 决策输出 | ALLOW / DENY / ASK、规则 ID、原因、分类 | 使用已有 PermissionDecision 或其精简包装，由 Hermes 映射为 None、block、approve |

插件内拟提供 evaluate_tool_call(request: GuardrailRequest) -> PermissionDecision。GuardrailRequest 包装现有引擎所需的调用、上下文、用户与会话规则及 ASK 策略，字段尽量沿用已有类型。该接口为内部契约，阶段二确定精确字段和错误类型后固定并测试。已有同步引擎继续同步，Hermes 回调按宿主协议调用。

规则模块不引用 Hermes PluginContext、审批对象或 UniClaw 会话对象。宿主适配层负责生命周期、路径提供和审批执行。未来其他 Agent 可实现同样的输入转换与决策执行，届时依据真实第二个消费者抽出公共包。此次保留原 BuildProfile 和规则分组的兼容含义用于对照，宿主上线规则通过明确配置选择，不能自动默认 PRO，也不能把它当作 Hermes profile。

## 文件布局与迁移清单

以下路径以拟创建的独立插件仓库为根。

| 文件或目录 | 职责 |
|---|---|
| plugin.yaml、__init__.py | 元数据、配置声明、注册入口，注册期只装配回调 |
| adapters/hermes.py | 读取 Hermes 调用上下文，转换请求、汇总决策、调用宿主审批 |
| contracts.py | 插件内部请求与异常契约，复用原类型，隔离宿主对象 |
| guardrail/ | 迁入原目录完整结构，逐步改为包内导入和显式依赖 |
| guardrail/sensitive_protection/assets/ | 原规则数据和许可资料，验证插件安装后可读取 |
| docs/migration-inventory.md | 逐文件、规则、辅助能力、资源、原测试和迁移提交映射 |
| docs/capability-matrix.md | 工具 × OS × 后端 × 模式 × 能力的结果、缺口和发布状态 |
| tests/test_plugin_gate.py | 第一条规则的真实加载与副作用断言 |
| tests/guardrail/ | 迁入并适配原模块测试，保留有价值的行为合同 |
| tests/test_hermes_mapping.py、tests/test_hermes_e2e.py | 工具映射、多目标汇总、审批及完整执行验证 |

迁移清单至少覆盖 normalizer、tool_schema、shell_syntax、path_policy、engine、baseline、baseline_rules 全部分类、detectors 全部分类、configurable、context、contract，以及 sensitive_protection。初始统计只用于核对当前来源，测试不冻结文件数或规则数。测试应验证源清单每项均有迁移映射，注册规则均有执行或不适用说明。

## UniClaw 耦合的处理原则

| 方法 | 适用范围 | 判断 |
|---|---|---|
| 去掉 | 目标产品中没有对应行为的产品专属分支或例外 | 阶段二保留可追溯实现，阶段三证明不适用后从 Hermes 活跃路径退出，记录理由。避免直接删除其所属的整类安全保护。 |
| 改为参数 | 保护目录、执行端路径、OS、规则集合等仍有安全意义的信息 | 首选，限于实际迁移需要。参数由可信宿主提供，规则内部不读取启动进程全局环境来代表所有会话。 |
| Hermes 专用 | 工具格式、profile 绑定、配置、生命周期和审批 | 集中在 adapters/hermes.py，维持规则模块可独立调用。 |

具体迁移要求如下。

- HEXAGENT_BUILD_VARIANT 及 Lite/Pro/Server。原定义和规则 ID 保留用于迁移对照，去掉实时环境变量推断。按实际后端选择规则。PRO 的虚拟机假设不能直接应用到本地 Windows，SERVER 也不能代表任意 SSH 环境。
- HEXAGENT_APP_DIR、HEXAGENT_DATA_DIR、便携版和 sys.frozen。由适配器传入受保护目录及明确的例外。保持“保护安装目录”的安全意图，避免自动把整个 HERMES_HOME 设成拒绝访问区域。
- 产品数据目录、技能、MCP 缓存、sessions 清理。逐项辨认保护或放行含义。原例外不自动授予 Hermes。需要等价映射时验证范围、可信身份和路径边界，失败时不得扩大放行范围。
- APPDATA、LOCALAPPDATA、本地脚本读取和 VM 路径。静态上下文由执行端提供。脚本检测需要受控的执行目标读取能力。无法获得目标脚本时标为上下文缺失，按已批准的受控调用错误策略处理。
- 内部 skill、可信 MCP 和 system 来源。由宿主可信调用信息确定。模型仅提交同名工具或 source 参数不能取得豁免。
- 敏感文本模块。完整迁移算法和资源，同时保留它与权限决策的独立入口。当前检测返回包含原文、原值和掩码的 finding，适配层仅对外输出必要摘要，普通日志不得记录原值。决定自动挂载在哪类操作前，明确产品目标及数据流。

## 阶段一 · 一条真实规则证明插件链路

**实施默认建议**为 Windows 本机、单一临时 profile、临时文件工作区和受保护子目录。它利用当前机器验证文件规则；终端、远端和其他 OS 在矩阵中单列。具体验收客户端在实施开始时记录，最低要求为真实 PluginManager 发现和 model_tools 工具分发，再在选定用户入口复测。

- [ ] 固定 Hermes 提交、Python 测试环境和插件仓库位置。按现有插件结构创建最小 plugin.yaml 与 register(ctx)。
- [ ] 使用现有安装目录保护规则的路径判断逻辑，将测试子目录作为受保护根。先写行为测试，确认缺少插件时测试不能得到预期阻断，再完成回调。
- [ ] 从临时 HERMES_HOME 发现、显式启用插件，经真实 write_file 调用验证命中。断言返回阻断原因且目标未产生副作用。
- [ ] 验证正常目录和相似前缀目录写入成功，禁用插件后回到 Hermes 原有行为，再启用后保护恢复。
- [ ] 对可信代码运行 hermes plugins doctor <插件目录> --ci，保存注册结果、调用返回和磁盘前后状态。通过 scripts/run_tests.sh <插件仓库>/tests/test_plugin_gate.py 运行文件粒度测试，确认外部测试根也显式绑定临时 home。
- [ ] 形成阶段一记录，说明入口、调用点、决策、阻断位置和未测环境。只有此阶段通过才开展完整迁移。

## 阶段二 · 完整迁入并接通调用

- [ ] 生成源码文件、规则注册表、检测器分支、辅助 API、数据资源和原测试的迁移清单。每项记录源位置、目标位置、哈希或来源提交、规则 ID 和初始状态。
- [ ] 将整个 guardrail 目录及相关资源纳入独立插件，保留原结构和可追溯来源。改写 hexagent.harness.guardrail 内部绝对导入及资源加载路径，排除运行时对 UniClaw/LangChain 的依赖。
- [ ] 在不预先重写规则算法的前提下，把需要的产品环境读取移动到显式上下文入口。保留原行为对照用例和原规则选择逻辑，避免迁移与业务策略修改混在一次变更中。
- [ ] 实现 contracts.py 与 adapters/hermes.py，让真实 pre_tool_call 经 evaluate_tool_call 调用完整引擎。为 write_file、patch、terminal 及其余已有规则识别的 Hermes 对应工具建立完整映射表。无对应工具明确登记。
- [ ] DENY 返回 block，ASK 返回 approve，ALLOW 返回 None。同时保留 rule_ids 与原因供测试定位。多目标操作的汇总优先级为 DENY > ASK > ALLOW。
- [ ] 配置用户规则、会话规则、ASK 动作和执行上下文的来源，验证注册后能调用、决策类型正确。ASK 未配置默认允许是原实现行为，必须在发布策略中显式处理，不能仅设置 ASK 模式就认为所有黄灯都会询问。
- [ ] 为 sensitive_protection 保留 inspect_sensitive_text 的独立调用及资源读取测试。原始检测器迁入与自动拦截接线分开记录。
- [ ] 以隔离的测试配置控制活跃规则。完整模块可加载并调用，未验证规则或豁免不得在正式用户任务中批量生效。
- [ ] 退出检查要求所有清单项都有目标位置和状态，完整包导入通过，真实 Hermes 调用进入迁入引擎。原测试失败必须分类为路径/接口适配问题、原有失败或语义差异并记录，不能静默跳过。

## 阶段三 · 逐项判断适配性并修正

能力矩阵以规则 ID 或独立 API 为最小条目，至少含原功能、原适用环境、Hermes 工具、执行端、上下文需求、测试、结果、修正和发布状态。下列状态按环境逐项填写，同一规则可在本地可用而在远程等待接口。

| 状态 | 判定依据 | 处理 |
|---|---|---|
| 可直接使用 | 等价输入得到相同决策，真实调用按预期阻断或放行 | 纳入对应环境的验收 |
| 适配后可用 | 工具格式、路径或配置不同，修正后测试证明等价行为 | 保留修正前失败和修正后通过的证据 |
| 等待宿主接口 | 必要上下文、调用时机或最终参数无公开获得途径 | 提交通用 hook/ctx 扩展，或收缩对应环境的承诺 |
| 目标环境不适用 | 依赖 UniClaw 专属运维行为或目标不存在 | 保留原能力与理由，移出该环境启用表 |
| 当前方案无法满足 | 无法在所需副作用前检查，或所需隔离无法由现有接线提供 | 给出技术证据与可选调整，作为明确缺口待决策 |
| 尚未验证 | 尚无足够测试 | 不计入已验证覆盖率 |

“完全不可用”仅在目标和约束明确且有技术证据时判定。缺上下文或缺 hook 通常先属于等待接口，避免提前丢弃可迁移能力。

- [ ] 先跑迁入的行为测试，再按矩阵运行真实 Hermes 工具调用。所有失败逐项分类，按规则族修复并回归。
- [ ] patch 覆盖单路径替换和 V4A 的 Add、Update、Delete、Move 两端。任何目标硬拒绝时阻断整次调用。解析失败的受控操作返回错误决策，不能用空路径视作放行。
- [ ] terminal 核实 Shell、最终 cwd、workdir 优先级和目标路径。文件规则测试路径边界、大小写语义、符号链接和实际执行解析之间的一致性。使用临时目录、无害标记命令及原生 OS 测试，验证副作用是否发生。
- [ ] 网络、数据外发、定时任务、子 Agent、MCP 等能力先核实各自 Hermes 工具与嵌套执行路径。只写在提示词中或挂在可选扫描工具上不能验收为强制执行前防护。
- [ ] 验证硬拒绝先于用户放行，保留 read-only 白名单、可信来源和 ASK 配置在原引擎中的实际优先级。若改变原安全策略，逐项标明前后行为并取得该策略决定，避免把语义变化归为纯适配。
- [ ] 验证审批通过、拒绝、超时和无人值守行为。持久放行键必须绑定被批准范围，避免按整个 terminal 或文件工具授权。会话批准与后续执行须对应同一操作。
- [ ] 检查其他插件修改参数的顺序。当前 pre_tool_call 的 modify 在回调结果收集后合并，需证明检查对象与最终执行对象一致。若无法保证，记录真实复现并扩展通用执行前接口，不通过私有函数或插件专属 core 分支绕过。
- [ ] 对 sensitive_protection 分别验证离线算法、资源、API 及候选接线位置。首选已有明确副作用前检查的外发操作。若要求最终回复或模型请求脱敏，验证流式提前展示和辅助调用覆盖，相关产品策略在此阶段明确。
- [ ] 根据矩阵逐类处理 UniClaw 目录、版本和豁免。修复后重跑对应原用例和 Hermes 路径，形成正式启用表与缺口清单。

## 阶段四 · 实际应用验收

- [ ] 从独立插件仓库安装到隔离 profile，在目标用户入口验证启用、重启、新会话、更新和禁用。确认工具或提示词相关变更遵守 Hermes 会话缓存规则。
- [ ] 每个发布启用的能力都有正常、命中、边界和错误行为证据。决策以外必须检查实际文件、进程标记或受控网络接收端等副作用。
- [ ] 在同一进程服务两个 profile 的条件下做 A→B→A，验证策略、目录、缓存和授权不串用。异常、并发与重试保持调用对应，避免审批后重复执行。
- [ ] 验证回调异常、超时、规则资源缺失、插件未加载、配置损坏和宿主分发异常。当前已注册 pre_tool_call 的异常/超时有阻断处理；插件未加载和宿主分发异常要另验。若要求插件缺失也拒绝执行，必须明确部署检查或通用宿主准入机制。
- [ ] 执行 hermes plugins doctor <插件目录> --ci，按发布要求运行 hermes plugins validate <插件目录>，通过 scripts/run_tests.sh 运行迁移测试、适配测试和受影响宿主测试。
