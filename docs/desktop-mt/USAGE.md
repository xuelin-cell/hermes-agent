# 本地多账号开发版：使用与人工验收

适用范围：Windows、`desktop-mt` 分支、源码开发运行。当前接入的是 MaaS 登录和本机 Hermes，尚未接入多租户云端。自动化与真实账号的验收结论分别记录在[阶段三 P26](03-lifecycle-and-acceptance.md#p26--完整验收与使用说明)，不以自动化通过代替人工验收。

## 打开开发版

本机已有启动入口保持不变，在 PowerShell 执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\stan\Documents\ChatGPT\Uni-Work\Launch-HermesDesktopMT.ps1"
```

这是本机开发脚本，不是官方安装器，也不随分支推送。它调用开发仓库的 `npm run dev`，使用已有 Python 环境和 Git Bash；不要用官方安装器覆盖这个开发目录。保留启动终端，账号退出时开发监督进程还要负责重开 Electron，Vite 继续运行；普通应用退出不会自动重开。

首次打开先显示短信登录页，登录前不启动 Hermes。完成图形验证码、发送短信并登录后，主进程查询套餐、准备当前账号环境，再自动进入原版桌面，不需要额外点击“进入”。完整、未到期的加密登录记录可在下次打开恢复；恢复不延长期限，也不静默刷新 token。

没有套餐或套餐查询失败仍可进入桌面，原版自定义模型能力保留。进入桌面不代表模型一定可用：模型调用仍需对应提供方、Key、网络和平台授权。运行中不自动刷新套餐／Key；需更新时退出账号并重新登录。套餐刷新只维护产品管理的 MaaS 配置，不覆盖个人模型、默认选择、MCP 或 Skills；若选中的 MaaS 模型已退出套餐，需要自行选择有效模型。

## 退出、换账号与后台工作

| 操作 | 实际结果 |
| --- | --- |
| 右下角“账号 \| 退出”并确认 | 停止当前账号的托管工作，清除恢复登录凭据，重开登录页；历史和文件保留 |
| 登录另一个账号 | 打开另一个独立 Home、默认工作区和桌面状态；不导入前一个账号的数据 |
| 再登录原账号 | 按平台身份域和稳定 UID 复用原目录，不以手机号或新 token 新建目录 |
| 开启托盘且托盘可用时关闭主窗 | 只是隐藏，后台工作继续；不是退出账号或退出应用 |
| 托盘菜单退出，或未走托盘隐藏的完整应用退出 | 统一确认并停止托管工作，保留登录记录，不自动重开 |
| 取消退出确认 | 继续使用当前账号，不开始停止事务 |
| 运行中登录到期 | 提示到期，保留账号和退出入口；不自动停止任务、锁定界面或重启 |
| 到期后重新打开 | 不恢复到期身份，要求重新登录，原账号数据保留 |

托盘设置沿用原版外观设置。退出会停止桌面后端、账号及其 Profiles 的消息网关和可确认归属的相关子进程；定时任务定义与工具配置保留。重新运行后的定时补跑沿用原版规则，不保证错过的每次执行都补跑。原版账号网关的自动启动项在退出时禁用／备份，登录不会自动重新启用。

停止失败时只提供“重试／关闭应用”，不允许继续切换账号。关闭应用不等于清理成功；下次打开先处理可信遗留记录，确认停止后才开放登录。仍无法安全处理时保留记录、提示寻求支持，不无限重试。**不要手工删除恢复记录或按名称批量结束所有 Python／Hermes 进程。**

模型 Key 与登录 token 是不同凭据。桌面显示登录到期，不等于 Key 一定同时失效；后续模型调用能否成功以平台实际授权为准。

## 数据存在哪里

默认位置如下；若本机通过启动参数指定独立测试根，实际位置以该次启动根为准。

```text
%LOCALAPPDATA%\hermes-desktop-mt\accounts\account-<完整摘要>\
  hermes-home\       会话、记忆、配置、账号内 Profiles、日志
  workspace\         当前账号的默认工作目录

%APPDATA%\HermesDesktopMT\
  maas-login.enc       系统加密的恢复登录记录
  maas-logout-pending.json
                      运行／退出恢复记录，正常运行时也会存在
  accounts\account-<完整摘要>\desktop-state\
                      连接、默认项目、原生 OAuth、账号文件缓存
  Partitions\hermes-mt-<完整摘要>\
                      Electron 按账号与用途保存的草稿、Cookie 等
```

账号标识由平台身份域和可信 UID 的完整摘要确定。Home 与桌面状态不会因为 Key 更新换位置；浏览器分区摘要还包含用途，因此不能把 `Partitions` 中的摘要直接当作账号 ID。窗口位置、外观、托盘等应用偏好仍可跨账号共用，不属于账号内容泄露。

不要上传 `maas-login.enc`、账号 `.env`、原生 OAuth 文件或浏览器数据库。登录记录使用系统加密，模型 Key 按原版机制存于账号 `.env`，不能将整个账号目录视为全部加密。备份需同时考虑账号 Home、工作区与桌面状态，并保护其中的秘密；本轮没有实现备份／跨电脑恢复工具。

目录隔离是应用层隔离，不是 Windows 安全沙箱。同一 Windows 用户运行的工具可能访问其他目录；主动打开同一个外部项目也会共享该项目文件。官方版固定使用 `X:\HermesOfficial`，开发版不得认领、删除其数据或按名称停止其进程；是否能在实际安装环境中并行稳定运行仍需人工验收。

## 双账号人工验收

准备两个可信 MaaS 账号 A、B，以及各自可用的模型。模型调用可能计费，由你手动执行；无需向开发人员提供短信码、token 或 Key。测试文件仅放在账号默认工作区，不选择同一个外部项目。

1. 登录 A，确认右下角脱敏账号。发一条能识别本次验收的短消息，记下会话是否保存；让工具在默认工作区创建一个无敏感信息的小文件。另建一个不发送的草稿。
2. 如需验收自定义模型，在 A 中配置个人模型并设为默认，记录选中状态，不提交或截图 Key。
3. 点击右下角“退出”并确认。等待自动回到登录页，不直接关闭 PowerShell 终端。观察 A 的托管任务是否确实停止。
4. 登录 B，确认账号显示已变更，A 的会话、文件、草稿、个人模型与账号连接不应出现在 B 中。为 B 分别创建自己的短对话、文件和草稿。
5. 退出 B，再登录 A，确认 A 的会话内容、工作文件、草稿和个人默认模型恢复，B 的内容未混入。再回 B 检查其数据也保留。
6. 开启托盘，运行一个可观察的短任务，关闭窗口后确认任务继续；从托盘恢复，再使用完整退出，确认任务停止。重新打开检查原账号数据保留。
7. 用真实有效但未购买套餐的账号验收自定义模型；若没有这个样本，记为“未验收”，不以套餐请求失败或无 token 请求替代。
8. 如需官方版对照，手动同时打开官方安装版和开发版；在开发版退出／换账号时确认官方版的任务、历史和文件不受影响。不要在个人运行实例上制造崩溃或强制结束试验。

仅记录每项“通过／未通过／未验收”、脱敏账号和发生的现象。真实对话内容、手机号全文、短信码、Key 和 token 不写进提交或验收文档。电脑休眠／唤醒与平台真实到期需要另行安排，不用调整个人系统时间或改真实登录记录来伪造结果。

## 遇到问题

- 启动失败：按提示完整退出，再重新打开。空间不足先释放空间；持续失败保留数据并寻求支持，不自动重置配置或改用官方环境。
- 退出失败：先使用“重试”；选择关闭应用后，下一次打开会先处理原账号工作。若提示无法安全收尾，提供错误发生阶段及脱敏信息，不删除标记来绕过保护。
- 运行日志：账号 `hermes-home\logs\desktop.log`；后端日志也在该 Home 的 `logs` 中。登录前未加载桌面主进程时，先查看启动终端的报错。对外提供日志前检查、去除凭据和会话正文。
- 需要恢复旧无账号开发数据：当前不会自动认领。先单独确定精确导入范围，不能直接覆盖账号 Home。
- 本版本尚未支持多租户云端、会话同步、运行中套餐热更新或账号自定义 Chromium 启动参数；不把原版远程连接设置视为云端适配已完成。开发分支更新应经 Git 审核与提交，不用官方自更新覆盖定制代码。
