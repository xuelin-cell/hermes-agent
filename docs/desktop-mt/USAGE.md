# 本地多账号开发版：使用与人工验收

更新：2026-10-23。适用范围：Windows、`release` 分支、源码开发运行。当前连接 MaaS 和本机 Hermes；独立安装包尚未完成验收。

## 打开开发版

Windows 源码开发版可双击仓库根目录的 `Start-UniWork.cmd`。也可在项目目录用 PowerShell 执行：

```powershell
.\Start-UniWork.ps1
```

启动脚本以自身所在目录定位仓库，自动设置源码根目录、Python 和 300 秒启动等待时间，再执行 `npm run dev --workspace apps/desktop`；无需每次手工输入环境变量。变量只用于本次进程，不写入系统环境；脚本结束时恢复调用终端的原变量和目录。

默认沿用已有的 `HERMES_DESKTOP_PYTHON`；未设置时使用本次本机开发准备的 `.hermes/uniagentgate-native/checks/Scripts/python.exe`。该目录属于本地运行环境，不随仓库分发，也不会由启动脚本下载或安装。更换或重新准备解释器后可执行 `.\Start-UniWork.ps1 -Python "D:\path\to\python.exe"`。运行前需已有 Node 依赖及可用的 Hermes Python 环境。

保留开发启动终端查看日志。这是开发服务的终端，与修复前登录后额外弹出的消息网关控制台不同。账号退出后开发监督进程会重新打开 Electron，Vite 继续运行。

未登录时先显示短信表单，登录前不启动 Hermes。输入图形验证码、发送短信并登录后显示官方启动画面；后台查询套餐、准备账号环境和后端，完成后自动进入桌面。完整未到期的加密记录在下次打开恢复，不延长期限。

整个过程只需原生窗口的一次 MaaS 登录，进入桌面后不再显示第二个 Web 登录页。旧 Web 缓存不改变当前账号，也不会因本轮代码清理而被删除；账号草稿、历史和分区保留。

登录表单采用深色双栏样式，窄窗只显示表单，小窗口可纵向滚动。此样式不改登录后的主题偏好、官方启动动效或退出规则。

没有套餐或查询失败仍可进入桌面，保留自定义模型。实际模型调用需要可用提供方、Key、网络和授权。需要刷新 MaaS 配置时退出账号并重新登录；个人模型、默认选择、MCP 和 Skills 保留。

## 回复与自我介绍

启用 `uniwork-kits` 的普通助手在桌面和消息平台共用公共话术：普通问候简短回应，询问身份或能力时使用 UniWork 风格的介绍模板；已安装专家继续使用自己的名称和人设。内部上传、图片分析规则明确标为应用提醒，不应被当成用户的话来确认或复述，`analyze_image` 指引和自动上传逻辑保留。

每次登录或恢复登录并准备账号环境时，桌面都会将当前账号默认 Home 的 `SOUL.md` 完整覆盖为内置的“身份与表达”模板，保留元景数字员工的名称、自我介绍、如实说明技术来源、语言风格和不夸大能力等完整规则，新旧账号使用同一规则。手动修改的默认 SOUL 也会在下次准备时覆盖；不会遍历其他账号或改写专家 Profile。替换失败会阻止本次环境准备，保留原文件。旧会话已经保存的系统提示不会被重写，需要新建会话验证。

公共话术通过原生插件系统提示段加载，不改写 `SOUL.md`，已有账号和新账号都适用。更新后完整退出并重新打开应用，让后端与消息网关加载新插件，再新建会话验证；微信可发送 `/new` 开始新会话，这会重置当前对话上下文。已有会话可能继续沿用保存的旧提示。用户自行停用相关插件时，不强制重新开启。

微信人工检查：发送“你好”应得到简短问候；询问“你是谁／你能做什么”应得到介绍；实际处理图片或文件时，不应复述内部上传规则。自动化只验证提示词接入、隔离和工具链路，不代表真实模型话术或微信收发效果已验收。

## 消息平台自动连接

登录或恢复登录并准备好当前账号后，应用在后台检查默认环境及受管 Profiles 的已启用配置，无需先进入消息平台页面。没有启用且配置完整的平台时，不启动消息网关；聊天后端仍按原流程运行。原版明确停用、暂停或独立运行的命名 Profile 不被自动加入受管范围。

已有网关只有在 PID、创建时间、实时 Home 和进程身份均可核实时才复用。未运行时通过原版 `gateway run` 启动本次应用运行期的网关，不安装或重新启用 Windows 开机启动项。旧配置的固定准入规则会补齐；运行中的网关若需要加载新规则，先安全停止，再启动一次。

保存、解绑与后台恢复共用桌面串行队列。微信扫码保存后由后端直接走同一套准备与重启（与恢复、重试共用后端网关锁），扫码后立即离开消息页也会完成重启；后端无法重启时页面回退为一次重试。连接失败不阻塞桌面聊天，只在消息平台页显示结果、重试和查看日志入口；关闭页面不打断任务。后续断线沿用原版重连，桌面不另加自动重启循环。平台提供的具体网络或认证说明保留在卡片和日志中，无法确定原因时不会擅自判为 Key 失效。

关闭到托盘继续运行；完整退出或退出账号停止当前账号的托管工作。再次打开才重新执行一次自动恢复，解绑的平台不会因此被重新绑定。开始退出后不再接受新任务，沿用原有归属复核、停止失败提示和下次启动遗留清理。

人工验收请由用户明确操作，真实发消息可能触发模型费用：

1. 配好一个平台并确认已连接，完整退出应用，再打开，不进入消息平台设置，直接从该平台发一条测试消息。
2. 再进入消息平台页，核对连接结果；网络暂时不可用时，确认桌面聊天仍可使用，平台页有原版重连状态或失败说明、重试和日志入口。
3. 关闭到托盘与完整退出分别测试，确认前者继续接收、后者停止；取消退出不影响原任务。
4. 按 A→B→A 切换账号，核对各自配置和进程；不要为验证而将同一个机器人同时绑定给两个账号。
5. 解绑最后一个平台后完整退出并重新打开，确认不会重新绑定，也不会启动空消息网关。

以上真实 IM、网络中断和双账号收发场景仍需人工确认；自动化与隔离进程检查不替代真实平台验收。

## 连接器 MCP

在能力页面选择“连接器”，默认打开 HexAgent 风格的推荐目录，支持按名称、介绍和供应商搜索。QQ 邮箱、网易邮箱、高德、WPS 等 11 项目前仅提供目录及详情展示；点击卡片可查看说明，授权服务尚未接入，不填写或保存凭据，也不代表已经连接。

切换到“MCP”可查看当前 Profile 的配置及插件提供的 MCP，不需要开启开发者模式。页面布局与操作对齐 UniWork：上方是内置的 UniAI-Toolkit 和 arXiv-mcp（只读，只能开关，不能编辑或删除），下方是自定义 MCP 服务；桌面连接器桥接服务不会混入自定义列表，插件提供的 MCP 单独只读列出。读写仍走 Hermes 原生 MCP 接口。切换推荐／MCP 标签不会丢失当前 MCP 编辑草稿，服务深链直接打开 MCP。页面分别显示启用状态及最近一次测试结果，保存不等于重载或工具调用已经成功。

- 新增：点“添加 MCP 服务器”，选 HTTP 或 Stdio，展开空白表单；名称和地址（或命令）填好后才写入配置，写入时为关闭状态。
- 编辑：展开后按字段填写类型、名称、地址和请求头，或命令、参数和环境变量；停止输入约半秒自动保存。改名直接改“名称”。表单里没有的字段（超时、工具过滤、授权方式等）原样保留。
- 改了就关闭：已启用的服务一旦修改配置，立即自动关闭，需要重新开启。
- 开启先测试：打开开关时先测试连接，通过才真正启用并显示“N 个工具可用”；失败时开关保持关闭，显示“失败”，展开可看原因。需要 OAuth 的服务失败后，展开有“授权”按钮。
- 删除需确认；页面打开时自动测试已启用的服务。

参数按空格拆分，含空格的参数用双引号括起来。请求头和环境变量逐行填写；需要密钥时可写 `${变量名}` 引用 `.env` 中的值。

有套餐时，启动前在账号默认 Home 写入 UniAI-Toolkit（元景 MCP），地址使用专用模型 Key 的环境变量引用；保留用户停用和工具过滤。明确无套餐删除该记录，查询失败不改；其他 Profile 不自动配置。用户手动删除后，有套餐的下一次启动会重新写入。只支持远程文件地址，不上传本机文件。

页面读取 MCP 配置时，地址、Header、环境变量和命令参数中可识别的密钥显示为打码值，保存时在当前窗口的 preload 中还原。`${DESKTOP_MT_MAAS_API_KEY}` 等未展开引用原样保留；不要把打码值当作真实密钥，或从另一个窗口复制来填写。提示打码值已过期时，重新读取配置后再编辑保存，不要用点号替换凭据。

插件提供的 MCP 回到插件页面管理，不能作为普通配置删除。配置接入、打码与页面清理已完成，模拟回归通过；真实元景连接、模型工具调用和长任务仍待人工验收，状态见[实施计划](06-mcp-connectors-plan.md)。

### MCP 人工验收

选择没有任务运行的时间进行；不要提供短信码、token、Key 或完整凭据截图。

1. 退出后重新登录有套餐账号，在默认 Profile 打开连接器，确认存在 `UniAI-Toolkit`。其他 Profile 不自动写入；若没有该项，先核对是否在默认 Profile，以及本次套餐是否查询成功。
2. 展开元景服务，确认表单只读，地址中的 Key 已打码或仍为环境变量引用，没有完整密钥。
3. 在没有在途工具调用时关闭、再打开元景服务：打开时应先显示“连接中…”，测试通过后显示“N 个工具可用”。失败只记录脱敏错误、发生时间和 Profile；不要因此清空账号配置。
4. 用一个单独的测试服务验证新增、编辑（确认改后自动关闭）、改名、开启失败的提示和删除，避免改坏正在使用的配置。
5. 新建会话，明确要求调用元景的一项工具，检查实际工具调用及结果，而不是只看模型文字。模型和远程服务可能计费，由你手动执行。
6. 如需验证长任务，使用不敏感且远程可访问的文件地址；本轮没有本地文件预上传。记录是否成功、耗时及错误，特别观察约 300 秒的 HTTP 读取限制，不自行修改超时或反复提交付费任务。

以上场景尚未实际通过时，保持“未验收”，不因模拟测试通过就认定真实工具可用。

## 技能、云盘与本地产物

- 技能市场可浏览推荐和公共目录，安装到当前账号及 Profile，安装后在“已安装”管理，新会话加载。当前市场搜索只针对首批加载列表，不是全市场搜索。安装成功不表示依赖、授权或 Windows 执行条件已经就绪。
- 默认内置 18 个 UniWork 技能，另保留内部 `hermes-agent`。更新同步时，未修改的旧随包副本移除，用户修改过的副本移入 `skills/.retired-hermes`；主动市场安装与自建技能保留。不要手工清空技能目录来解决依赖问题。
- 个人云盘已接入主进程身份，可浏览远端目录、在当前目录搜索、新建文件夹、重命名、移入回收站及获取预览／下载链接。当前没有上传入口或自动同步。旧加密登录记录缺少完整手机号时，仅云盘要求退出重登一次，本地桌面仍可使用。
- 云文件通过签名链接预览或由系统浏览器下载，不会自动保存到账号工作区，也不会因为界面可见就自动交给 Agent。普通网络失败不自动退出账号；真实双账号云盘与服务端身份绑定仍待验收。
- 本地产物是近期会话消息中的图片、文件和链接索引，不是电脑全部文件列表，也不是独立存储空间。本地生成文件不会自动进入云盘，云盘也不是会话、记忆或配置的备份。

不恢复旧 Python Web 登录／云盘代理，也不消费旧 Web 凭据。完整边界见[技能市场与个人云盘](cloud-and-market-repair.md)。

## 退出与后台工作

| 操作 | 实际结果 |
| --- | --- |
| 右下角“退出”并确认 | 显示退出等待画面，停止托管工作，清除登录，重开登录页 |
| 登录 B，再返回 A | 使用各自 Home、默认工作区和桌面状态；同账号复用原数据 |
| 关闭到可用托盘 | 窗口隐藏，后台任务继续 |
| 完整退出／托盘菜单退出并确认 | 立即隐藏窗口与托盘，后台停止，保留登录，不自动重开 |
| 取消退出 | 当前账号继续工作 |
| 运行中登录到期 | 非阻塞提示，保留任务及退出入口 |
| 到期后重新打开 | 先处理遗留工作，再要求登录，保留数据 |

窗口消失时后台可能仍在收尾；若停止失败，会出现“重试／关闭应用”提示。未确认停止前不能登录另一账号。关闭失败应用后，下一次打开先处理原账号记录；仍无法确认时保留证据并提示寻求支持。

退出停止账号桌面后端、消息网关和可信子树，保留历史、工作文件、定时任务定义和工具配置。定时补跑沿用原版。账号网关自动启动项会禁用／备份，登录不会自动重新启用。

不要手工删除恢复记录或按名称批量结束 Python／Hermes。登录到期不代表模型 Key 一定同步失效。

## 消息展示：低打扰与中文

自动恢复、重试或保存启用配置时，会为微信、钉钉、飞书、企微所在的受管 Profile 写入中文及安静展示配置。旧账号显式开启的工具进度、中间解说、推理、Working 通知、引导回执和技术尾注也会关闭。整个受管网关通过两个子进程环境开关关闭忙碌回执和首次教程，同时移除宿主显式开启的 `display.busy_ack_enabled`，避免覆盖环境开关。混用或仅配置 5G 时同样生效；5G 不再发送引导、打断、排队回执，消息处理照常，未修改 5G 适配器和专用启动器。配置损坏或待写节含共享 YAML 别名时只跳过对应展示准备并记日志，不阻断保存、扫码和启动。原生 typing、reaction、企微流式收尾与最终回答、文件继续使用原版链路。不改变排队、引导、打断和危险操作的权限判断。

钉钉、飞书、企微不在普通聊天中推送 Home channel 教程，不自动设置接收目标。微信仍把扫码人作为默认接收人。澄清选项说明、新建／重置／清空／撤回的确认及审批展示使用中文；飞书安静模式的审批结果、过期卡片点击提示及更新问询结果也使用中文。选项、风险原文和实际动作保持原样。中文目录补齐 `/context`、`/status` 和 Matrix `/resume` 的漏译说明；命令、占位符和取值不变。

每次账号恢复还会检查所有受管 Profile，即使没有绑定消息平台，也会一次性将未设置或默认 `on`（包括布尔 `true`）的 `display.memory_notifications` 设为字符串 `off`。这同时隐藏桌面与消息平台的后台记忆整理通知，记忆整理继续运行，待审批建议不会自动通过。已有显式 `off`、`false`、`verbose` 等选择保留；初始化后用户改回 `on` 也不会被覆盖。一次性标记放在插件自有配置 `plugins.entries.desktop-messaging.settings.memory_notifications_initialized`，与配置一起原子保存，失败时不标记完成。

需要完整退出并重开新版应用加载配置与插件。仅更新环境开关不强制重启已经运行且配置未变化的网关，可使用消息平台重试重新连接。记忆设置不计入触发网关重启的 `changed`：网关每轮读取，桌面 Agent 在创建／重建时读取，已创建的 Agent 或正在整理的任务不保证立即静默。第一次替换旧网关时，旧进程仍可能发一次旧的停止通知。新进程不广播上线、重启或停止；这不表示任务继续运行。原版同一开关还会关闭本次停机打断 Cron 的手机通知，任务状态和停止记录仍按原版保存。

限制：

- 语言只在未设置或为默认 `en` 时写成中文，并在平台配置里记下已设置过；之后用户改成任何语言都不再覆盖，原本选的其它语言也保留。`display.language` 是 Profile 共享语言，也会影响该 Profile 的桌面界面和其他渠道的目录文案；不是四个平台独立语言。未改桌面推理配置、模型提示词或其他平台的展示开关。显式设置的 `HERMES_LANGUAGE` 仍优先，不擅自删除或改写。
- 拥有独立网关、设为 `gateway.standalone`、已停用或标记清退的 Profile 不属于本次受管扫描，不写入记忆通知设置。新建 Profile 在下次准备时处理。独立启动、绕过桌面插件启动的网关不保证获得上述环境开关。
- `/new` 成功后的模型／上下文信息与随机 Tip、选择“始终确认”后的追加教程、取消后的 `Conversation unchanged`、通用审批超时仍由核心生成；本轮未移除或翻译。飞书“点击已过期卡片”的中文提示不等于通用审批超时已翻译。
- 模型失败、空回复、限流／额度耗尽、卡住或不活跃超时、关闭／重启期间新消息不被接收、历史读取或压缩失败、附件送达失败、后台任务运行中／启动或执行失败，以及 `/context` 等高级命令和更新提示中核心直接拼接的部分，仍可能为英文。未知确认或发送失败时保留原版回退，不伪造成功。
- 语音转写回显、部分后台结束回执和显式开启的自动压缩进度仍保留。不能据此宣称全部过程提示已隐藏或所有提示均为中文。
- 用户定时结果和后台业务结果保留；不全局关闭后台通知，不设置“隐藏所有警告”。平台中的真实收发效果仍需分别人工确认。

完整范围与验证记录见 [消息展示实施计划](16-messaging-quiet-and-chinese-plan.md)。

## 消息平台的生成成品

在微信、飞书、企业微信（机器人模式）、钉钉里让元景生成图片、视频、语音、音乐或翻译文档时，应用和桌面一样先把成品下载到本机，再作为附件发给对方，不再只发会过期的链接。

- 成品存在账号默认工作目录下的 `outputs`，各聊天共用，不自动清理。
- 文生视频、图生视频、翻译、播客交给后台：先回复“已提交”，完成后把附件发回原聊天。完成那一刻如果对方正好发来图片、文件或语音把回复打断，附件会跟在下一条回复后面发出。
- 钉钉没有发视频的接口，钉钉里的视频仍发链接。
- 下载失败或超过 20 秒没下完时发原链接；超过 20MB 的成品既发附件也附原链接，平台发不出附件时还能用链接。
- 对方在这些平台发来的图片、文档可以直接交给元景使用（图生视频、改图、翻译），自动上传，不需要先复制；只认当前账号收到的文件。
- 主模型看不了图时，对方发来的图片同样引导模型用元景看图。
- Telegram、QQ、元宝、企业微信回调模式等其他平台保持原样。
- 按代码判断：飞书、钉钉如果手动开启了流式输出，补上的附件引用可能以 `MEDIA:` 文字留在已发出的消息里（附件照常发送）。默认不开流式，不受影响。

实施范围与验证记录见 [消息会话复用本机成品交付](15-messaging-local-deliverables-plan.md)。

## 数据位置

默认位置：

```text
%LOCALAPPDATA%\uniworker\<摘要前 12 位>\
  account-id         账号完整标识，用于核对目录归属
  home\              会话、记忆、配置、Profiles、日志、Python 依赖
  workspace\         账号默认工作区

%APPDATA%\uniworker\
  maas-login.enc       系统加密的恢复登录记录
  maas-logout-pending.json
                      正常运行／退出恢复记录
  accounts\<摘要前 12 位>\
    account-id         账号完整标识，用于核对目录归属
    desktop-state\     连接、项目、原生 OAuth、账号缓存
  Partitions\hermes-mt-<摘要>\
                      按账号与用途保存的浏览器状态和草稿
```

账号目录由身份域和 UID 的完整摘要决定；浏览器分区摘要还包含用途。窗口位置、外观、托盘等设备偏好保持应用级。AppData 被系统重定向到其他盘时仍使用其实际位置，不扫描或批量重命名各盘文件夹。主动选择的外部项目、下载目录与官方对照版不改变。

账号仍使用 12 位短目录，`hmt` 改为 `uniworker` 仅增加 6 个字符，不保证任意深层依赖或文件名都不会超过路径限制。旧 `%LOCALAPPDATA%\hmt`、`%APPDATA%\hmt` 及更早的 `%LOCALAPPDATA%\hermes-desktop-mt`、`%APPDATA%\HermesDesktopMT` 不迁移、不回退读取，也不删除；首次使用新目录需要重新登录，账号、窗口位置和内置浏览器状态都从新目录开始。升级前请正常退出旧版，让后端和消息网关停止，再使用更新后的启动入口；旧数据由你手动处理，不要手工修改或复制 `account-id`。已有的旧 UniWork 数据复制功能不受本次改名调整。

本机启动脚本的 `HERMES_DESKTOP_USER_DATA_DIR` 也需指向 `%APPDATA%\uniworker`；显式指定旧路径会覆盖应用默认值。本机入口已同步调整，其他机器的自定义启动脚本需自行同步。非 Windows 默认账号数据位于 `~/.uniworker`，应用状态位于 Electron 的 `appData/uniworker`。

登录密文受系统加密保护，模型 Key 在账号 `.env` 中按原版机制明文保存。不要上传登录密文、`.env`、原生 OAuth 文件或浏览器数据库。

账号目录是应用层隔离，不是 Windows 沙箱。同一 Windows 用户的工具可能访问其它目录；主动选择同一外部项目会共享文件。官方对照版固定目录为 `X:\HermesOfficial`，不在开发版认领或清理范围。

## 双账号人工验收

准备两个 MaaS 账号 A、B 和可用模型。模型调用可能计费，由你手动执行；不向开发人员提供短信码、token 或 Key。测试文件只放在账号默认工作区。

1. 登录 A，确认右下角账号。发一条短消息，在默认工作区创建测试文件，并留下一个未发送草稿。
2. 如需验证个人模型，配置并设为默认，记录选择，不截图 Key。
3. 点击退出并确认，等待自动返回登录页，观察 A 的托管工作停止。
4. 登录 B，确认没有 A 的会话、默认工作区文件、草稿、个人模型和账号连接；为 B 创建自己的内容。
5. 退出 B 再登录 A，检查 A 的对话正文、文件、草稿和默认模型保留，B 的内容未混入；再回 B 检查。
6. 开启托盘并运行可观察的短任务，关闭窗口确认任务继续；完整退出确认任务停止，重开检查数据保留。
7. 有有效无套餐账号时验证自定义模型；没有样本就记为未验收。
8. 如需官方对照，手动同时运行两版，观察开发版退出／换账号不影响官方版工作和数据。

只记录通过／未通过／未验收、脱敏账号和现象，不保存完整手机号、验证码、凭据或对话正文。不要在个人运行实例上制造崩溃、修改系统时间或改写真实登录记录。

## 排障与当前限制

- 启动失败：按提示完整退出后重开；空间不足先释放空间，持续失败寻求支持，不重置账号数据。
- 停止失败：使用显式重试；关闭后重开仍需完成原账号清理，不能删记录绕过。
- 网关重启被命名 Profile 拒绝、技能依赖未就绪和旧宿主路径等问题已有诊断，尚未在本次文档更新中修复。不要反复重试、强制启动独立网关或向系统 Python 盲目安装全部库。
- 日志：账号 `hermes-home/logs/desktop.log`；登录前的错误先查看启动终端，对外提供日志前去除敏感信息。
- 旧无账号数据不自动导入，导入或清理需另行确定范围。
- 当前未接入 MaaS 多租户云端、会话同步、运行中套餐热更新、通用的平台 MCP／Skills 下发或账号自定义 Chromium 启动参数。内置 UniAI-Toolkit 是按套餐准备的固定项。定制分支经 Git 更新，不用官方自更新覆盖开发目录。
- 套餐 HTTP 401 的首次聊天页重登提示存在已知可见性问题；真实双账号、模型及官方版并行等完整状态见[验收状态](03-lifecycle-and-acceptance.md#p26--当前验收状态)。
- 本轮整理和自动化回归的实际通过、失败与限制见[整理计划的 R11 记录](04-desktop-consolidation-plan.md#r11-实施记录2026-10-10)；不把受控登录、文件保留或夹具修复等同于完整聊天验收。

## macOS 凭据存储补充（2026-10-22）

macOS 使用用户数据目录中的 `app-secret.key`（0600）进行 AES-256-GCM 本地加密，登录、云盘和连接器不再访问系统钥匙串。密钥不随安装包分发。Windows/Linux 保持原系统加密策略，不新增明文回退。能读取本地密钥和密文的同用户程序可解密凭据，保护能力弱于钥匙串。

旧版 Mac 凭据需要重新登录；连接器旧密钥和数据库保留在对应目录的 `legacy-keychain-backup`，需要重新授权。备份在侧车启动前进行，中断后可恢复；密钥损坏不会自动覆盖。后续升级保留本地密钥。系统录屏、麦克风及 Gatekeeper 授权不属于此调整。
