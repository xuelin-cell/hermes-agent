## Hermes 实现

唯一状态继续使用当前 Profile 的 `config.yaml` 中 `mcp_servers.UniWork-Drive.enabled`，不增加平行开关或账号全局布尔值。缺失 `enabled` 默认允许，原先手动关闭保持关闭。设置页沿用现有配置读写、差异补丁、串行自动保存和连接/Profile 归属，不回写短期凭证或无关字段。

入口放在“设置 → 安全 → 审批”，标题“允许智能体操控资料库”，说明“允许智能体基于你的指令读写个人云盘文件”。直接使用 Hermes 的 `ToggleRow`/`ListRow`、字号和布局；九种语言一并补齐，登记现有设置搜索/定位入口。云盘加入会话失败时的指引也改到新权限设置位置。

“扩展 → 连接器 → MCP”隐藏受管 UniWork-Drive 整行，不删除配置。仅当服务名和受管标记同时匹配才隐藏；用户同名自定义 MCP 仍按普通服务操作，其他 MCP 不变。

权限边界位于 Electron 的云盘 MCP HTTP 入口：

1. 每个 Profile 绑定不同临时 MCP 凭证，根据凭证定位 Profile，读取其真实配置后检查权限。
2. 关闭时工具发现不再返回云盘工具；旧会话即使缓存工具定义，实际调用仍返回 `DRIVE_ACCESS_DISABLED`，不发上游请求。
3. 拒绝结果明确引导到新设置位置，说明可手动管理，不可绕过，也不限制百度网盘和其他连接器。
4. 原有在途调用取消监测同时检查权限；已经到达服务端的操作不能靠关闭开关回滚，不增加写请求重试。
5. 资料库 UI 继续走原来的账号客户端，不受 MCP 开关限制。

### 和原版缓存处理的区别

遵守 Hermes `AGENTS.md` 的会话缓存约束，不移植 HexAgent 的 AgentManager、Reminder 注入或“下一轮重建 Agent”机制，也不主动重载其他 MCP。开关保存成功后关闭立即阻止后续调用；开启后的工具挂载在新会话生效。已缓存网盘工具的旧会话重新开启后可继续调用。

这是官方 MCP 的授权边界，并非系统沙箱：拒绝说明要求模型不通过其他工具绕过，但不宣称阻止一个具有任意终端/HTTP 权限的程序直接访问所有系统资源。
