# Hermes 桌面本地多账号

更新：2026-10-13。代码核对基线：`aebebfc9ef`。适用范围：Windows、`desktop-mt` 分支、源码开发运行；独立内部测试包尚待适配和验收。

当前实现为 MaaS 公共登录与本机 Hermes 多账号环境。同一时间使用一个 MaaS 账号；重新登录同一账号复用其历史、配置和文件。Hermes Python 后端核心保持原版，本地不使用容器、虚拟机或 PostgreSQL。

## 启动与运行

1. 应用先取得单实例锁，处理未完成的账号运行／退出记录。
2. 主进程恢复完整且未到期的加密登录记录；无法恢复时显示短信登录页。
3. 登录或恢复成功后显示官方 `ConnectingScreen`，后台独立查询套餐。
4. 套餐查询结束后准备账号目录、模型配置与专用 Key，固定账号上下文。
5. 启动并连接当前账号的原版 `hermes serve`，交接到桌面聊天界面。

无套餐或套餐查询失败不注销账号，也不阻止进入桌面和使用个人模型。运行中不自动刷新套餐或 Key；需要更新时退出账号并重新登录。

## 账号与退出

- 右下角显示脱敏账号和退出按钮。退出账号确认后显示等待画面，停止托管工作，清除恢复登录记录并重启 Electron 到登录页。
- 完整退出应用确认后立即隐藏窗口、移除托盘，后台完成停止检查；保留登录记录，不自动重开。失败时显示重试／关闭提示。
- 开启托盘且托盘可用时，关闭主窗只隐藏窗口，后台工作继续。
- 取消退出确认不开始清理。退出或换账号均保留账号历史、文件和配置。
- 运行中登录到期只提示，保留账号和手动退出入口，不自动停止任务、注销或重启。冷启动不恢复到期记录。

## 职责

| 模块 | 实际职责 |
| --- | --- |
| 登录 Renderer 与受限 preload | 表单、验证码、短信操作和启动画面 |
| `electron/login/` | MaaS 请求、身份校验、登录记录加密和恢复 |
| `electron/entry_local/` | 账号目录、配置、运行上下文、存储隔离、退出与恢复 |
| 原版 Hermes | 会话、记忆、模型调用、Profiles、MCP、Skills 和工具执行 |

身份、token、模型 Key 和账号路径由主进程保管，不通过新增登录 IPC 返回页面。`entry_local` 是主进程模块，不提供独立 HTTP 服务，也不代理每轮对话。

账号目录和浏览器分区属于应用层隔离。同一 Windows 用户的工具仍可访问其它目录；用户主动打开同一个外部项目时会共享文件。

当前没有接入 MaaS 多租户云端、Entry、Cube、会话同步、专门的离线历史模式或通用的平台 MCP／Skills 下发。内置 UniAI-Toolkit 已按套餐接入默认 Home，不代表上述统一下发能力已实现。

本分支不再提供浏览器桥接、专用 Web 构建／部署、Cube 镜像或来源分支 GitCode 同步。公共 UI 仍可按功能同步；官方桌面远程连接、REST／WebSocket 和文件能力保留，不等于已接入本产品云端。

技能市场和个人云盘已接通代码，复用当前本机 Hermes 的技能接口和主进程身份，不增加第二套 MaaS 登录。云盘是远端文件服务，不是云端 Hermes，也不自动同步本地会话、记忆或工作区。本地产物仍从近期会话整理图片、文件和链接。

默认内置集合现为 18 个 UniWork 技能，另保留内部必需的 `hermes-agent`。技能包文件安装、运行依赖就绪与真实任务成功是三件事；完整 Windows 使用和第三方凭据隔离尚待验收。功能及授权边界见[技能市场与个人云盘](cloud-and-market-repair.md)。

## 桌面模型直接读图

`hermes-agent/release` 的 `desktop-deliverables` 插件按当前会话/Profile 与实际请求模型的 `supports_vision` 判定。桌面模型设置中的 `image` 会写入该能力；明确为 false 的模型继续原来的识图链路，不能用模型显示名称或仅有 audio/video 能力代替判断。

- 已作为图片附上的内容继续由主模型直接分析。release 现有“文件”选择入口已把图片转为 image 附件，此次不改桌面附件协议。
- 只有本机路径或视频抽帧时，模型用插件工具 `desktop_read_image` 将图片部件送入当前模型上下文；它复用原生解码、尺寸与重复加载限制，不调用外部识图模型。视频抽帧仍用原有终端工具，音频另行处理。
- 执行前仅限制 `mcp__UniAI_Toolkit__analyze_image`、`mcp__yuanjing__analyze_image`、`mcp__1__analyze_image` 与 `vision_analyze`。同服务的编辑、生成、搜索、上传及其他工具不屏蔽。未知第三方识图工具不能仅按名称模糊禁用，需要确认语义后单独登记。
- 图片加载限本会话附件、引用文件、当前目录及会话登记的工作根；抽帧后cd到兄弟目录不会撤销工作根内图片的读取资格，敏感路径/其他账号目录和指向未授权位置的链接仍被拒绝。显式 text/辅助视觉路由、已知不接受工具图片的接口、缺失或损坏图片会明确失败，不静默转 MCP；接口实际拒绝图片后的文字结果也明确提示未交付。支持 image 不代表任意接口都接受工具结果中的图片。
- 使用原生本轮上下文和插件中间件，不改 Hermes Python 核心，不动态删换工具列表或重写系统提示/历史。最近实际请求模型只记录在现有 Profile/会话/轮次状态内；轮内切换为纯文本时，允许执行的原生vision_analyze也在最新模型上下文内运行，不能过早恢复旧模型。持久历史沿原生投影保留图片路径和文字，不能视为已持久保存像素；恢复后必要时重新加载原图。

隔离回归：18 个 Python 文件 374 项通过，覆盖实际插件注册、Profile A→B→A、模型切换、真实 Agent 循环和本地 HTTP 请求中的图片数据、接口拒图恢复、纯文本上传、其他 MCP 与交付物；4 个桌面测试文件 44 项通过，覆盖附件、模型配置与插件打包。视频链路另用真实ffmpeg经Agent终端抽取三色帧并cd到兄弟目录，实际主模型HTTP请求中的三张图可解码还原；后续图片编辑和检索后仍保留。纯文本对照仍上传三帧走MCP，主模型请求无图片。模型输出、MCP及对象存储响应为测试替身，没有调用付费模型。测试夹具另修正邮件 txt 上传回执误写为 image/png 的 MIME，生产邮件链路未改。

真实 Electron/服务商识图质量和 Windows/Linux 尚待验收。生效需完整重启后端并新建会话，以重新获取插件工具快照；未自动操作现有桌面窗口。人工核对：分别用 image/纯文本模型发送图片附件、从“文件”入口选图片、分析视频抽帧；image 分支应无远端 analyze_image，纯文本保持原识图；再验证图片编辑、文件上传和普通检索。严格直读遇到接口不兼容时应重新附图或换兼容模型。

## 协作规则

- 不使用子 agent，不操作用户正在使用的桌面窗口。
- 不修改 Hermes Python 后端核心，不改官方对照版，不自动认领或清理旧无账号数据。
- 修改保持小而完整；验证后本地提交，只在用户当次明确授权后推送。
- 新增命名函数／方法附简洁中文注释；提交标题简洁中文，正文说明实际行为、验证和限制。
- 验证使用独立目录、窗口与端口；短信发送和付费模型调用由用户明确操作。
- 验收记录放在提交正文和本目录，不创建 `ACCEPTANCE.md`。
- 本机 Git Bash 特殊配置、忽略的启动脚本及临时计时代码不上传。
