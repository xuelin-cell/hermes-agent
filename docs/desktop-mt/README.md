## 2. 已确认的行为

1. 同时只使用一个 MaaS 账号。首次登录创建独立环境，再次登录同一账号复用历史和文件。
2. 公共 `login` 在 Electron 主进程中负责 MaaS 请求、身份、有效期和凭据保管；Renderer 通过受限 IPC 调用。
3. `entry_local` 是主进程中的代码模块，接收可信登录结果，管理账号目录、配置、Hermes 进程和本地连接。它不另外提供 Python／HTTP 服务，也不代理每轮对话。
4. 登录前不启动本机 Hermes；账号环境就绪后，复用原版 REST／WebSocket 连接与后端。
5. 保留自定义模型、个人 API Key、Profiles、MCP、Skills 等原版能力。MaaS 登录与是否购买套餐分开判断。
6. 关闭窗口并留在托盘时托管工作继续；退出账号或退出应用时停止该账号的全部托管工作，保留数据。
7. 用户主动退出账号或切换账号时，停止旧账号工作，再自动重启开发版 Electron 进入登录页。正常退出应用不自动重开；下次手动打开按恢复登录规则处理。
8. 退出提示统一，不按任务数量改变提示。2026-10-04 用户确认简化运行中到期规则：只提示登录已过期，不自动停止任务、暂停调度、锁定界面或重启。用户自行选择退出并重新登录；不自动延长有效期。MaaS 调用被平台拒绝时给出提示，登录 token 与模型 Key 的有效期分别处理，不能仅凭登录期限断言模型 Key 已失效。
9. 不做专门的离线历史模式、运行中套餐／Key 热更新或 MCP／Skills 平台统一下发。
10. 账号目录是应用层隔离。用户主动打开同一外部项目仍共享文件；不宣称同一 Windows 用户下的任意程序被安全隔离。

## 3. 模块与数据边界

| 部分 | 负责 | 不应承担 |
| --- | --- | --- |
| 登录页、账号角标 | 输入、进度、脱敏账号、退出操作 | 决定 UID、账号路径或有效期；保存 MaaS token |
| 公共 login | 固定 MaaS 接口、响应解析、登录记录加密、到期事件 | 启停 Hermes、写工作区、持有云端数据库密码 |
| entry_local | 稳定账号目录、MaaS provider 配置、进程归属、停止与连接 | 短信协议、模型推理、每轮对话转发 |
| 原版 Hermes | 会话、记忆、模型调用、工具和 Profile 行为 | 新增 MaaS 业务逻辑 |

拟新增目录为 `apps/desktop/electron/login/`、`apps/desktop/electron/entry_local/`、`apps/desktop/src/app/login/`，共享 IPC 类型放在现有桌面类型组织位置或一个小的共享类型文件。实施前核对现有命名，不创建空模块或通用插件框架。

```text
%LOCALAPPDATA%\hermes-desktop-mt\accounts\<安全账号标识>\
  hermes-home\       原版会话、记忆、配置及账号内 Profiles
  workspace\         该账号的默认工作目录

%APPDATA%\HermesDesktopMT\
  maas-login.enc       使用系统加密能力保存完整公共登录记录
  accounts\<安全账号标识>\desktop-state\
                      主进程连接、Profile、默认项目、原生凭据与文件缓存
  Partitions\hermes-mt-<完整摘要>\
                      Electron 管理的账号／用途浏览器存储，含草稿与界面状态
```

- 安全账号标识由明确的平台身份命名空间和可信 UID 确定，不能由手机号、token、模型 Key 或 Renderer 任意路径决定。
- Electron 的应用级 `userData` 根目录固定。Chromium 的 Cookie、localStorage、IndexedDB、预览和远程 OAuth 分区使用原生 Session／partition 按账号及用途隔离；实际文件由 Electron 存入 `Partitions`，不手工复制数据库，也不塞进 `desktop-state`。原版 Renderer 草稿和界面持久化逻辑保持不变。
- Hermes 安装目录、Python 环境和账号数据分开；不为每个账号复制仓库或安装一套 Python。
- 旧无账号开发数据保留且不自动认领。删除或迁移需要另行确定精确范围。
- `X:\HermesOfficial` 和官方对照源码不在修改、清理或进程停止范围。
- 本机专用 `scripts/start-desktop-mt.ps1` 继续留在本地忽略范围；不把 Git Bash 特殊路径提交进仓库。

## 4. 已知问题与实施前置条件

### 本地身份恢复与套餐查询分开

2026-10-02 的未认证只读请求观察到：不带 token 调用 `my-plan` 也返回 HTTP 200，正文中 `apiKey`、`models` 等字段为 null。此观察不能证明所有环境、所有失效 token 都有相同行为。

2026-10-03 用户确认采用简单的本地恢复规则，替代原计划中必须在线复核身份的要求：

1. 主进程读取并解密完整登录记录，检查平台身份域、UID、token 和有效期。
2. 记录有效且未到期，恢复原 UID；后续 `entry_local` 按此 UID 选择原账号环境。
3. 没有记录、记录损坏或到期，回到登录页，保留用户数据，不自动认领旧无账号数据。
4. 套餐由 P10 单独查询。无套餐不影响身份和自定义模型；查询失败不直接判定登录失效，页面提供手动重试。

身份恢复本身不请求 MaaS、不重新保存记录、不延长期限，也不增加静默刷新或 token 解析机制。P10 在登录或恢复成功后独立查询套餐，不用其结果反向判断身份；账号目录与原版 Hermes 启动仍由 P11～P17 接入。

### 自动重启需要先验证开发启动器

当前 `npm run dev` 使用 `concurrently -k`。Electron 退出可能连带结束 Vite，不能仅调用 `app.relaunch()` 就宣称完成自动重启。P03 先用隔离环境验证监督进程和前端服务的关系，再确定最小的启动器调整；不更改用户的 Git Bash 本地配置。

P03 已接入常驻开发启动器并完成真实进程夹具验证，具体证据与仍待人工验证的范围见阶段一 P03。现有 PowerShell 启动命令不变。

### 退出要确认工作确实停止

原版 `local-backend-lifecycle.ts` 中的部分清理使用超时和 `Promise.allSettled`，原版消息网关也可以独立存活。这些基础能力可复用，但“清理调用返回”不等于全部进程已经停止。

只处理归属当前账号的托管工作。禁止按进程名称批量结束所有 Python／Hermes，禁止未经归属检查调用全机停止操作。若核心现有接口无法满足某类托管工作停止，记录具体反例并讨论，不修改核心或缩小承诺掩盖问题。

## 5. 提交规则

- 每个提交尽量为 100～300 行有效产品代码，通常不超过 400 行。测试、文档单独统计，同时展示总 diff；不能通过生成文件或机械移动隐藏改动规模。
- 行数是拆分依据，不是凑数目标。一个完整改动只有几十行也可以提交；预计超过范围时，先按可验收行为继续拆分。
- 每个产品代码提交必须接入当前阶段可运行的流程或有真实运行夹具。纯测试能证明的只写为组件验证，不能冒充产品端到端验收。
- 新增函数、方法附近写简洁中文注释。优先使用现有 Electron、Node、`yaml` 和项目组件，新增依赖前阅读现有能力、类型与官方资料。
- `main.ts` 等大入口仅接线；新增职责放入小模块。必须抽取既有行为时，单独提交并做回归，禁止夹带大面积重构。
- 一个行为与必要测试同次提交，提交前检查差异和无关改动。保留现有 `apps/desktop/测试.txt`。
- 只有用户确认本文档后才实施。实施中的每个完成小改动本地提交；不自动推送。需要用户参加的短信、付费模型调用和人工验收应明确操作及预期。
- 发现新规则或接口证据改变计划时，更新受影响条目；用户选择尚未明确的事项先讨论，独立工作仍可继续。
