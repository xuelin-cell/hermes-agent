# 个人微信扫码连接

日期：2026-10-14。状态：已实现，模拟测试通过；真实微信扫码待人工验收。

## 行为

原来要在终端运行 `hermes gateway setup` 才能看到二维码。现在参考 UniWork，在消息页的“微信 ClawBot 集成”卡片里点“配置”即可；整体界面见[消息平台阶段一](09-messaging-ui.md)。

| 状态 | 页面显示 |
| --- | --- |
| 未连接 | “配置”按钮 |
| 等待扫码 | 二维码和“请用微信扫码” |
| 已扫码 | “已扫码，请在手机上确认” |
| 二维码过期 | 显示“二维码已过期”和“刷新二维码”，由用户重新生成（与 UniWork 相同，不自动换码）；一次登录最长等 5 分钟 |
| 确认成功 | 自动保存凭据、打开微信通道并重启消息网关；提供“重新扫码”和“解绑”，卡片连接状态以原生接口为准 |
| 解绑 | 确认后清除凭据、关闭微信通道并重启网关 |

扫码成功后的默认设置（简化界面不展示权限字段，已有配置继续保留）：

| 项目 | 默认 |
| --- | --- |
| 私聊 | 只允许扫码的微信号本人（`WEIXIN_DM_POLICY=allowlist`）；拿不到扫码人 ID 时退回配对审批 |
| 群聊 | 关闭 |
| 主动消息 | 发给扫码人本人（`WEIXIN_HOME_CHANNEL`） |

## 实现

| 部分 | 位置 |
| --- | --- |
| 后端接口 | 新增内置插件 `plugins/weixin_qr/dashboard/`，挂在 `/api/plugins/weixin-qr/`：开始、查询、解绑（与 UniWork 相同，没有单独的取消接口；关闭二维码只是收起，重新生成时旧二维码作废） |
| 前端 | 新增 `apps/desktop/src/api/weixin-qr.ts`、`apps/desktop/src/app/messaging/weixin-qr-setup.tsx`；消息页挂载，文案在简体、繁体、英文语言文件 |
| 测试 | `tests/plugins/test_weixin_qr_plugin.py`、消息页测试、截图夹具 `apps/desktop/scripts/weixin-qr.renderer.mjs` |

- 没有改 Hermes 后端已有文件。插件复用 `gateway/platforms/weixin.py` 的请求函数，保存方式与 Telegram 扫码相同（`save_env_value`、`_write_platform_enabled`、`_restart_gateway_after`）。
- 登录状态只在发起它的后端进程内存中；同一次登录的请求都带同一个 Profile 作用域，并把 Profile 作为查询参数告诉插件写到哪里。
- token 只留在后端，接口不返回。解绑只删除当前绑定账号自己的凭据文件。
- 消息页保存后刷新状态、跟踪网关重启，失败时保留手动重启与日志入口。
- 二维码用最高纠错级别 `H`，与 UniWork 相同（UniWork 记录中等级别时微信扫不出）。

依赖风险：插件调用 `weixin.py` 的内部函数 `_new_session`、`_fetch_qr`、`_api_get`。同步上游后这些名字变化时插件会失效，插件测试会先失败，届时只需改插件。

## 开发模式缺组件（2026-10-14）

真实运行时点“扫码连接”报 503“Weixin needs aiohttp and cryptography”。原因只在开发模式：

| 账号状态 | 用哪个 Python 环境 | aiohttp（微信） | mcp（UniAI-Toolkit） |
| --- | --- | --- | --- |
| 新账号，从没装过组件 | 源码目录的 `.venv` | 有 | 没有 |
| 装过任意组件之后 | 账号自己的环境：基础依赖 + 已装的组件 | 没有 | 装过才有 |

安装版打包时装好全部组件（`uv sync --all-extras`，只排除 kittentts），不受影响。上游微信和 MCP 都不会在用到时自动补装。

处理（参考 UniWork“组件随环境装好、扫码时不安装”）：新增 `apps/desktop/electron/entry_local/dev-extras.ts`，开发模式启动账号桌面前，读 PM 记录的组件；账号已有自己的环境但缺 `mcp` 或 `messaging` 时，用上游文档的 `pm.sync_venv([...], explicit=True)` 补装，最多等 3 分钟，失败只记日志、照常启动。

- 新账号跳过：它用 `.venv`，已有 aiohttp；从零建环境要重新下载全部依赖，实测慢网下 707 秒后下载超时，不能卡住登录。账号有了自己的环境后，下次启动再补齐。
- 已记录齐全时不启动 Python，不增加启动时间。账号 `9e45…` 已有 `mcp`、`messaging`。
- 原生测试的临时账号或离线开发可设 `HERMES_DESKTOP_MT_SKIP_DEV_EXTRAS=1` 跳过。
- 扫码页面不变，不做现场安装。

验证：新增测试 3 项（读记录、只补缺的、新账号与安装版跳过、失败不中断），去掉“新账号跳过”或“只补缺的”后对应测试失败；Electron 入口测试 48 项、类型检查、ESLint 通过；在临时目录用真实命令运行，确认调用能走到安装微信组件这一步。
