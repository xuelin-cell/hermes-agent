## P18 · 显示当前账号角标

2026-10-04 已完成：复用原版状态栏，在右下角显示主进程提供的脱敏手机号。按用户本轮确认，不增加信息菜单、环境标识或有效期文字，退出按钮留到 P19。主窗和完整副窗分别通过只读 IPC 获取同一有效身份；接口检查所属窗口、主框架、账号 Session 和桌面页面地址，拒绝页面传入参数，只返回脱敏手机号及用于刷新显示的有效期，不返回 UID、token、Key 或账号路径。

窗口首次加载、重新聚焦和有效期检查时刷新展示；读取失败、未登录或到期后隐藏旧账号。没有增加登录恢复、身份续期或注销操作，到期停止托管工作仍由 P22 实施。

证据边界：使用真实 Electron 和原版 Python 后端，MaaS 身份与套餐为受控测试响应；没有调用付费模型，没有操作用户已有窗口。真实双账号短信登录、聊天、退出和换账号仍待阶段三后续验收。Hermes Python 核心、官方版和本机启动脚本未修改。

## P19 · 退出账号并停止普通桌面后端

- 提交主题：`feat(entry-local): 停止桌面后端并返回登录页`。
- 行为：退出统一确认；确认后封闭旧账号操作入口、取消未完成启动、关闭连接、停止所有桌面 Profile 后端、确认退出，再清除可恢复登录记录并重启桌面进入登录页。
- 失效标记先于清理持久化，避免中途崩溃后自动恢复一个正在退出的账号；进程归属记录在停止得到确认前保留。文件与历史不删除。
- 自动检查：双击退出只运行一次，迟到启动不会重新产生后端，清理失败不能直接切到另一账号。
- 真实验收：普通对话／工具执行中退出，确认其后端及所托管子进程停止；新窗口显示登录页，重新登录同账号历史仍在。
- 边界：此单元先验收普通桌面后端；消息网关等由 P20/P21 补齐。中间版本只用于受控测试，不能对用户宣称全部托管工作已停止。

## P20 · 停止当前账号的消息网关

- 提交主题：`feat(entry-local): 按账号停止独立消息网关`。
- 预计位置：`entry_local` 网关生命周期适配；复用原版已有 CLI／接口，原版 Python 文件只读核查。
- 行为：枚举当前账号及其 Profiles 的网关归属，停止并确认退出，同时处理会自动拉起它的监督机制。账号 A 的停止不能作用于 B 或官方对照版。
- 自动检查：可控进程夹具模拟正确归属、PID 重用、已退出和拒绝停止；没有可信归属时不按进程名强杀。
- 真实验收：在隔离账号启动真实网关，退出账号后确认不再处理工作、不会自行重启；同时运行的官方版仍正常。
- 边界：不直接照搬全局 `gateway stop --all` 或卸载清理流程。若当前原版接口不能按账号完成停止，记录证据，与用户讨论后再调整方案。

## P21 · 覆盖其余托管工作与关闭托盘行为

- 提交主题：`feat(entry-local): 统一账号托管工作的退出生命周期`。
- 行为：核对定时任务、后台终端、MCP 子进程、桌面辅助窗口和已发现的独立守护进程；对能证明归属的资源纳入同一停止流程。
- 定时任务定义保留，账号未运行时不执行。重新登录后的补跑／错过时间处理沿用原版语义并实测，不新增自定义补跑规则。
- 将退出应用、托盘菜单退出和退出账号接入同一停止入口；退出应用不重启。关闭窗口留在托盘时继续工作，相关设置与提示一致。
- 真实验收：分别启动一次短定时任务、后台命令和可控 MCP，检查关闭到托盘继续、退出后停止。逐类记录，不用“杀掉父进程”替代结果。
- 边界：不能保证停止用户在工具外自行启动的任意 Windows 程序。若 Hermes 自己产生了无法归属／停止的托管程序，视为未解决项，不把它归为用户外部程序以绕过验收。

## P22 · 到期后停止账号工作

- 提交主题：`feat(login): 到期后停止本地账号并要求重新登录`。
- 行为：主进程维护到期检查，正常计时、电脑唤醒和关键操作前都检查。到期封闭操作并走 P19～P21 的停止流程，然后重启到登录页。
- 计时不依赖 Renderer 存活，也不因为模型 Key 仍可用而继续工作。提示不提供“继续使用”选项。
- 自动检查：可注入时钟的正常到期、时间跳变、超长计时、重复事件；测试钩子只能在测试夹具中使用，不提供生产免登录开关。
- 真实验收：在独立 Electron／真实后端夹具中设置短有效期，执行中到期；另测休眠跨过到期时间后恢复。用测试身份不冒充真实 MaaS 过期验证。
- 边界：停止失败进入明确错误状态，不能恢复旧账号操作或启动新账号；历史继续保留。

## P23 · 环境准备失败后可重试

- 提交主题：`fix(entry-local): 保留账号数据并恢复失败的环境准备`。
- 行为：处理目录不可写、配置解析失败、凭据写入失败、后端启动和健康检查失败；只显示本次失败阶段，不退回其他账号或官方安装。
- 自动检查：使用真实临时文件和失败进程验证重复准备不会清空历史、留下重复后端或把半写入配置当作完成。
- 真实验收：对临时账号制造一个配置错误，再修复并点击重试；原标记文件和历史保留，成功后只有一个有效连接。
- 边界：基础错误处理随各功能提交完成；本提交补足跨模块中断恢复，不把所有错误处理拖到最后。

## P24 · 停止失败保留归属并禁止切换

- 提交主题：`fix(entry-local): 停止失败时保留归属并阻止账号切换`。
- 行为：超时、拒绝退出、子进程残留和身份无法确认分别记录；停止失败显示可重试状态，保留进程归属与停止意图，不把 Promise 已结算当作成功。
- 自动检查：故意延迟／拒绝停止的进程夹具，验证下一账号不能启动；重试完成后才允许回登录页。
- 真实验收：模拟停止阶段失败，确认窗口不给旧账号继续操作；停止恢复后退出一次完成，没有循环重启。
- 边界：不能使用“强制忽略并继续换账号”的入口；不结束其他安装的进程。关键阻止逻辑在 P19 已具备，本步补复杂故障覆盖。

## P25 · 崩溃后恢复账号归属与遗留清理

- 提交主题：`fix(entry-local): 恢复崩溃后的账号进程归属`。
- 预计位置：`backend-ownership.ts`、`backend-exit-recovery.ts` 的账号接线及 `entry_local` 恢复流程。
- 行为：复用原版 PID、启动时间、父进程和 nonce 归属证据；重新打开先处理遗留停止意图，不连接另一账号后端。
- 真实验收：在隔离目录中强制结束测试 Electron，再打开；确认遗留后端得到正确处理、不重复启动。PID 已重用时不误杀。
- 分别测试“普通运行崩溃”“退出中崩溃”“已过期后重开”。失败清理不能丢掉唯一归属记录，自动恢复不能无限重试。
- 边界：强制测试仅作用于本轮创建并确认归属的测试进程，不对用户正在工作的桌面或官方版做崩溃试验。

## 每个小提交的检查方法

在 `apps/desktop` 中按实际改动选择检查；文件名以该提交已经存在的文件为准，不执行空的占位测试命令。

```powershell
# 运行本次修改对应的主进程测试文件
npx --no-install vitest run --project electron electron/<实际测试文件>.test.ts

# 界面有改动时运行对应的 UI 测试
npx --no-install vitest run --project ui src/<实际测试文件>.test.tsx

# 类型检查；失败时区分本次引入与已存在的问题，并记录证据
npm run typecheck

# 在仓库中检查本次 diff
git diff --check
git diff --stat
```

- 上面带尖括号的路径是使用说明，不是可以直接运行的命令。每步提交说明中必须填写实际执行命令。
- 按风险运行所触及区域的 lint 和回归测试；涉及启动／退出时，包含现有 ownership、pool-stop、quit、恢复等相关测试。
- 实际启动／重启验收使用现有源码运行入口；构建接线有变化时验证 Electron 打包脚本。不要顺手打安装包、升级依赖或部署云端。
- 测试使用独立的 Home、工作区与 Electron 状态目录；不写入官方目录或现有个人会话。Python 相关测试若需要执行，遵守仓库的 `scripts/run_tests.sh`，不绕开隔离规则。
- 每个代码提交写 `git diff --numstat` 的产品代码／测试／文档统计，按总计划控制大小；已经通过且没有新风险的检查不反复重跑。

## 最终验收矩阵

| 场景 | 必须观察到的结果 | 证据类型 |
| --- | --- | --- |
| 未登录打开 | 有登录页，无账号后端、无自动 Profile 预热 | 真实 Electron 与进程记录 |
| 正常短信登录 | 页面正确、身份可信、凭据未泄露 | 用户操作与脱敏记录 |
| 恢复／过期／网络故障 | 分别恢复、重登、重试；无错误放行 | 已核实协议＋真实启动 |
| 有套餐／无套餐 | MaaS 与自定义模型按各自条件使用 | 真实账号；缺样本明确标注 |
| A→B→A | 会话、文件、草稿、Profile、连接和预览存储隔离且可恢复 | 真实后端／Chromium 文件与窗口 |
| 切换默认模型后重登 | 个人配置和默认选择不被套餐同步覆盖 | 实际设置与配置文件 |
| 关闭到托盘 | 已托管任务继续 | 真实短任务 |
| 退出账号／应用 | 托管后端、网关、定时执行及相关子进程停止 | 分类别进程／任务观察 |
| 停止失败 | 保留归属、不能启动另一账号、重试可恢复 | 故障夹具＋真实进程 |
| 重启／崩溃／电脑唤醒 | 不重启失效账号，不重复进程，不丢历史 | 隔离的 Windows 实测 |
| 官方版并行运行 | 数据与进程不受开发版登录、退出影响 | 并行运行人工确认 |

本矩阵全部有明确结论后才能提交最终验收报告；“未验证”必须保留为未验证，不算通过。
