# P01：MaaS 登录与套餐接口契约

核查日期：2026-10-02。范围：桌面公共 Login；不修改 Hermes 核心或云端 Entry。

本文件区分三种证据：参考源码行为、真实请求观察、桌面实现规则。源码支持某种形状不等于上游已实测返回该形状。真实短信链路尚待用户操作；2026-10-03 用户确认 P09 按完整本地加密记录与原有效期恢复，已接入此规则。

## 2. 四个已知接口

以下路径均相对于上述 `/app` 根地址。请求由 Electron 主进程发出，Renderer 不能替换 URL 或传入任意请求头。

| 动作 | 方法与路径 | 请求数据 | 已知响应用途 |
| --- | --- | --- | --- |
| 图形验证码 | `GET /login/captcha` | 无 | `captchaId`、`b64s` |
| 短信发送 | `POST /login/sendCode` | JSON：`phone`、`captchaCode`、`captchaId` | 判断发送是否成功，不建立登录态 |
| 短信登录 | `POST /login/smsLogin` | JSON：`phone`、`smsCode`、`origin: app`、`application: uniwork` | 取得 UID、登录 token、有效期 |
| 当前套餐 | `GET /gateway/uniwork/my-plan` | `Authorization: Bearer <登录 token>` | 模型 API Key、模型目录和主模型 |

请求声明 `Accept: application/json`；POST 使用 JSON 内容类型。不新增 application，不使用平台公共 Key 兜底，不自动重试短信发送或登录 POST。

### 响应包裹与业务状态

Web 的 `sms_login` 接受对象响应，业务 `code` 为 `0`、字符串 `"0"` 或缺失；其他 code 视为业务失败。若 `data` 是对象则取 `data`，否则取根对象。这个容忍范围是参考实现，不是所有接口的已验证正式协议。

桌面必须同时检查 HTTP、JSON、业务状态和动作所需字段；不能仅靠 HTTP 200 放行。缺失 code 时仍需完整、有效的登录字段，不能把任意对象当成功。验证码和短信接口的具体成功／失败包裹将在 P05～P07 的真实链路补证。

## 3. 登录身份与期限

Web 登录响应消费这些字段：

| 字段 | 参考行为 | 桌面约束及待核实内容 |
| --- | --- | --- |
| `uid` | 转为非空字符串 | 来自主进程直接取得的登录响应；实际类型及跨登录稳定性待实测 |
| `token` | 非空字符串 | 仅主进程保管，不从 Renderer 接受已登录身份声明 |
| `expiresAt` | 正数，Unix 毫秒时间戳 | 必须是有限数且在未来；不能把秒时间戳误当毫秒 |
| `expireIn` / `expires_in` | `expiresAt` 不可用时，按当前时刻加秒数 | 有限正数；不得默认补一个固定有效期 |

登录 token 用于 MaaS 身份／套餐请求；`my-plan.apiKey` 是供模型调用的 Key，不能拿模型 Key 当登录 token。套餐有效期字段也不能替代登录有效期。

Web 不解码或验证 JWT，只信直接登录这一跳。桌面同样不通过解析 token 中的字段建立新身份。P08 加密保存完整登录结果，P09 校验该记录并沿用原 UID、token 和有效期，不重新计算期限。

UID 规范化必须无损；如实测发现超出 JavaScript 安全整数范围的数值 UID，应先解决解析精度，不得四舍五入后分配账号目录。不要把手机号当稳定 UID。

## 4. 套餐与模型

参考源码接受根对象或 `data` 对象；读取 `apiKey` 及 `models`。`models` 支持 JSON 字符串或对象，解析后包含 `models` 数组与 `main_model_id`。

结构示意（人工构造，不是已实测登录样本）：

```json
{
  "apiKey": "<模型 Key，禁止写入日志>",
  "models": {
    "models": [
      {"id": "example-id", "model": "example-model", "base_url": "https://example.invalid/token-plan"}
    ],
    "main_model_id": "example-id"
  }
}
```

- 主模型按 id 匹配，参考实现未匹配时取第一项。
- 保留每个模型自己的地址，去掉末尾斜线后仅在缺少 `/v1` 时补上；不能改成通用 MaaS 网关地址。
- 参考实现按模型名去重；桌面不能照搬这一点丢掉同名不同端点。
- 模型地址只供后端调用，不作为 Login 请求目标；配置写入前另行验证结构与协议。
- Web 把网络异常、无 Key、错误形状等压成 `None`。桌面不能据此宣布“无套餐”，更不能据此清除旧配置。
- 在已经可信登录的前提下，仍须确认空套餐的业务语义；有 Key 但无模型是配置不完整，不应伪装成完整可用套餐。

## 5. 本轮真实只读观察

通过 PowerShell `Invoke-WebRequest -UseBasicParsing`，超时 15 秒，对已知 `my-plan` 路径分别执行一次 GET。没有使用用户 Cookie、已有登录记录、手机号或真实凭据，没有发送短信、登录或调用模型。

| 请求 | HTTP | 返回字段 | 结论 |
| --- | --- | --- | --- |
| 不含 Authorization | 200 | 根对象包含 `apiKey`、`models`，两者为空；无 code | 200 不能证明身份有效 |
| Bearer 人工构造的无效测试串 | 200 | 同样包含空 `apiKey`、空 `models`；无 code | 空套餐不能区分无效凭据与有效无套餐 |

输出仅保存状态、字段名以及 Key／models 是否非空；不保存响应原文或凭据。人工无效串不等于真实过期或被撤销 token，这两种情况尚未验证。

Web 源码注释称“没 token／坏 token 返回 500”，与本次两项观察不一致。因此既不能依赖 200 判定有效，也不能依赖 500 判定到期。

UniClaw 的 `loadAuthState()` 从 localStorage 中检查 token、用户记录和 application 后恢复前端状态；该函数没有向 MaaS 复核身份或期限。桌面不直接照搬明文前端存储，按下述规则在主进程读取完整加密记录。

## 6. 桌面判定规则

| 场景 | 桌面处理 |
| --- | --- |
| 短信登录成功，字段与期限合格 | 建立本进程可信身份，继续准备套餐 |
| 登录字段缺失、JSON 错误或期限非法 | 登录未完成，不启动账号环境 |
| 已保存期限到期 | 要求重新登录，不续长期限、不继续账号工作 |
| 上游正式协议明确凭据失效 | 回登录页；不能仅凭任意 401／500 猜测具体原因 |
| 网络失败、限流或上游异常 | 可重试的失败；不当作无套餐或删除账号数据 |
| `my-plan` 返回 200 空对象／空套餐 | 不能证明身份有效，不能用于恢复放行 |
| 完整加密记录通过平台身份域、UID、token 和期限校验且未到期 | 按原 UID 恢复身份，不请求 MaaS、不改写原期限 |
| 无记录、记录损坏或字段不合格 | 要求重新登录，保留原文件与用户数据 |
| 已建立身份下套餐为空或查询失败 | 套餐独立处理，不直接判定登录失效，不阻止自定义模型 |

错误日志只记录阶段、HTTP 状态及受控错误类别；不照搬 Web 的上游原文日志，不回显 token、Key、完整手机号、验证码或未知响应体。

## 7. 待补证与实施顺序

1. 在登录页接通后，由用户完成正常短信链路，仅提取字段名称、类型、期限单位和脱敏结果。不要求用户在聊天中粘贴凭据。
2. 同账号两次登录验证 UID 稳定性；需要第二次时由用户决定是否发送短信，不重复消费旧验证码。
3. 有套餐、有效但无套餐、真实过期、撤销及限流分别记录；无对应账号／条件则明确未验收。
4. P09 已按用户 2026-10-03 确认的完整记录与本地期限恢复规则实施，不再等待新增在线身份验证接口。

P10 单独查询套餐；阶段二使用主进程已建立或恢复的 UID 准备账号环境。真实短信与 UID 稳定性样本仍需用户操作补证，不影响已确认的本地恢复规则实施。

## 8. P05 验证码补证（2026-10-03）

实际 `GET /login/captcha` 返回 HTTP 200，根字段为 `code`、`data`、`msg`，业务 `code` 为数值 0；`data` 包含字符串 `captchaId` 和带 `data:image/png;base64,` 前缀的 `b64s`。只记录字段和类型，不保存响应原文。

真实 Electron 登录窗口通过主进程完成首次取图和一次手动刷新，图片解码与显示正常，页面没有直接请求 MaaS。桌面按此结构实现，不保留 Web 对无前缀图片或根对象字段的旧容忍路径。非零／缺失 code、缺失字段、非图片 URL、SVG 和异常响应均不作为成功；字符串 `"0"` 的解析仅有受控测试，未观察到上游实际返回。

短信发送、短信登录及恢复身份的证据边界保持原有记录。

## 9. P06 短信实现边界（2026-10-03）

桌面沿用参考 Web 的 `POST /login/sendCode` 和三个 JSON 字段，成功冷却 60 秒。实现要求 HTTP 成功且业务 `code` 为 0 或字符串 `"0"`；缺失 code 不当成功。该响应结构目前只有受控测试，真实发送响应及手机收信尚待用户在页面操作验证，不能称为上游已确认。

标准 HTTP `Retry-After` 的秒数与日期、HTTP 429、非成功业务 code、坏 JSON、HTTP 503 和超时均在受控测试中覆盖。未确定的业务限流码不做猜测映射；未知失败没有自动重试，页面允许用户检查输入并刷新图片后再发送。没有发送真实短信、提交短信登录或获取新的账号凭据。

## 10. P07 短信登录实现边界（2026-10-03）

桌面按 P01 契约接入短信登录。已知的 `data` 对象或根对象字段均有受控样本；存在 `data` 时必须是对象，不在坏 `data` 下回退根字段。业务 code 为 0／字符串 `"0"` 或缺失时，仍须完整校验身份与期限；其他 code、空 UID／token 和非法有效期不建立身份。没有自行解析 JWT 或补默认期限。

受控测试覆盖字符串 UID、安全整数 UID、超大数值 UID、绝对毫秒期限、两种相对秒字段、缺失字段、过期、HTTP／网络／JSON 失败、并发提交和关闭后迟到响应。真实 Electron 检查使用同一主进程代码，仅替换网络响应，不请求真实短信登录。新增 IPC 返回值只含 `maskedPhone` 和 `expiresAt`；P07 时凭据仅保存于主进程内存，P08 已接入下述加密记录。

真实手机号收信、上游短信登录成功结构、UID 类型及跨登录稳定性仍未验收。P07 的验证只涵盖当时的进程内登录，P08 存储与 P09 本地恢复分别见后两节；本地账号环境仍未完成。

## 11. P08 安全存储边界（2026-10-03）

完整记录包含固定平台身份域 `maas.ai-yuanjing.com/uniwork`、UID、token、有效期和脱敏手机号，经 Electron 系统加密后原子写入 `maas-login.enc`。保存失败时不建立身份，不回退明文。该文件不是 Hermes 模型配置、模型 API Key 或账号会话库。

真实 Windows Electron 进程已经完成加密、退出与新进程解密验证；网络登录仍是受控样本，不能据此认定 MaaS 登录字段已实测。损坏、解密失败或身份域／字段错配均拒绝读取，原文件不因读取失败被删除或改写。P08 当时只验证存储，当前恢复规则见下一节。

## 12. P09 本地恢复规则（2026-10-03）

用户确认保持四步：主进程读取完整加密记录并检查平台身份域、UID、token、有效期；未到期则恢复原 UID；无记录、损坏或到期要求重新登录且保留数据；套餐单独查询，不以无套餐或查询失败取消身份和自定义模型能力。

已接入主进程恢复与受限 IPC。页面先等恢复结果，再显示账号或表单；UID、token 不返回页面。恢复不发送网络请求、不再次写入记录、不延长期限、不静默刷新。P09 只恢复身份，账号环境由阶段二接入，套餐查询属于尚未实施的 P10。
