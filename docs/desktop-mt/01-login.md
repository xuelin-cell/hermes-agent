# 公共 Login 与登录界面

实现位置：`apps/desktop/electron/login/`、`apps/desktop/src/app/login/`。接口字段见 [MaaS 契约](MAAS_CONTRACT.md)。

## P01 · 固定请求与身份规则

MaaS 请求由 Electron 主进程发出，固定使用 `https://maas.ai-yuanjing.com/app` 和 `application=uniwork`。身份来自短信登录响应，或经过完整校验且未到期的本地加密记录。套餐结果不作为恢复身份的依据。

废弃的 `/api/uniwork/auth/*` Python Web 登录代理已移除。原生登录不经过本机 Hermes 的登录代理；官方远程 OAuth、Cookie 和本机连接令牌仍保留，不属于该删除范围。

## P02 · 登录壳与账号运行时

`bootstrap.ts` 先设置固定应用级 `userData`、执行启动前平台设置、取得单实例锁并完成遗留清理，再打开登录窗口。

登录前不加载原版 `main.ts`，不启动 Hermes、安装引导、Profile 预热或旧连接。登录窗口关闭会取消启动；账号交接成功后才由主进程销毁登录窗。身份归 `LocalRuntimeContext` 持有，窗口关闭只解绑登录 IPC。

账号准备完成后，主页面直接进入原版桌面，不再通过 Renderer 的第二套 Web 登录。旧 `auth_token`、`user_info` 等缓存不用于恢复、选择或退出账号，也不自动清除；原生登录及加密记录是本地账号的唯一来源。官方远程连接的 OAuth 和 Cookie 机制仍保留，与已删除的 MaaS Web 登录链不同。

## P03 · 开发监督重启

`scripts/dev-electron.mjs` 只接受自己持有的 Electron 子进程发出的明确重启消息，且旧进程正常退出后才启动新 Electron。账号退出重启期间 Vite 保持运行；普通退出、崩溃和异常退出不自动重启。

`desktop-relaunch.ts` 合并重复重启请求。受监督的开发模式通知启动器，其它运行方式调用 Electron 的 `app.relaunch()`。

## P04 · 登录页面

独立 `login.html` 加载固定深色、蓝青渐变的短信登录页，复用现有 `BrandMark`、`Input`、`Button` 与国际化。默认窗口为 1080×760，宽窗显示品牌与表单双栏，窄窗只显示表单；最小窗口为 400×300，内容不足以完整显示时可纵向滚动。表单包含手机号、图形验证码和六位短信码，支持键盘提交、输入校验和重复提交保护。

`src/app/login/login.css` 的配色只作用于登录表单区域，不写全局主题或用户偏好。采用新登录页的展示设计，身份与请求继续走原生受限 IPC；不包含跨设备同步承诺或无有效链接的条款说明。

登录或恢复成功后只显示官方 `ConnectingScreen`，等待套餐查询、环境准备与桌面交接。账号在交接前到期时回到空登录表单。

## P05 · 验证码与受限 IPC

专用 preload 仅提供 `restore / plan / captcha / sendSms / login` 五项能力，不提供通用文件或进程桥接。主进程校验绑定窗口、主框架、准确页面地址和参数数量；窗口关闭时移除处理器。

验证码首次加载自动获取。点击图片刷新，清空旧图片和输入；失败可再次点击，迟到响应不覆盖新图片。仅接受有效 ID 和 PNG／JPEG／GIF 的 base64 图片。

## P06 · 短信发送与冷却

页面和主进程均阻止并发发送。成功后冷却至少 60 秒；主进程持有截止时间，刷新页面或改手机号不能绕过当前窗口内的冷却。此记录不跨应用重启持久化。

HTTP 429 和有效 `Retry-After` 按响应期限等待；没有有效期限的 429 等待 60 秒。其它失败允许用户修正输入后重试，不自动发码或猜测业务限流码。

## P07 · 短信登录

主进程提交手机号、短信码、`origin=app` 和 `application=uniwork`，校验业务状态、UID、token 和未来有效期。UID 接受非空字符串或非负安全整数，期限不使用默认值。

加密保存成功后才建立身份。关闭或到期后的迟到结果不能继续准备账号；有效身份下的重复登录请求复用当前身份。新增 IPC 只返回脱敏手机号和有效期，不返回 UID 或 token。

## P08 · 加密登录记录

`CredentialStore` 在固定 `userData/maas-login.enc` 保存平台身份域、UID、token、原有效期和脱敏手机号。使用 Electron `safeStorage` 与原子文件替换；系统加密不可用或保存失败则登录失败，不回退明文或仅内存保存。

读取失败、损坏、解密失败或字段不合法时保留原文件。完整手机号、验证码、短信码和模型 Key 不写入这份记录。

## P09 · 本地恢复

1. 主进程读取并解密记录，检查平台身份域、UID、token、有效期和脱敏手机号。
2. 完整且未到期，恢复原 UID、token 和原期限。
3. 无记录、损坏或到期，显示登录表单，保留数据。
4. 恢复身份后单独查询套餐，再准备原账号环境。

恢复本身不联网、不重新写记录、不延长期限、不解析 JWT，也不静默刷新。页面等待恢复结果后才决定是否获取验证码。

## P10 · 独立套餐查询与交接

主进程使用登录 token 查询 `my-plan`，合并并发请求，区分 `available / empty / failed`。模型 Key 与完整目录由主进程保管；IPC 只返回状态、模型名称与默认标记。

查询结束且身份、窗口来源仍有效时自动触发账号准备。无套餐或失败也可进入桌面；配置写入规则见[账号环境](02-local-environment.md)。环境或后端启动失败由启动失败提示处理，不在登录窗口内重复初始化运行时。

各请求超时 15 秒，拒绝跳转、不携带 Cookie、不自动重试。查询失败不直接清除身份；HTTP 401／403 单独记录为套餐鉴权拒绝。

## 当前验证边界

R11 复测了受控短信链、系统加密与跨进程恢复、套餐交接、账号准备及新登录页的宽／窄窗。真实短信双账号、跨登录 UID 稳定性和模型调用仍需人工验收；套餐 401 首次重登提示仍是未解决问题。完整命令与结果见[整理计划的 R11 记录](04-desktop-consolidation-plan.md#r11-实施记录2026-10-10)。
