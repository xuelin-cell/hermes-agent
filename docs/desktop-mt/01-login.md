# 阶段一：公共 Login 与登录界面

状态：开始实施；P01 契约记录已建立，真实登录样本待补，P09 恢复验证受阻，其他功能尚未实施。前置约束见 [总计划](README.md)。对应原步骤 1～8。

本阶段重点是能真实打开和使用登录流程；进入 Hermes 账号环境由阶段二接入。除 P01 的接口记录外，每个单元预计新增／修改约 100～300 行产品代码；超出时继续拆分，不压缩成难读代码。

## P01 · 固定接口契约与恢复登录规则

当前证据见 [MaaS 契约](MAAS_CONTRACT.md)；P01 的执行结果见提交 `4c51af14`。

- 提交主题：`docs(login): 明确 MaaS 接口和恢复登录判定`。
- 范围：新增脱敏的接口契约文档。依据 Web `maas.py` 和真实响应，记录 URL、请求字段、响应包裹、业务 code、超时及错误类型。
- 已知接口：`GET /app/login/captcha`、`POST /app/login/sendCode`、`POST /app/login/smsLogin`、`GET /app/gateway/uniwork/my-plan`；默认 `origin=app`、`application=uniwork`，不得自行发明新 application。
- 核对 UID 类型与稳定性、`expiresAt` 毫秒／`expireIn` 秒、模型 Key 与登录 token 的区别。UID 必须来自主进程直接完成的可信登录响应。
- 实际验收：用户通过正常流程登录，提取脱敏字段结构；对照未携带 token、明确失效 token 和无套餐场景。不存在相应样本时明确注明；不能拿无 token 代替“有效但无套餐”。
- 完成条件：可清楚区分已确认行为和未验证行为。恢复规则若仍缺外部证据，P09 标为受阻，不用自制 JWT 解码、空套餐或 HTTP 200 替代验证。
- 不发送重复短信、不复用已消费验证码、不在记录中保留实际凭据。文档提交本身不代表接口已全部验收。

## P02 · 分离桌面窗口与后端启动

- 提交主题：`refactor(desktop): 分离桌面启动与本地后端启动`。
- 预计位置：`electron/entry.ts`、`electron/main.ts` 的启动接线和一个小的启动协调模块。
- 行为：提供不启动 Hermes 的登录窗口入口；账号放行前不启动安装引导、后端、Profile 预热或自动连接。
- 自动检查：测试重复启动请求、取消与无账号三种行为；TypeScript 编译和已有启动测试。
- 真实验收：用独立桌面数据目录打开程序，确认窗口可用且没有新建 Hermes 后端进程。启动器已有 Node/Vite/Electron 进程不算后端。
- 边界：本提交尚未接入 MaaS。未实现部分展示准备中的状态，不能提供免登录进入聊天的生产入口。

## P03 · 验证开发模式的桌面重启

- 提交主题：`fix(desktop): 保持开发服务运行并支持桌面重启`。
- 预计位置：`apps/desktop/scripts/` 的小启动协调脚本及 `package.json` 必要接线；优先复用既有进程管理能力。
- 行为：明确区分正常退出和有意重启。自动重启保留 Vite、使用同一开发仓库、只启动一个新 Electron；正常退出能结束开发启动链。
- 自动检查：重启意图只消费一次，崩溃不会产生无限重启；测试夹具中的旧进程先退出、新进程后出现。
- 真实验收：沿用用户启动入口，连续触发两次受控重启，记录 Electron PID 变化和 Vite 可访问；手动退出后不自动重开。
- 边界：重启探针只用于隔离测试夹具，不新增长期存在的用户调试按钮；本机 Git Bash 脚本仍不入库。

## P04 · 接入登录页面

- 提交主题：`feat(login): 增加桌面短信登录页面`。
- 预计位置：`src/app/login/`、Renderer 入口与已有样式／国际化组织位置。
- 行为：参考 Web 卡片布局，提供手机号、图形验证码、短信码、按钮及内联错误提示。使用现有桌面组件和主题机制。
- 自动检查：表单校验、提交中禁用、键盘操作和错误展示；不把截图像素作为唯一断言。
- 真实验收：实际窗口中检查浅色／深色、窗口缩小、键盘 Tab 和 Enter；尚未接入的请求入口明确不可用。
- 边界：无开发免密登录、无云端选择；不先挂载聊天页面再用登录遮罩覆盖，避免后台已开始读取旧数据。

## P05 · 受限 IPC 与真实图形验证码

- 提交主题：`feat(login): 通过主进程获取 MaaS 图形验证码`。
- 预计位置：`electron/login/` 请求模块、受限 preload、共享类型及登录页。
- 行为：Renderer 只能调用明确的验证码动作；MaaS URL 在主进程固定，不允许页面传任意 URL、请求头或文件路径。
- 自动检查：非受信窗口／子框架调用被拒绝，网络超时可恢复，迟到的刷新响应不覆盖更新的一张图。
- 真实验收：打开页面能看到真实验证码，点击能刷新；检查请求来自主进程。失败后有重试，未启动 Hermes。
- 边界：若登录页与原 preload 共用窗口，必须证明登录页拿不到原有文件／进程操作权限，不能只靠隐藏按钮。

## P06 · 短信发送与倒计时

- 提交主题：`feat(login): 接入短信发送和重复点击保护`。
- 行为：提交手机号、图形码和 captchaId；成功才开始倒计时，失败允许修正并刷新验证码。页面和主进程都阻止并发重复发送。
- 自动检查：校验失败不发请求、重复点击仅发一次、失败不残留倒计时。限流时尊重上游响应。
- 真实验收：用户输入自己的信息并点击发送，确认收到短信；由用户决定是否额外验证错误图形码，不自动批量发码。
- 边界：不自动重试短信发送，不保存明文手机号、图形码或短信码到日志。

## P07 · 短信登录与可信账号身份

- 提交主题：`feat(login): 建立 MaaS 登录身份与有效期`。
- 行为：主进程校验登录响应，保存当前进程内的 UID、token、有效期；页面只收到脱敏账号、状态和必要有效期信息。
- 自动检查：缺失 UID/token/有效期、错误业务 code、已过期和并发登录响应；失败不留下半登录状态。
- 真实验收：用户完成一次真实登录，页面显示正确脱敏账号；用替身服务模拟过期与错误字段，清楚标注该部分不是上游实测。
- 边界：先不启动 Hermes，也不把身份声明写入账号目录；主进程重启后的恢复由后续步骤完成。

## P08 · 加密保存完整登录记录

- 提交主题：`feat(login): 加密保存账号登录记录`。
- 行为：把平台命名空间、UID、token、有效期作为一份记录，通过 Electron 系统加密能力保存，文件原子写入。
- 预计位置：`electron/login/credential-store.ts` 及 Login 接线；独立于原版可选的连接凭据加密开关。
- 自动检查：损坏密文、解密失败、保存失败、记录字段错配；不得回退为明文文件。
- 真实验收：在 Windows 的隔离 Electron 夹具中加密、退出、重开并解密；检查磁盘记录不包含明文 token。保留原始失败文件供诊断，不覆写账号数据。
- 边界：加密存储本身不代表可以自动恢复登录；MaaS 模型 Key 最终供原版后端读取的形式见 P13。

## P09 · 按已核实规则恢复登录

- 提交主题：`feat(login): 恢复有效账号并区分重新登录与重试`。
- 前置：P01 的恢复身份规则有足够证据，P08 可用；不能因后续步骤需要而跳过此条件。
- 行为：读取、解密、检查期限，再按已确认协议验证。明确失效回登录页；网络或不确定结果显示重试，不启动账号环境、不删历史。
- 自动检查：正常恢复、到期、撤销、网络失败、空套餐和篡改记录。验证结果未到时不得开始账号启动。
- 真实验收：关闭重开恢复同一真实账号；断网重试、过期重登分别验证。若撤销行为无法复现，单独写为未验收。
- 边界：不自行延长上游期限、不静默刷新、不用未验签 JWT 的字段作为新身份。

## P10 · 套餐获取与模型信息解析

- 提交主题：`feat(login): 解析 MaaS 套餐模型并区分查询结果`。
- 行为：解析 `apiKey`、字符串或对象形式的 `models`、`main_model_id`、各模型专用地址。补 `/v1` 的规则沿用核实后的契约，保留专用路径。
- 将有套餐、可信身份下确认无套餐、查询失败分开；没有套餐不取消已经可信建立的账号身份。无 token 的空响应不是确认无套餐。
- 自动检查：多模型、同名不同地址、缺失字段、无 Key、非 JSON、业务失败和超时；不能只按模型名去重后丢掉不同端点。
- 真实验收：页面显示真实账号套餐的模型名称，主进程保管模型 Key；可用的无套餐账号另测。没有样本的情况只报告解析测试结果。
- 边界：不写 Hermes 配置、不调用付费模型。模型 Key 不通过新增 Login IPC 返回页面；原版模型设置能力不在本步改造。
