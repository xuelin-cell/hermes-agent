# 三场景统一执行与代码能力

目标：hermes-agent/release。日常办公、学习生活、代码开发的新建会话共用原 Hermes 创建与执行路径，场景不再决定执行器。Hermes Python 核心保持不变。

## 当前开放范围

数字员工 `/codex` 暂时停用：桌面补全和帮助不展示，手动输入不派发；插件不注册该斜杠命令及执行提示钩子，`hermes kit` 不提供 `codex` 子命令，保留 CLI 实现也拒绝启动。原实现和下述历史验证保留，供未来明确恢复时使用；不表示当前功能开放。三场景普通 Hermes 开发任务保持可用。完整重启后加载后端变更，已有历史不迁移、不删除；本次不修改旧 `code_mode` 核心执行分支。

## 已实现

- 三场景侧边栏统一展示全部会话历史，取消普通列表、置顶候选、搜索结果、归档及项目分组中的场景过滤；保留原账号/连接范围、用户主动筛选和原会话身份。删除无调用者的项目场景筛选辅助函数，不改写已存分类或会话记录。

- 主聊天和分屏新建不再因代码场景自动传 `code_mode=true`。已有模型、所属连接/Profile、目录、会话分类与界面布局规则保留；使用与办公/学习相同的后端默认规则，不改写用户显式配置的运行方式。
- 专家、技能、插件和连接器沿原 Hermes 能力机制使用，不再复制一套 Codex 能力配置。其可用范围、安装依赖与会话工具快照时机均遵守原机制；不承诺安装/更改后正在执行的轮次立即切换。
- 删除桌面专用能力投影目录、前端新建/冷恢复等待、连接器更新回调、专用通信接口/类型、打包项、提示文案及专用测试。原连接器保存、授权、刷新和启动仍保留。
- 原生 Codex 运行时及其会话模型代理保留，用于旧会话兼容与后续按需编码；本次没有删除用户配置、凭据、历史或生成过的受管配置。

## 旧代码会话

旧记录持久保存 `code_mode`，直接恢复仍沿旧执行方式；本次不批量修改数据库、不静默关闭或重建正在运行的实例。

现有侧栏历史会话菜单中的“分支”可以复制已保存历史并创建普通 Hermes 子会话。公开 `session.branch_stored` 保存子记录时不继承 `code_mode`，保留父会话来源、历史、目录及所属 Profile。原记录不改。分支沿原新会话模型配置规则，不等于把旧临时模型选择、工具快照或未保存的运行中状态全部迁移。

## 用户显式 `/codex` 编码

数字员工自己的 `/codex` 通过现有 `uniwork-kits` 的公开 `ctx.register_command` 注册为斜杠命令，出现在原生命令目录、帮助和补全中，不作为技能提供。桌面收到该命令确认的原始输入后，交给既有 `send` 分支，复用正常会话发送和排队；没有新增任务执行器。裸 `/codex` 只显示用法，不启动模型。

原来的 `skills/uniwork/codex` 及技能展开解析已删除。原生技能同步负责移除旧内置副本；用户修改过的副本沿原机制归档，其他技能保留。Hermes 自带 Codex 技能未改动。

- 现有插件 `pre_llm_call` 经公开 `ctx.state` 按 Profile/会话交接本轮显式输入和模型选择，`post_llm_call` 清空参数；CLI直接读取本轮参数，不再改写shell命令或接受可重放的 `--request`。宿主进程结束后残留参数失效；不查询最新用户消息，因此排队输入不会改变当前任务。只有 `/codex 任务内容` 才允许运行。裸命令请用户补充任务，普通编码消息和历史调用不提供启动资格。
- 子命令附于已有 `uniwork-kits` 插件，保留本轮参数传递、账号模型校验及原有 Codex 协议转换；复用原生插件 state 交接参数，轮次结束只留下空键；不保存任务历史、结果或凭据，不新增任务管理机制。没有新增专用RPC、IPC、任务服务、状态仓库、弹窗或独立任务表。
- 模型名称与提供方读取本会话原生记录，跟随用户在当前会话的选择，不另取账号默认模型。未单独指定提供方的会话沿用所属 Profile 的提供方；对应专用 Key 仍来自所属数字员工账号。Profile 的任务与目录从本 Profile 读取。选择个人模型、Key 缺失或提供方身份不匹配时拒绝，不回退到其他资源；计费由数字员工模型服务处理。
- 每次执行使用临时独立 Codex 配置目录，复用现有运行组件和 `CodexChatProxy`；凭据不放命令行或工具输出，不读取个人 Codex 配置。PATH 指向旧 Hermes 安装时，CLI 使用桌面已声明的 Python 与运行目录继续执行；没有替换全局命令、修改旧安装或注入其他工具。缺组件时提示修复安装，不要求反复输入。
- 运行状态、输出、停止和结果沿原生终端工具及当前会话历史展示；Hermes 据此继续回复。前台执行，原生停止负责终端进程树清理；不另开会话。
- 额外权限或第三方交互请求明确拒绝并停止，不自动同意。运行器仍限制工作目录写入和网络，不替代 Hermes 终端本身的审批。

## 验证与边界

原生命令注册/目录/分发、退役技能重复同步清理、现有 kit 命令分发，以及本轮显式输入、账号和 Profile 隔离使用临时配置和原生数据库验证。

真实 Codex 0.147.0（macOS arm64）通过原生 LocalEnvironment 执行插件 CLI（此前探针曾替换 hermes 入口，因此这部分结果不证明真实入口已接通），以本机合成模型验证 A→B→A 账号绑定、实际文件写入、审批拒绝、普通消息拒绝及原生中断后的后代进程退出。退出码为 0、3、2、130；没有付费调用。

旧 `code_mode` 会话继续保留原方式，未自动迁移。不修改 Hermes Python 核心，不操作用户窗口，不提交或推送。实际服务商质量、账单扣减和其他操作系统未实测，不能写成通过。

普通能力页三个场景均为专家、技能、连接器；原生开发者/嵌入插件管理保留。取消入口后的七个旧编辑器及代码项目树专用实现/测试已删除，共用预览、改动对比和旧地址跳转保留。

实际命令入口回归：以产品打包脚本准备插件，使用现场原始 PM hermes 命令（不替换 shim），经原生 hook、工具分发和终端进入桌面所选运行目录；真实 Codex 0.147.0 完成六组本机模拟模型测试：模型 A→B→A、专家 Profile、另一账号及选中模型失败。各组使用原生队列提前写入后续消息，当前任务均未串用；普通新轮由CLI拒绝。失败组对同一模型重试后退出，没有更换模型。此前定向回归 154 项通过、1 项 Windows 平台跳过；未测试实际服务商计费或操作现有用户窗口。

命令边界回归覆盖 `--help` 不执行、`cd DIR &&` 与 `env` 正常调用、旧 `--request` 拒绝，以及轮次结束/普通新轮拒绝。同一后端双会话并发实测通过，两次模型请求重叠，任务、模型、目录和结果各自对应；原始证据见开发工作区 R409；模型服务使用本机测试替身，不等同真实计费或跨平台验收。

运行组件交付：CLI在调用前通过原生 `pm.ensure("codex")` 准备锁定版本，再读取受管绝对路径；不依赖宿主PATH，不自行编写下载器，不更改模型选择。安装策略禁止或下载失败时报告组件准备失败，不归因为额度不足。旧测试曾把另一安装目录的Codex加入PATH，因此不能证明数字员工运行目录缺组件时可用；已在实际缺组件的数字员工运行目录通过该公开接口完成安装及版本检查；移除额外Codex PATH后，同后端双会话并发与六组模型/账号/Profile验证通过，Python定向110项通过、1项平台跳过。
