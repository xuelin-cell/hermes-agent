# 每个对话独立工作文件夹（对齐 UniWork）

日期：2026-10-19。状态：第一步已实现，自动测试通过；实机检查待用户验收。第二步待消息接入合并后再做。

## 概述

现在没选目录的对话全部共用账号的 `workspace\`，文件混在一起，同时运行的对话还会互相影响交付卡片。改为与 UniWork 安装版一致：**没选目录的新对话，发第一条消息时在 `workspace\` 下自动建一个本对话专属文件夹**，AI 在里面干活。用户主动选了目录的照旧。

分两步：第一步只做桌面新对话；消息平台和定时任务等消息接入（`12-messaging-integration-plan.md`）合并后再做。

## 已确认的决定

| 项 | 决定 |
| --- | --- |
| 文件夹位置 | 账号 `workspace\` 下一层，例如 `%LOCALAPPDATA%\hmt\<12 位>\workspace\20261019-103015\` |
| 文件夹名 | 本地时间 `YYYYMMDD-HHmmss`；同一秒已存在时依次加 `-2`、`-3` |
| 建立时机 | 普通新对话在发第一条消息时建；只打开新对话不发消息不建。分屏或标签栏“+”新开的对话，Hermes 打开时就创建会话，文件夹也随之建立，没用过的标签会留下空文件夹 |
| 跨对话提示 | 不加。新对话的 AI 只在自己文件夹里工作，与 UniWork 相同 |
| 旧对话 | 不迁移，仍在 `workspace\` 根目录 |
| 分叉对话 | 沿用原对话的文件夹，不新建（分叉不走普通发送和分屏新开入口） |
| 删除对话 | 不删文件夹，避免误删用户文件；与 UniWork 相同 |
| 模型提示词 | 不加。不照搬 UniWork 的 `tmp\`、`outputs\` 约定，也不新增技能说明 |

## UniWork 对照

核对 `Kyle549/UniClaw` 的 `uniwork_release` 分支和本机已安装的 UniWork 数据：

| 类型 | UniWork 的做法 |
| --- | --- |
| 桌面对话，未选目录（安装版） | 每个对话 `%APPDATA%\UniWork\sessions\session_<毫秒时间戳>\`，内含 `outputs\`、`tmp\`；打开新对话即预建，本机 60 个中 42 个为空 |
| 桌面对话，未选目录（U 盘便携版） | 自动选中 U 盘根目录 `工作空间\`，所有对话共用 |
| 桌面对话，选了目录 | 在所选目录工作，并在其中建 `outputs\`、`tmp\` |
| 微信、飞书、钉钉、企业微信 | 共用固定的 `sessions\claw\`；发给某个专家的用 `sessions\claw-<专家编号>\`；不允许选目录 |
| 定时任务 | 每个任务一个 `sessions\cron-<任务编号>\`，每次运行共用；可选“工作空间” |

本方案有意保留的差别：

- 名字用好认的时间，不用毫秒时间戳。
- 发送时才建，不留下空文件夹。
- 不预建 `outputs\`、`tmp\`。Hermes 没有这两个目录的约定；生成类工具下载时照旧在用到时建 `outputs\`。
- 专家（配置档案）自己设了工作目录的，照用专家的目录。

## 第一步：桌面新对话

### 什么时候自动建

以下条件全部满足才建，任何一条不满足就保持现有行为：

1. 本机桌面账号环境，主进程提供建文件夹接口。云端浏览器版和非账号环境不变。
2. 普通发送或分屏新开的普通对话。Bot 工作区标签、新手引导对话不建。
3. 用户没有主动选目录（没有 `cwd_explicit`，或选回了“默认工作区”）。
4. 目标配置档案的默认目录就是账号 `workspace\`：按档案调用 `config.get project` 取得，与主进程持有的账号工作区比较。专家设了自己目录的不建。

建好后以 `cwd` 加 `cwd_explicit: true` 发给后端，后端按“用户选了这个目录”处理。`session.create` 失败时，请主进程删掉这个刚建、仍为空的文件夹。

### 改动位置

不改 Python 后端和 Hermes 核心。

| 部分 | 位置 | 说明 |
| --- | --- | --- |
| 建、删文件夹 | 新增 `apps/desktop/electron/entry_local/conversation-folder.ts` | 只在当前账号 `workspace\` 下操作；名字由主进程生成，不接受页面传来的路径或名字；独占创建防止重名覆盖；拒绝链接和 junction；删除只针对本进程刚建且仍为空的文件夹 |
| 受限接口 | 账号 IPC 注册处加通道，`preload.ts` 加对应方法 | 来源校验沿用 `isDesktopRendererSender`；参数只有页面查到的默认目录，主进程核对后才建 |
| 发送时接入 | 新增 `apps/desktop/src/app/chat/composer/workdir-mt/conversation-folder.ts` | 判断上面四个条件、调用接口、失败清理 |
| 两个创建入口 | `use-session-actions/index.ts` 的普通发送和分屏新开处各加一行调用 | 标注 `// desktop-mt:` |
| 选择器 | `workdir-mt/` 文案和 `folders.ts` | 发送前仍显示“默认工作区”，说明改为“每个新对话会在默认工作区中新建一个文件夹”；对话开始后显示文件夹名，点开看完整路径；“最近使用”排除自动建的文件夹（按位置和名字格式识别） |
| 文档 | `07-chat-workdir.md`、本目录 `README.md` | 更新行为说明和与 UniWork 的差别 |

### 已知限制（不改核心的代价）

- 侧边栏改成“分组 → 项目”时，每个自动文件夹会各成一组。这个分组由后端 `tui_gateway/project_tree.py` 按文件夹生成，排除它们需要改核心。默认“按日期”显示不受影响，UniWork 也没有这种分组，建议先接受。
- 发了消息但 AI 没写任何文件的，会留下空文件夹，不自动清理。UniWork 同样不清理。
- 旧对话的目录是 `workspace\` 根目录，包含所有新文件夹。旧对话和新对话同时在跑时，交付插件仍判为目录冲突、两边都不靠目录对比补卡片；旧对话不再使用后自然消失。
- 不加提示词，所以两种现有情况不变：模型留在文件夹里的中间文件（如排版检查时渲染的页面图片）可能被补成卡片；模型偶尔把成品写到别的目录（如 `home\cache\scratch\`），这时只靠它自己写的 `MEDIA:` 出卡片。两者都与是否分文件夹无关。

## 影响评估

### 路径长度

上次超长的是下载 Python、装插件、装专家和依赖包，都在账号 `home\` 里，路径到了 285～321 字符（见提交 `7906c2d02f`）。本方案不改 `home\`。

| 位置（本机实测，用户名 4 个字符） | 长度（字符） |
| --- | --- |
| 现在的 `workspace\` | 54 |
| 加一层对话文件夹 | 70 |
| 第二步的定时任务文件夹 `cron-<12 位编号>` | 72 |
| UniWork 的对话文件夹 | 68 |
| `workspace\` 现有最长文件（AI 建的 Python 环境里的文件） | 183 → 199 |
| 同一文件，换成 Windows 允许的最长 20 字符用户名 | 215 |

最坏情况离 260 上限还有 45 个字符。

### 功能

| 功能 | 影响 |
| --- | --- |
| 插件、专家、依赖、内置 Python | 无，都在 `home\` |
| 用户删掉某个对话的文件夹 | 再打开时 Hermes 自动退回上一层 `workspace\`（`tui_gateway/session_workdir.py::_heal_dead_cwd`） |
| 右侧文件面板 | 只显示本对话的文件 |
| 交付卡片 | 两个新对话同时在跑时，各自文件夹互不包含，不再因冲突少出卡片；每个文件夹很小，结束时的目录对比不会因超过 3000 项失效 |
| 专家自带工作目录 | 照旧使用专家目录 |
| 设置 → 会话 → 默认项目文件夹 | 未设置时显示账号 `workspace\`（原版写死为系统用户目录，2026-10-19 修正）；设置了目录后，新对话都在该目录工作，不再自动建对话文件夹 |
| `workspace\` 根目录的说明文件（AGENTS.md 等） | 子文件夹里读不到；本机两个账号的 `workspace\` 均没有这类文件 |
| 跨对话用文件 | 新对话只看自己文件夹，需要用户给出路径；与 UniWork 相同 |

实机检查（需要真实模型调用的项由用户操作或明确授权）：

1. 新对话发消息：文件夹按时建好，AI 在里面工作，交付卡片和右侧文件面板正常。
2. 让 AI 在对话里建 Python 环境、装 npm 包，不报路径过长。
3. 装一个插件和一个专家，`home\` 不受影响。
4. 删掉某个对话的文件夹再打开该对话，退回 `workspace\`。
5. 手动选目录、Bot 对话、定时任务的行为与改动前一致。
6. 开两个新对话，同时让它们生成文件（一个生成图片、一个写 Word），两边都出卡片。
7. 从某条消息分叉出新对话，新对话仍在原文件夹工作。
8. 重新统计 `workspace\` 下最长路径。
