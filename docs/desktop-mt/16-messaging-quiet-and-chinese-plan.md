# 消息平台低打扰与中文提示：单提交实施计划

日期：2026-10-23。实施分支：`release`。整理时本地 HEAD：`accc960d06`；复核时 HEAD：`68a35d0f2b`。

状态：第一轮已按正式扩展可用范围实施并完成定向验证。第一至八节保留用户修订的第一轮需求基准，第九节记录该轮交付；第二轮补充以第十节为准，替代第一轮“混用 5G 保留忙碌回执”的限制，并新增桌面与消息平台共享的记忆通知默认设置。未改核心、未操作真实用户运行实例。

## 一、目标

用户通过微信、钉钉、飞书和企业微信发消息时，尽可能直接得到回答和交付物，不必理解网关、工具、Profile 或命令教程。

统一原则：**正常过程静默，必要交互简短中文，失败说明准确，技术细节留在日志。**

- 保留运行中追加指令、引导、排队和原有执行能力，只减少对应的固定回执与教程。
- 正常聊天主要展示最终回答、交付文件和平台原生等待效果。
- 用户明确要求的后台结果、定时提醒不是噪声，继续按原投递规则发送。
- 任务确实未完成、附件未送达、需要用户确认或会话数据出问题时，不能用静默冒充成功。
- 固定系统提示以简体中文表达。模型回复继续尊重用户明确的语言要求，不翻译用户引用、代码或外文资料。

## 二、范围与不可突破的边界

### 本轮范围

- 个人微信 ClawBot、钉钉、飞书、企业微信智能机器人。
- 已有账号和新账号的消息展示配置、受管 Profile 的生效路径。
- 桌面自动恢复、首次连接、保存配置后重启、手动重试，以及关闭应用时的相关展示。
- 常规聊天与高频控制操作涉及的固定系统提示。

### 本轮不做

- 不修改 Hermes Python 后端核心，包括 `agent/`、`gateway/`、`hermes_cli/`、`tools/`、`tui_gateway/` 等既有核心文件。
- 不通过插件猴子补丁、替换网关内部方法或检查调用栈来绕过上述边界。
- 不改变消息调度、任务执行、排队模式、账号鉴权、危险操作审批、会话存储或数据恢复语义。
- 不改 SOUL、自我介绍模板或公共模型身份提示词。
- 不改 5G／uniAgentGate、官方对照版、用户历史和文件。
- 不新增独立消息网关、翻译服务、模型翻译调用或通用插件框架。
- 不全面翻译数十个高级管理命令的所有分支；未覆盖分支明确记录，不宣称全量中文化。
- 不处理第三节第 11 条所列核心硬编码英文失败提示（用户已确认）：本轮保持原样，在交付清单中列为“未覆盖”，不在平台适配器里做整句映射，也不改核心文案。
- 不承诺应用关闭后任务继续，也不借本计划实现自动任务恢复。

## 三、当前已经核对的事实

1. 微信、钉钉、企微的源码默认展示较安静；飞书默认显示工具变化、中间解说与长任务通知。显式配置仍可能覆盖默认值。
2. 工具进度、中间解说、推理、Working 心跳和忙碌回执是不同通道。只设置 `tool_progress: off`，不能关掉其余提示。
3. 原生 `HERMES_GATEWAY_BUSY_ACK_ENABLED` 检查位于输入处理之后，可以隐藏普通忙碌回执而保留该次输入处理。它不等于覆盖所有主动命令回执或停机期间来信说明。
4. `gateway_restart_notification` 同时影响启动、重启和停止通知，还涉及部分定时任务中断通知。不能只按配置名称判断影响范围。
5. Home channel 教程在空历史且未设置目标时发送，并非严格意义上的每个平台仅首次连接一次；新建会话后仍可能出现。
6. 当前没有统一的“所有消息发送前改写”插件钩子。普通插件的模型输出转换不能覆盖网关直接生成的固定提示。
7. 部分系统提示走中文目录，部分硬编码英文；设置中文语言并不等于所有分支自动翻译。
8. Home channel 提示的发送入口没有专用的通知类型标记，不能假定发送层已经能可靠识别它的来源。
9. 核查时桌面受管消息网关没有统一设置语言。中文目录可以覆盖 `/stop`、重置结果及部分审批结果，但 `/new` 的破坏性确认、危险命令审批标题／期限、超时等仍有核心硬编码。目录条目数一致不能证明所有交互已中文化。
10. 多账号时 `HERMES_LANGUAGE` 经 Profile 的 secret 作用域读取，只在启动进程里传环境变量不一定对该 Profile 生效；`display.language` 写入该 Profile 的 `config.yaml` 更可靠（见 `agent/i18n.py` 的 `get_language`）。该设置不进入模型提示词，但与桌面界面及同 Profile 的其它渠道共享，不能同时宣称不影响其语言。显式环境语言仍优先。
11. 以下失败提示在核心中硬编码为英文，且带命令教程，不走中文目录：
    - 通用失败 “Something went wrong… Use /retry… /new… `hermes logs`”（`gateway/run_turn.py`，约 2032 行，含限流、额度、400 拒绝等分支后缀）；
    - 模型空回复 “{model} didn't produce a reply… Send `continue`… /model”（`agent/turn_explainers.py` 的 `EMPTY_RESPONSE_EXPLANATION`）；
    - 会话历史暂不可用（`gateway/run_turn.py`，约 2109 行）；
    - 后台任务无法启动或中途失败（`gateway/run_turn.py`，约 2441、2555 行）。
12. 个人微信扫码保存时已自动写入 `WEIXIN_HOME_CHANNEL=扫码用户`（`plugins/weixin_qr/dashboard/plugin_api.py`），微信不会出现 Home channel 教程；该教程只影响钉钉、飞书、企微。这三个平台当前按 `*_ALLOW_ALL_USERS=true`（飞书、企微群聊也为 open）开放，第一个私聊者不一定是机主，不能照搬微信的自动设置。
13. 聊天中创建的定时任务默认投递回原会话（`cron/jobs.py` 中有 origin 时 `deliver="origin"`），未设置 Home channel 对用户主动创建的提醒影响很小。
14. 忙碌回执除环境开关外，还有按平台的展示项：`busy_steer_ack_enabled` 可关闭引导（steer）模式的回执；`busy_ack_detail` 只控制回执中的迭代／工具细节，不关闭回执本身。排队、中断等普通回执仍需 `HERMES_GATEWAY_BUSY_ACK_ENABLED`。

主要核查入口：

- `gateway/display_config.py`：平台展示默认值与解析规则。
- `gateway/run_busy.py`：忙碌输入处理、回执与首次教程。
- `gateway/run_turn.py`：首次接触与 Home channel 教程、运行期展示。
- `gateway/run_shutdown.py`、`gateway/run_notifications.py`：生命周期和后台通知。
- `gateway/platform_registry.py`、`hermes_cli/plugins.py`：正式平台注册与可用插件扩展能力。
- `agent/i18n.py`、`locales/zh.yaml`：固定文案的语言解析和中文目录。

以上核心文件只作为阅读依据，不列入本计划的修改范围。

## 六、实施顺序：验证随步骤完成，最后一个提交

### Q01：先验证无核心改动的扩展能力

- 逐项登记本轮目标消息的产生位置、类型标记、发送入口、原生开关和平台差异。
- 优先验证钉钉、飞书、企微的 Home channel 教程（微信已由扫码设置接收人，不在此列），以及审批和澄清，明确哪些能够可靠区分系统提示与正常回复。第三节第 11 条的核心硬编码失败提示不在验证与处理范围内。
- 核对正式平台注册、延迟加载、Profile 作用域及插件重载行为，不依赖碰巧生效的加载顺序。
- 微信只能使用经验证的插件扩展方式；不覆写核心类方法，不改网关内部对象。
- 不做宽泛关键词或英文检测；无法可靠区分来源的分支，不静默、不兜底翻译、不宣称已覆盖。
- **若关键能力缺失，暂停对应实现并报告，不擅自放宽“不改核心”的限制。** 一次提交不意味着可以跳过这个判断。

完成依据：用隔离实例和实际调用入口，证明目标系统提示可以被处理，正常模型回复、引用同类文案的回答及文件交付不会被误处理。

### Q02：统一既有展示开关与启动接线

- 使用各平台独立配置，统一关闭过程展示、推理、长任务心跳和技术尾注，不顺带影响 5G、桌面聊天或其它平台。
- 低打扰设置是本轮产品要求，不仅补缺省值；既有账号显式开启的目标项目也要更新。其他无关设置和凭据保留。
- 为四个平台的受管 Profile 写入 `display.language: zh`（写进该账号 Profile 的 `config.yaml`，不只依赖进程环境变量）；验证审批、`/new`、`/stop`、忙碌回执等走目录的提示显示中文，模型回复语言不受影响。
- 关闭普通忙碌回执：排队、中断等用 `HERMES_GATEWAY_BUSY_ACK_ENABLED`，引导模式回执用平台展示项 `busy_steer_ack_enabled: false`，`busy_ack_detail` 同步关闭；验证输入仍按当前有效模式处理，未被重复排队或丢弃。
- 关闭上下线广播，并检查定时任务被停止的记录／反馈是否受到连带影响，不伪造继续运行或完成状态。
- 核对保存平台、自动恢复、扫码后重启、手动重试的入口一致性；不引入额外重启循环。
