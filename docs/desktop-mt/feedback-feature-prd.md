# 「反馈问题」功能需求文档（可复用版）

| 项目 | 内容 |
|---|---|
| 文档性质 | 产品需求说明（PRD），面向跨项目复用 |
| 适用产品形态 | 桌面客户端（Windows NSIS 安装包 / macOS 安装包），Electron + 本地后端 |
| 参考实现 | `libs/hexagent_demo`（`frontend/src/components/FeedbackTab.tsx`、`backend/hexagent_api/routes/feedback.py`、`electron/main.js`） |
| 文档目的 | 描述"用户上报问题 → 自动采集现场 → 送达研发"的能力边界、交互契约与数据契约，使其他项目可据此重新实现，而不必复用具体代码 |

## 1. 背景与目标

### 1.1 问题

桌面客户端的故障现场高度分散，用户口述往往无法定位：

- 后端日志在本地数据目录，用户不知道路径，也不该被要求去找；
- 渲染进程报错只在 DevTools 里，用户不会开、开了也已经滚走；
- 桌面主进程的启动、IPC、更新日志是独立文件，后端看不到；
- 配置形态（执行模式、模型供应商、MCP、构建档位）直接决定复现路径，但用户说不清。

结果是：一条"点不动了"的反馈，需要多轮往返才能凑齐现场，问题常常因此被搁置。

### 1.2 目标

| 编号 | 目标 | 判定方式 |
|---|---|---|
| G1 | 用户在设置页 3 步内完成一次反馈上报，不需要知道任何文件路径 | 首次使用者无需指导即可完成 |
| G2 | 研发拿到反馈包后，不联系用户即可还原运行环境 | 包内含版本、平台、构建档位、配置快照、运行态 |
| G3 | 反馈包内不出现任何明文密钥/令牌 | 抽检任意包，无 `sk-` 形态令牌、无 `token=xxx` 明文 |
| G4 | 弱网或未登录场景下仍能完成反馈 | 云端路径失败时，本地打包保存 100% 可用 |
| G5 | 上报行为对业务功能无副作用 | 打包/上传期间不阻塞会话、不修改用户配置 |

### 1.3 非目标

- 不做工单系统、不做反馈进度回查、不做客服回复通道；
- 不做崩溃自动上报（本功能是用户主动触发）；
- 不做远程诊断、不做远程日志回捞；
- 不做日志的云端长期归档策略（由后台侧负责）。

## 2. 角色与场景

| 角色 | 关心什么 | 在本功能中的位置 |
|---|---|---|
| 终端用户 | 我把问题说清楚就行，别让我找文件 | 表单填写者、上传发起者 |
| 技术支持 / 值班 | 快速判断是不是已知问题、是否要升级研发 | 反馈包的第一读者（钉钉/后台） |
| 研发 / 工程师 | 用哪份日志、哪个时间窗、什么配置能复现 | 反馈包的主要消费者 |
| 后台运营 | 按版本、平台、档位统计反馈分布 | 上传接口的表单字段消费方 |

典型场景：

1. **崩溃/卡死**：用户描述"导出 PDF 后卡住"，选择今天，粘贴截图，上传。
2. **VM/沙箱起不来**：用户选择发生日期，描述"启动就失败"，此时后端日志已被压平为 SSH 错误，必须依赖虚拟机侧产物才能定位。
3. **网络/上传失败**：云端上传报错，用户改走本地打包，通过 IM 把包发给对接人。
4. **未登录/登录态失效**：用户仍可本地打包，不因身份问题丢失现场。

## 3. 名词定义

| 名词 | 含义 |
|---|---|
| 反馈包 | 一次反馈产出的压缩文件（zip），含描述、截图、日志、配置快照 |
| 问题日期 | 用户选择的故障发生日期，用于把工程师的注意力收敛到某个时间窗 |
| 排查指引 | 包内一份面向工程师的 Markdown，说明每个文件是什么、先看哪个 |
| 采集清单 | 本次会随包上传的内容条目集合，必须在提交前对用户可见可查 |
| 云端路径 | 打包后直传公司网关/对象存储，后台可见 |
| 兜底路径 | 打包后落盘到用户选定位置，由用户经 IM 人工转交 |
| 客户端档位 | 同一产品的不同分发形态（如 Lite / Pro / 便携版），决定大量代码分支 |

## 4. 范围

**In scope**

- 设置页内的固定入口与表单
- 现场自动采集（前端日志、桌面日志、后端日志、虚拟机产物、配置快照）
- 打包、脱敏、名称规范化
- 云端上传路径 + 本地保存兜底路径
- 上传后台的表单字段契约
- 中英文案与本地化错误提示

**Out of scope**

- 反馈状态查询、客服回复、工单流转
- 崩溃自动采集、后台静默上报
- 日志上传后的保留期与删除策略
- 非桌面形态（纯浏览器部署仅保留兜底路径，见 §10.6）

## 5. 功能需求

### FR-1 入口

| 项 | 要求 |
|---|---|
| 位置 | 设置面板侧栏固定一项，命名「反馈问题 / Feedback」，文案随界面语言 |
| 可见性 | **始终可见**，不依赖配置是否加载成功、不依赖是否已登录、不按执行模式隐藏 |
| 默认态 | 不是默认选中项，用户主动点击进入 |
| 页脚 | 该页**不出现**"无更改/保存"这类面向配置编辑的全局页脚，动作按钮由本页自持 |
| 优先级 | 置于侧栏末位，避免与配置类入口争夺注意力 |

**验收**：新建用户首次打开设置 → 侧栏可见该项；配置接口报错时该项仍可进入并完成兜底上报。

### FR-2 表单

三项输入，**除登录身份外均允许为空**（允许"只发日志不写描述"）。

**FR-2.1 问题发生日期**

- 控件：下拉单选，默认「今天」。
- 选项：今天、昨天、2–6 天前、以及一项「7 天前或更早」。
- 每个选项文案附带具体日期（如「昨天 2026-11-09」），减少用户对"昨天"的理解偏差。
- 选择结果随包写入元数据，并直接决定工程师的查看起点。
- 「7 天前或更早」是一个粗粒度选项，**不得作为可解析日期外传**（见 §13 偏差 D-6）。

**FR-2.2 问题描述**

- 多行文本，可选，建议展示高度 5–7 行（超出滚动，不撑高整页）。
- 占位文案需明确告知：可以只贴截图、可以 Ctrl+V 直接贴图、可贴多张。
- 换行与中文全角字符原样保留。

**FR-2.3 截图附件**

- 支持三种方式中的至少两种：文件选择（可多选，仅图片）、粘贴板粘贴、拖放（拖放为可选增强）。
- 每张显示缩略图 + 文件名 + 单个删除按钮，可重复添加、可混用不同方式。
- 仅接受图片类型，非图片文件静默忽略且不报错打断。
- 同名文件重复添加不覆盖。
- 提交后截图随包进入 `screenshots/`，文件名需安全化（去路径、去非法字符、限长）。

**验收**：粘贴 3 张 + 选文件 2 张 → 缩略图 5 个；删中间 1 张 → 剩 4 个且不影响其余预览。

### FR-3 采集清单（提交前告知）

提交动作前，用户必须能知道"这次会带走什么"。要求：

- 在表单区域用一句说明概括：会收集**问题描述、截图、近期前端/桌面/后端日志、脱敏后的配置快照**；
- 措辞不制造"已上传"的错觉：云端路径与本地路径要分别说清；
- 采集项变更（新增日志源）时必须同步更新该说明与包内排查指引。

> 复用提示：不同产品对隐私口径要求不同，**采集清单文本必须做成可配置项**，不要硬编码。

### FR-4 主路径：云端上传

| 项 | 要求 |
|---|---|
| 触发 | 「上传到云端」按钮 |
| 前置 | 已登录，且本机可取到用户唯一标识（手机号/uid）与有效访问令牌 |
| 前置缺失 | 就地提示"未找到登录信息，请重新登录后上传"，**不弹出系统对话框、不生成文件** |
| 过程 | 按钮进入加载态，两个提交按钮同时禁用，防重复提交 |
| 成功 | 弹窗告知"已上传，工作人员将尽快查看"，展示后台返回的受理标识（可选） |
| 失败 | 就地展示失败原因，**同屏给出兜底引导**（"请改用『把日志保存到』…"），不清空表单 |
| 二次确认 | 不需要（包内已含用户主动填写的描述与截图，且采集清单已明示） |

**验收**：断网点击上传 → 出现错误提示与兜底引导 → 表单内容完整保留 → 切到兜底路径可直接成功。

### FR-5 兜底路径：本地打包保存

| 项 | 要求 |
|---|---|
| 触发 | 「把日志保存到」按钮 |
| 二次确认 | 需要。说明"将打包日志与描述，下一步选择保存位置，然后请通过 IM 发给对接人" |
| 取消确认 | 关闭弹窗，表单状态完整保留 |
| 保存方式 | 桌面端走系统「另存为」对话框，默认文件名由服务端生成的时间戳命名；浏览器形态走浏览器下载 |
| 用户取消保存 | 视为放弃本次，不报错、不重置表单 |
| 保存成功 | 弹窗展示"已保存"与**完整保存路径**（可读、可复制所指向的位置信息）+ 转交提示 |
| 关闭成功弹窗 | **重置表单**（描述清空、截图清空、日期回到今天），语义上表示本次反馈已结束 |

**验收**：确认 → 另存为取消 → 表单不变；再确认 → 保存成功 → 路径可见 → 关闭 → 表单为空。

### FR-6 幂等与重置

- 兜底路径成功后 → 重置（见 FR-5）。
- 云端路径成功后 → **必须同样重置**，避免同一现场被重复上报（见 §13 偏差 D-3）。
- 任何路径失败 → 一律不重置。

### FR-7 状态模型

| 状态 | 表现 | 可退出 |
|---|---|---|
| 空闲 | 两个按钮可点 | — |
| 打包中（本地） | 本地按钮加载态、两按钮禁用 | 完成后自动退出 |
| 上传中（云端） | 上传按钮加载态、两按钮禁用 | 需支持超时退出（见 NFR-3） |
| 确认弹窗 | 可取消 | 取消/确定 |
| 保存成功弹窗 | 展示路径 | 关闭 |
| 上传成功弹窗 | 展示成功说明 | 关闭 |
| 错误提示 | 就地错误条，不遮挡表单 | 下次提交时清除 |

## 6. 反馈包内容规格

包的定位是"工程师打开就能自己往下走"，因此**必须自带阅读顺序**。

### 6.1 目录结构

```
<timestamp>.zip
├─ 排查指引.md                ← 要求工程师先读；说明每个文件的用途与查看顺序
├─ 问题描述.txt               ← 用户原话；为空时写占位说明
├─ 元数据.json                ← 见 §7
├─ 配置快照.json              ← 当前配置，凭证已掩码
├─ 自定义模型快照.json        ← 可选，凭证已掩码
├─ screenshots/               ← 用户截图，文件名已安全化
├─ logs/
│  ├─ 前端控制台.txt          ← 渲染进程最近 N 条
│  ├─ 桌面主进程.log          ← 桌面壳日志尾部
│  ├─ 业务分域.log            ← 从主进程日志按关键字抽取出的专题日志（可选）
│  ├─ backend/**              ← 本地后端日志目录（按修改时间新→旧）
│  └─ vm/**                   ← 仅 macOS：虚拟机宿主/客户机产物（可选）
└─ ...
```

### 6.2 容量与截断规则

| 规则 | 要求 |
|---|---|
| 日志总预算 | 建议 50 MiB 原始量上限；超出后按"新→旧"停止收集 |
| 单文件超限 | 取**尾部**（保留最近活动），并在文件首行插入一行截断标记，写明原大小与保留量 |
| 前端控制台 | 环形缓冲，建议 500 条，按时间正序导出 |
| 桌面主进程日志 | 读取端尾部截断（建议 2 MiB），避免超大 payload 走 IPC |
| 虚拟机产物 | 单独预算、**不占**日志总预算，否则大后端日志会把最关键的那几百 KB 挤掉 |
| 压缩 | 必须压缩；截图与日志是可压缩文本，压缩率高 |
| 命名 | 默认文件名为时间戳（`YYYYMMDDHHMMSS.zip`），并由服务端在响应中回传，保证"另存为"默认名与包内一致 |

### 6.3 专题日志抽取

从桌面主进程日志中，按关键字前缀（如业务模块标签）抽取相关行，单独落一个文件，帮助工程师跳过启动噪声。要求：

- 抽取行必须同样过脱敏；
- 无匹配行时不生成该文件（不产出空文件）；
- 抽取值是"副本"，主日志仍完整保留。

## 7. 元数据规格

元数据是"盲开者也看得懂"的关键，字段分四组。

### 7.1 时间

| 字段 | 说明 |
|---|---|
| 打包时间（本地时间 + Unix 时间戳） | 便于与各日志时间戳对齐 |
| 问题日期 | 用户选择值（见 FR-2.1） |
| 日志检索窗口起点 | 由问题日期回推若干天（建议 2 天）预计算，供工程师直接过滤 |

### 7.2 版本与平台

| 字段 | 说明 |
|---|---|
| 产品版本 | 后端包版本 |
| 运行时版本 | Python/Node 等运行时版本（按待排查问题选择） |
| 桌面应用版本 | 由渲染层提供的 `app.getVersion()` 结果 |
| 操作系统 / 版本 / 架构 | 复现条件 |
| 渲染层 UA | 捕捉 Chromium 侧差异 |

### 7.3 客户端档位

| 字段 | 说明 |
|---|---|
| 版本档位（build variant） | Lite / Pro / 便携 等，直接决定代码分支 |
| 分发形态（distribution） | 安装版 / 便携版 |
| 版本类型（edition） | 标准 / 企业 |
| 便携标记 | 布尔 |

> 要求：档位判定不能只依赖环境变量，需能在变量缺失时从执行模式等间接信号回退推导，否则打包产物会落下空值。

### 7.4 配置与运行态

| 字段 | 说明 |
|---|---|
| 配置快照 | 当前配置全文，凭证掩码 |
| 自定义模型快照 | 可选 |
| 运行态概览 | 会话数、磁盘会话数、Code 会话列表等轻量计数，用于判断"是不是因为装的东西太多" |

### 7.5 排查指引字段

| 字段 | 说明 |
|---|---|
| 工程师提示 | 一段自然语言：从哪天开始看、没找到该往哪扩 |
| 建议阅读顺序 | 文件清单 + 每个文件"什么情况下看" |

**验收**：把包交给一个没参与实现的工程师，他能在 5 分钟内独立判断"看哪个文件"。

## 8. 隐私与脱敏（硬性要求）

| 编号 | 要求 |
|---|---|
| P-1 | 结构化配置中，键名命中 `api_key / token / secret / password / bot_token / client_secret`（大小写不敏感、可嵌套）的字符串值，替换为 `<masked:N chars>`，**保留长度信息** |
| P-2 | 自由文本（含日志文件、用户可见 URL）中的 `sk-…` 形态令牌、`token=/key=/secret=/password=/access_token=/appkey=` 查询参数、`Bearer …` 头，全部替换为掩码 |
| P-3 | 日志文件在写入包之前必须过脱敏，不能只在配置文件上做 |
| P-4 | 脱敏失败不得导致打包失败：无法解码的内容按可容错方式处理，宁可少信息不可泄密 |
| P-5 | 用户截图不做内容识别，但需在采集清单中明示"截图会被一并上传" |
| P-6 | 密钥/令牌**不落盘、不写日志、不进包**；上传用的访问令牌只在进程内存中保留 |

**验收**：构造含 `sk-` 令牌、`?key=` 参数、`Bearer` 头的配置与日志 → 生成的包内搜不到任何原文。

## 9. 上传接口契约（后台对接）

### 9.1 请求形态

- 传输：multipart
- 主体：`file` = 反馈包（zip）
- 鉴权：`Authorization: Bearer <登录令牌>`

### 9.2 表单字段（后台不拆包即可筛选）

| 字段 | 用途 |
|---|---|
| 上传者标识（手机号/工号/uid） | 归属与联系 |
| 应用标识 | 多产品共用同一后台时区分来源 |
| 问题描述 | 后台列表摘要 |
| 问题日期 | 排序与聚合 |
| 应用版本 | 版本分布 |
| 客户端档位 / 分发形态 / 版本类型 / 便携标记 | 分群定位 |
| 平台系统 / 版本 / 架构 | 平台分布 |
| 截图数量 | 便于判断信息量 |

### 9.3 响应与失败

| 结果 | 要求 |
|---|---|
| 成功 | 返回受理标识与成功消息；消息语言跟随请求语言 |
| 鉴权失败 | 返回明确的"登录态失效"，前端引导重新登录并提示兜底路径 |
| 上游错误 | 返回上游状态码信息，**文案必须引导用户改用兜底路径**，不能只显示英文堆栈 |
| 打包失败 | 单独区分"打包失败"与"上传失败"，因为前者用户重试无用 |

### 9.4 语言协商

- 请求携带界面语言（`Accept-Language`）。
- 服务端所有面向用户的错误文案按语言返回中/英两套；前端只在服务端没给 detail 时兜底。

## 10. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-1 | 性能 | 打包在本地完成；打包期间不得阻塞主线程 UI（桌面端写入磁盘用异步 IO，避免多 MB 同步写冻结窗口） |
| NFR-2 | 体积 | 单次上传建议 ≤ 30 MB（压缩后）；超出应提示用户减少截图 |
| NFR-3 | 超时 | 上传必须有客户端超时（建议 30–60s）与失败出口；不得出现"一直转圈"（见 §13 偏差 D-4） |
| NFR-4 | 离线 | 云端不可用时兜底路径必须完全可用，且不依赖网络 |
| NFR-5 | 兼容 | 仅需覆盖 Windows（NSIS 安装形态）与 macOS 两种桌面分发；Linux/商店版不在本次范围 |
| NFR-6 | 存储 | 临时产物（如导出用的临时文件）用后必须清理；不得在用户目录留下中间文件 |
| NFR-7 | 无副作用 | 打包不得修改用户配置、不得触发模型请求、不得中断进行中的会话 |
| NFR-8 | 可定位 | 每次上报在本地日志留一条不含敏感信息的记录（时间、结果、耗时），便于排查"用户说点了没反应" |
| NFR-9 | 可复用 | 采集源清单、容量预算、上传地址、应用标识均通过配置注入，不硬编码在产品代码里 |

## 11. 边界与异常场景

| 场景 | 期望行为 |
|---|---|
| 未登录 | 云端按钮给出"请重新登录"，本地路径仍可完成 |
| 登录令牌存在但后端未同步 | 后端需明确返回鉴权失败原因，前端引导重新登录；不得让用户误以为"账号被盗" |
| 用户不填描述、不传截图 | 允许，包内写入占位文本 |
| 截图超大 / 超多 | 按 NFR-2 提示；不得因单张超大图导致整包失败 |
| 日志目录不存在（全新安装） | 包内省略该目录，不报错 |
| 日志文件正在被写入 | 允许读到部分内容，不因读取失败中断打包 |
| 主机为 macOS 但从未创建虚拟机 | 省略虚拟机产物目录，不报错 |
| 保存对话框被取消 | 表单保留、无错误提示 |
| 保存路径无写权限 | 展示系统错误原文 + 提示更换路径，表单保留 |
| 打包过程异常 | 提示"打包失败"，**不提示"请重试上传"**（重试无用，应引导反馈给对接人） |
| 重复点击提交 | 按钮禁用；同一现场不应产生两份包 |
| 界面语言切换 | 所有文案立即跟随；已选日期与已填描述不丢失 |

## 13. 参考实现的已知偏差（复用时应避免照抄）

| 编号 | 偏差 | 影响 | 建议 |
|---|---|---|---|
| D-1 | 注释声称支持拖放上传，实际只实现了文件选择与粘贴 | 文档与行为不一致 | 要么实现拖放，要么删掉对外宣称 |
| D-2 | 云端上传无采集清单告知（仅一句"优先上传"） | 隐私口径不清晰 | 按 FR-3 补采集清单 |
| D-3 | 云端成功后不重置表单 | 同一现场重复上报 | 与 FR-6 对齐 |
| D-4 | 两个反馈请求均无超时/取消 | 弱网下永久转圈 | 加超时 + 失败出口 |
| D-5 | 截图无数量与单张大小上限，base64 直塞 JSON | 大图导致请求体过大、易失败 | 客户端先压缩/限张数，或改为分片上传 |
| D-6 | 「7 天前或更早」以字面量外传，无法解析为日期 | 工程师失去时间窗过滤 | 该选项应展开为具体日期或要求用户补选 |
| D-7 | 上传请求不携带令牌，依赖登录时把令牌同步进后端内存 | 后端重启、纯浏览器形态下易误报"登录过期" | 上传请求显式带 `Authorization`，或同步失败时明确降级提示 |
| D-8 | 桌面主进程日志超限只保留后半段 | 早期的专题日志可能丢失 | 专题日志应在写入时实时分流，而非事后从被裁剪的文件里抽 |
| D-9 | 卸载时未释放截图预览的临时 URL | 轻微内存泄漏 | 卸载时遍历释放 |
| D-10 | 旧版内联实现的样式残留（未被引用的 class） | 样式维护噪音 | 迁移时清理 |

## 14. 复用接入清单

在其他项目中落地本功能，需要提供以下**能力**（而非代码）：

### 14.1 桌面外壳（Electron 或同类）

| 能力 | 必需性 | 说明 |
|---|---|---|
| 读取应用版本号 | 必需 | 元数据与上报字段都需要 |
| 主进程日志落盘 | 必需 | 需有固定路径、轮转/截断策略、可尾部读取 |
| 读取日志尾部 | 必需 | 建议限 2 MiB，避免 IPC 大包 |
| 系统「另存为」 | 建议 | 缺失时降级为浏览器下载 |
| 弹出对话框的父窗口绑定 | 建议 | 避免对话框被应用窗口遮挡 |

### 14.2 本地后端 / 打包服务

| 能力 | 必需性 | 说明 |
|---|---|---|
| 打包接口 | 必需 | 输入描述/截图/日期/前端日志/桌面日志，输出 zip |
| 上传接口（或纯前端直传） | 必需 | 若前端直传，则脱敏与打包逻辑需另找落点 |
| 日志目录约定 | 必需 | 后端日志必须集中在已知目录下 |
| 配置快照读取 + 掩码 | 必需 | 需知道配置文件路径与凭证字段集合 |
| 运行态计数（可选） | 建议 | 会话数等轻量指标 |

### 14.3 身份与通道

| 能力 | 必需性 | 说明 |
|---|---|---|
| 用户唯一标识 | 必需 | 手机号/工号/uid，用于归属 |
| 有效访问令牌 | 必需 | 建议由前端在上传请求中显式携带 |
| 上传目的地 | 必需 | 公司网关或对象存储，地址与应用标识需可配置 |
| 后台列表页 | 必需 | 至少支持按时间、版本、平台、档位筛选并下载包 |

### 14.4 文案与设计

| 能力 | 必需性 | 说明 |
|---|---|---|
| 中英文案包 | 必需 | 包含按钮、提示、错误、保存对话框标题 |
| 服务端多语言错误 | 建议 | 按 `Accept-Language` 返回 |
| 亮/暗主题下的弹窗配色 | 必需 | 实践中出现过"亮色主题下弹窗文字近不可见"的回归 |

### 14.5 落地顺序建议

1. 先做**兜底路径**（打包 + 本地保存），它不依赖任何后端通道，可独立验收；
2. 再接**云端路径**（上传 + 表单字段契约 + 后台列表页）；
3. 最后补**采集广度**（虚拟机产物、专题日志、配置快照），每加一项同步更新采集清单与排查指引。

这个顺序的价值是：任何一步中断，用户侧都已经有一条能用的反馈通道。
