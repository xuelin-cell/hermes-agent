# 交付物显示与预览体验改造执行计划

日期：2026-10-18。分支：`release`（基线 `d149b1f1b4`）。参考实现：UniWork 桌面版 `Kyle549/UniClaw @ uniwork_release`（`ce575e5c`）、服务器版 `zhr12345678/Uni-Work @ feat/postgresql-multitenant`（`a0f5c5c`）。

状态：阶段 1 实现与自动化验证完成，等待用户核验；阶段 2～6 未开始。

路径约定：`src/`、`electron/` 指 `apps/desktop/` 下的对应目录；`plugins/` 指仓库根目录下的 Hermes 插件目录。行数是预估的产品代码行数，不含测试、夹具和文档。

## 1. 要解决什么

一句话：**模型生成的文件一定在对话里出现卡片，并且能在右侧预览；预览本身更快、更顺。**

2026-10-17 实测发现的问题：

| # | 现象 | 已查明的原因 |
| --- | --- | --- |
| 1 | 生成的视频、音频、图片在对话里打不开 | 模型照后端提示 `MEDIA:/absolute/path` 写成 `MEDIA:/C:\...`，盘符前多一个 `/`，主进程解析成 `C:\C:\...` |
| 2 | 交付物有时不出现卡片 | Hermes 没有“交给用户”工具，只靠模型在回复里写 `MEDIA:`，忘了写就没有 |
| 3 | 生成的图片、视频、语音不能在右侧预览 | 对话里只有内嵌播放器和“用系统播放器打开”，没有通往预览面板的入口 |
| 4 | PDF、Word 预览有大黑边 | 用的是 Chromium 自带 PDF 阅读器 |
| 5 | Excel 往下滚后滚不回 | 显示缩放不是 100% 时，FortuneSheet 往上滚算出原位（已在真实 Electron 复现，dpr 1.104） |
| 6 | PPT、Word 往回看要重新加载 | PPT 只保留一屏内页面、最多缓存 6 页；Word 走 Chromium 阅读器 |
| 7 | 打开 Office 预览总要等 | Word、PPT 点开才开始转换 |

## 2. 已确认的决定

| 事项 | 决定 |
| --- | --- |
| 分支 | 直接在 `release` 上改 |
| 阶段节奏 | 六个阶段，每阶段合成一个提交；**本地提交后暂停，用户核验同意后再推送**，然后进入下一阶段 |
| 交付物思路 | 参考服务器版“程序自己观察，不靠模型宣布”；补上桌面版特有的“看路径证据”“看用户指定目录” |
| 交付物放在哪 | **新建我们自己的 Hermes 插件**；同时关掉 `uniwork-kits` 插件里的交付兜底（Hermes 每条回复只采用第一个插件的改写，两个都补会互相顶掉）。改动前告知 xuelin |
| 卡片持久 | 硬要求：关掉对话再打开，补出的卡片必须还在 |
| 生成的媒体 | 图片、视频、语音和文档一样能在右侧预览 |
| PDF 查看器 | 全部 PDF（模型生成的和 Office 转出的）都换成白底分页查看器；不另补打印、下载、旋转按钮，下载走文件卡片 |
| 提前转换 | 文件卡片一出现就在后台排队转换 Word、PPT，同一时间只转一个；用户点开的插队 |
| PPT 前端兜底 | 维持不做（没有办公软件时 PPT 仍看不了） |
| 远程连接 | 交付物观察只管本机模式；远程模式文件不在本机，本轮不做 |
| Hermes 核心 | 不修改 `agent/`、`tools/`、`hermes_cli/` 等核心已有文件 |

## 3. 交付物方案（阶段 1、3、4）

### 3.1 证据分档

| 档位 | 证据 | 处理 |
| --- | --- | --- |
| 确定 | 本轮写文件工具（`write_file`、`patch`）参数里的路径 | 核对后出卡片 |
| 确定 | 本轮回复里的 `MEDIA:` 路径（含 `/C:` 写法） | 修正后出卡片 |
| 确定 | 本轮运行代码、终端命令执行前后，工作目录里多出来或改过的文件 | 核对后出卡片 |
| 确定 | 本轮生成类工具返回的链接，由插件下载到本地 | 出卡片 |
| 较大把握 | 本轮工具输出或回复里出现的路径，且文件在本轮期间改过 | 核对后出卡片 |
| 推测 | 回复结束时扫描工作目录、用户指定目录，本轮期间新出现的文件 | 同一目录本轮有别的会话在运行时不采用 |

核对条件：文件存在、非空、后缀在白名单、修改或创建时间不早于本轮开始减 2 秒。

### 3.2 通用规则

- 白名单后缀：docx、doc、xlsx、xls、pptx、ppt、pdf、md、html、htm、csv、png、jpg、jpeg、gif、webp、svg、mp3、wav、m4a、mp4、mov、webm、zip。
- 排除目录：`node_modules`、`.git`、`__pycache__`、虚拟环境，以及技能素材目录 `themes`、`templates`、`references`、`scripts`、`assets`、`examples`。
- 排除文件：隐藏文件、`~$` 开头的 Office 锁文件、`.tmp`/`.part`/`.crdownload`、`package.json` 与各类 lock 文件、用户本轮上传的附件。
- 排序与数量：文档 > 文本 > 图片 > 音视频；本轮有文档时隐去图片素材；最多 8 张卡。
- 扫描上限：最多 4 层、3,000 个文件、0.5 秒，超出即停；运行代码与终端命令前后的对比沿用同样上限。实测：本账号工作区 25 个文件 7 ms；1.8 万文件的代码仓库 1.9 s，所以必须设上限。
- 出卡片方式：插件在回复存入聊天记录之前，往回复末尾追加 `MEDIA:<路径>` 行（`transform_llm_output`）。Hermes 现行代码在持久化前执行该钩子，追加内容会存入聊天记录；阶段 3 用真实对话关闭重开验证，不成立时改由桌面版按回复记录结果。
- 任何一步出错：不出卡片、不打扰用户，只写日志。

### 3.3 新插件

- 位置：`plugins/desktop-deliverables/`（`plugin.yaml`、`__init__.py` 及子模块），登录时由 Electron 写入账号启用名单，做法同 `entry_local/uniwork-kits-config.ts`。
- 钩子：`pre_llm_call`（记本轮开始时间、用户消息里的目录）、`pre_tool_call`／`post_tool_call`（运行代码与终端命令前后对比，生成类工具下载链接）、`transform_tool_result`（告诉模型已下载到本地的路径）、`transform_llm_output`（追加卡片）。
- 与 `uniwork-kits` 的关系：移植其 `delivery.py` 中已验证的路径识别，并在 `plugins/uniwork-kits/__init__.py` 去掉交付兜底的注册（一行）。专家与 PPT 规则里的交付说明保持不变。

阶段 1 执行记录（2026-10-18）：

- 媒体路径在统一解析入口修正，图片与音视频保留对话内展示，并通过既有文件卡片打开右侧预览。图片复用 `useZoomPan`，支持滚轮、拖动、双击还原及缩放按钮；新增文案同步全部 9 种语言。
- 删除旧媒体包装、Markdown 专用重复分支和分类助手，以及播放器中不再可达的普通文件分支。文件卡片改用可嵌入段落的元素，避免媒体所在段落出现无效嵌套。
- FortuneSheet 向上处理滚轮前，把分数像素位置移回整数边界内侧，消除显示缩放的取整偏差；不替换库的行定位和滚动规则，不修改依赖。
- 新路径、预览入口、图片缩放和滚动断言均在旧实现上观察到失败，再切回新实现通过。真实 Electron 表格夹具覆盖 DPR 约 1.104 和 1.219，向下后连续向上滚动均移动。
- 真实 Electron 媒体夹具从对话 `MEDIA:/C:\…` 打开本机图片、视频和音频，检查实际图片解码、面板缩放／拖动／还原、媒体播放、原生进度拖动与 Range 读取。样例在独立临时目录生成，不启动 Hermes、模型或 Office，不使用用户现用窗口。
- 定向 Vitest、完整 TypeScript、改动文件 ESLint、脚本语法及 Git 差异检查通过。产品与测试文件格式检查通过；9 份语言文件在基线已有整文件格式差异，本次新增的文案行已单独核对格式，没有重排存量内容。

## 5. 每阶段的做法

- 新增函数附简洁中文注释；不修改 Hermes 核心已有文件；只暂存本阶段文件，不带入用户本机脚本。
- 新增和修改的测试先在旧实现上证明失败，再在新实现上通过。
- 跑 `npm run typecheck`、相关 Vitest、改动文件 ESLint 与 Prettier（只要求自己改的行）、`git diff --check`；涉及界面的用真实 Electron 夹具验证。
- 多语言文案同步 9 种语言与 `types.ts`。
- 提交说明按项目规范分段写，结尾附代码变化统计；本地提交后暂停，等用户核验。

## 6. 本轮不做

- 没有办公软件时的 PPT 前端兜底。
- 远程连接模式下的交付物观察与 Office 转换。
- 监视整个硬盘的文件变化。
- 修改 Hermes 后端提示词。
