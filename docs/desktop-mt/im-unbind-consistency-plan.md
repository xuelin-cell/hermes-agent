# IM 渠道解绑一致性实施计划

> 执行方式：按用户要求由当前会话逐项实施，不使用子 agent。实施时遵循 `superpowers:executing-plans`；本次仅制定计划。

**目标：** 四种可手动解绑渠道成功解绑后，统一回到“未连接＋配置”。

**架构：** 复用现有渠道插件清理绑定、主进程核对结果、页面展示状态的链路。先复现状态来源不一致，再局部修复，不新增状态机或修改核心。

**技术：** Python 插件、Electron 主进程、React／TanStack Query；沿用现有测试工具。

**需求依据：** 本文“目标与范围”及“页面统一展示”记录本会话确认的解绑语义。

日期：2026-11-09。状态：已实施并本地提交，待真机验收；结果见文末“实施结果”。代码基线：`9a88c91eb6`。

## 目标与范围

微信、钉钉、飞书、企业微信解绑成功后，统一显示“未连接＋配置”，不再保留“重新扫码／解绑”入口，也不能重启后恢复旧绑定。微信点击配置仍走现有扫码流程，其他渠道沿用现有凭据表单。

只处理解绑链路及其状态一致性；5G 消息网关保持账号管理规则，不新增手动解绑。保留近期页面快速展示、缓存和后台刷新优化。不修改 Hermes Python 后端核心，不操作用户正在使用的窗口，不替用户清理账号数据，不新增依赖。

## 已有证据与待证实项

- 用户截图中微信为“已禁用”，仍有重新扫码和解绑按钮，上方显示连接恢复失败。
- 只读检查发现当前账号 `.env` 中微信账号、Token、基础地址已删除，配置中的微信已禁用；同一运行后端仍返回 `configured=true`、`enabled=false`。这是实际数据来源不一致，不能仅修改标签。
- 启动凭据快照可能继续提供旧值；具体来源须用隔离环境复现后确定，不预先认定其他三种渠道具有相同根因。
- 主进程解绑完成条件同时要求目标未启用、未配置、必要凭据字段未设置，并核对网关动作结果。错误的 `configured=true` 会阻碍完成确认；本次顶部提示究竟来自确认超时还是网关动作失败，须进一步关联操作阶段。
- 日志另有启动恢复期间平台目录遍历的 `RuntimeError: dictionary changed size during iteration`。目前未证明它由本次解绑触发，单独复现、报告，不默认扩大本次修改范围。
- 先前核查时运行产物 `dist/python-plugins` 仍是旧版。实施验收必须重新核对源码、暂存插件和实际加载版本，不能仅依据源码推断用户已运行新实现。

## 方案取舍

采用已讨论的端到端一致性修复：清理目标绑定、准确读取状态、核对主进程完成结果，最后由页面反映事实。仅将“已禁用”改成“未连接”无法消除旧凭据或修复完成确认；每次强制重启桌面也会掩盖问题、破坏正常操作体验，均不采用。

不新建通用凭据框架或第二套渠道状态机。优先复用现有插件、原版配置能力和状态类型，只在证据明确的位置作小改动。

### 1. 隔离复现四种渠道的状态来源

- 在临时账号 Home 中准备各渠道的受控绑定，覆盖普通启动及多 Profile 环境。
- 对照解绑前后磁盘凭据、作用域／启动快照、平台接口的 `configured/enabled/env_vars`，日志仅记录存在性和状态，不输出凭据值。
- 通过现有接口执行解绑，再读取平台状态；用新进程重新读取，确认不会恢复旧绑定。
- 给微信现象增加先失败的回归用例；其他渠道分别验证，避免凭名称推定实现相同。

### 2. 修正解绑清理及状态来源

- 微信沿用 `weixin_qr` 插件解绑；另外三种沿用 `desktop-messaging` 插件保存／解绑接口。
- 明确各渠道由桌面管理的绑定字段，仅清除目标渠道的必要凭据和明确归属的绑定文件；保留其他渠道、用户文件及无关设置。
- 微信仅清理当前绑定账号的凭据及同步文件，不删除整个 `weixin/accounts` 目录；保留现有扫码写入与解绑互斥机制。
- 检查删除被拒绝、部分清理失败和旧启动凭据回读场景；不能在未完成清理时返回解绑成功。
- 状态接口对桌面管理渠道采用与解绑一致的绑定事实；仍沿用原版网关存活和归属检查，不以“禁用”等同于“未绑定”。不全局改变原版环境变量和其他 Profile 的凭据读取规则。

### 3. 对齐主进程完成确认与错误提示

- 保留“目标绑定已清理＋本次网关动作完成”的确认条件，不通过放宽断言消除超时。
- 有其他平台配置时沿用既有重启流程；最后一个平台解绑时沿用停止流程。不要承诺共享网关重启期间其他平台完全不断线。
- 区分“清理失败”和“绑定已清理但网关动作失败”；后者卡片显示实际未连接，顶部如实说明动作失败，不能伪装整体成功。
- 解绑不要求其他渠道全部重新连接成功；其他渠道真实错误留在对应状态中。
- 若需新增提示，补齐简体中文、繁体中文和英文。

### 4. 页面统一展示并保留缓存保护

| 事实 | 页面结果 |
| --- | --- |
| 未绑定或解绑成功 | 未连接，仅配置入口 |

## 实施结果（2026-11-09）

### 根因

状态接口对主助手走的是原版“不限作用域”的判断，凭据取自后端进程环境和启动时冻结的凭据快照。后端一旦开始服务专家助手（本产品启动时就会），核心便冻结这份快照，并且不再从进程环境里删除凭据。解绑只能删掉账号文件里的凭据，于是：

- 状态接口继续报“已配置、未启用”，页面显示“已禁用”并留着重新扫码和解绑。
- 主进程等不到“未配置”，约 2 分钟后按确认超时报失败。
- 钉钉早先已改为按账号文件判断，所以不受影响；微信、飞书、企业微信受影响。

隔离复现方式：临时账号里先写入凭据并放进进程环境，激活多助手托管，再走真实解绑接口。修改前飞书、企业微信、微信三个用例失败，返回值与用户截图一致。

### 改了什么

| 位置 | 改动 |
| --- | --- |
| `plugins/desktop-messaging/dashboard/plugin_api.py` | 状态接口对微信、钉钉、飞书、企业微信统一按账号文件判断是否绑定；5G 消息保持原判断。解绑后复查凭据确实已删，删不掉就报失败。解绑只要删过凭据就写下“明确停用”。 |
| `plugins/weixin_qr/dashboard/plugin_api.py` | 账号 ID 只认账号文件里的。先删账号文件再删凭据，文件删不掉时绑定保持原样、可重试。删后复查，写配置时与扫码保存共用同一把锁。 |
| `apps/desktop/src/app/messaging/` | 微信卡片与其它渠道统一：有残留就保留解绑入口，未启用时不显示旧错误。解绑失败的顶部提示分成“解绑未完成”和“已解绑但网关动作失败”两种，三种语言已补齐。 |

主进程 `messaging.ts` 没有改：完成条件本身正确，现有用例已覆盖成功、清理失败、网关动作失败、最后一个渠道停止和确认超时。没有修改 Hermes 核心。

### 已知边界

- 解绑后，旧凭据仍留在后端进程内存里，直到应用重启；新拉起的网关进程环境里也会带着它。这是核心的行为，插件改不了。它不会让渠道重新连上：网关遇到“明确停用”会忽略环境里的凭据，这一点有用例验证。后端内其它读取凭据的功能（例如主动发消息的工具）是否仍会用到旧凭据，未验证。
- 启动恢复期间的 `RuntimeError: dictionary changed size during iteration` 未处理。出错位置在核心的平台目录遍历（`hermes_cli/web_server_messaging.py` 遍历 `Platform.__members__` 时，另一线程正好登记插件平台），首次登记后不再出现。它会让恢复请求失败并显示“自动连接失败”，与截图上方的提示相符，但未单独复现，需另行处理。
