# BuiltinCrawl 桌面网址读取入口

桌面会把粘贴的网址编码为 `@url:` 引用。Hermes 原生引用展开调用原生抓取包装，只向模型提供正文，遗漏插件的 `fetch_status`、`reasons`、`browser_followup`；部分页面随后经正式工具重复抓取，404 还可能触发原生备用救援。

## 当前实现

在桌面统一会话发送边界 `requestForSessionProfile`，仅对带完整 connectionId/profile 的 `prompt.submit` 网址引用，读取所属会话的实际网页后端。选择 BuiltinCrawl 时移除外层 `@url:` 标记、保留原网址及引号，让模型按任务需要调用已注册的正式抓取工具。这里不再隐式预读，也不向模型另造一份质量摘要；正式工具继续提供完整质量信息并沿用已有 HTTP → 必要时渲染 → 必要时交互的策略。

- `prompt.ts` 管理引用处理、所属连接配置查询和待发送请求；原路由只增加入口调用，实际 RPC 路由与连接保持逻辑不变。
- 其他抓取后端保留原网址引用、原生预读及缓存；普通网址文本、文件引用、MCP 和非 prompt 请求不增加配置查询。
- 查询使用调用时捕获的完整 owner，不依赖当前窗口；不缓存后端选择，避免 A→B→A 或切换后端后沿用旧策略。
- 配置查询最多等待 5 秒；失败不发送。停止/关闭同一所属会话或 AbortSignal 会取消待发送请求；迟到响应不会补发。
- 去除外层标记前检查嵌套上下文引用，避免网址中包含的 `@file:` 等文字被原生解析器误当成新的文件读取指令。
- 不修改 Hermes Python 核心、历史消息、插件缓存版本、其他后端实现或账号配置。

## 行为验证

跨语言对照运行真实桌面函数 → 原生引用展开 → 正式注册工具，只替换网页 worker 的传输结果并使用隔离 Home：

| 场景 | 修复前 worker 调用 | 修复后 worker 调用 | 质量与备用行为 |
| --- | --- | --- | --- |
| partial 页面 | 2 | 1 | 正式返回 partial、原因和续读提示 |
| usable 页面 | 1（预读缓存复用） | 1 | 正式返回 usable |
| HTTP 404 | 2 | 1 | unavailable/http_error；原生备用救援 1→0 |
| Tavily 对照 | 1 | 1 | 保留原生预读与缓存 |

前端 5 文件 214 项通过，覆盖队列、分发、取消、配置失败、后端切换、嵌套引用和所属连接隔离。Python 6 文件 196 项通过，包含本入口跨语言对照、两个隔离 Home 的切换、真实 worker/Chromium、历史桥接、工具注册和 MCP 回归。上述次数是受控链路结果，不是公网耗时保证。

## 验证边界

仅覆盖桌面具有明确 owner 的发送路径；CLI、消息平台或直接调用 Hermes 原生 `@url:` 预读的入口保持不变。既有历史中的预读内容不改写。去掉隐式预读后，模型仍须根据任务选择工具；自然用户场景的实际选路与重复调用仍需 Electron 人工验收。本次并未宣称模型永不重复抓取，或把 partial 缓存为完整结果。

全量 renderer 类型检查在修改前后均报告两处相同的既有错误：聊天侧栏缺少 `emptyState`，邮件页面调用参数不足；本次不扩展修改范围。定向测试和构建结果另见工作区 R294 证据。
