# 兜底搜索梯子

## 什么时候进入兜底

- `mcp_vods.py` 自愈重试过一轮仍失败（非零退出）
- 或连续两次返回空
- 或候选全被 [output-rules](output-rules.md) 排除

**别因为第一次超时就跳过来**：超时不等于没资源，重试一次值得。

## 梯子顺序

任一层拿到可验证片源就停。

**第 1 层 · 夸克搜索**：`https://quark.sm.cn/s?q={片名}+资源` 或 `{片名}+网盘`，用 WebFetch 抓。主要目的是捞网盘资源——不用探测 m3u8，对用户最省事。没有 WebFetch 就直接进第 2 层。

**第 2 层 · 通用网页搜索**：用 WebSearch，这里可以加修饰词（mcp-vods 那边不行）：`{片名} 全集 在线观看`、`{片名} m3u8`、`{片名} 网盘 资源`、`{片名} {年份} 高清`。

**第 3 层 · 定向站内检索**：从前两层挑出像点播站的域名（判据见 output-rules 分层），做站内搜索。收益递减，投两三个候选就够。

## 拿到页面之后

网页搜索返回的是播放页，不是媒体地址。要从 `player_aaaa`、`vod_play_url`、`"url":"..."` 等字段挖出真实 `.m3u8`/`.mp4`，再用 `probe_media.py` 验证。方法见 [media-verify](media-verify.md)。页面 URL 本身不能当媒体 URL 输出。

## 对用户的话术

- 说：**"正在用网络搜索为你查找片源"**
- 不说：`mcp-vods 连接失败`、`uvx 超时`、`MCP error -32001`、`正在重试第 2 次`

用户要的是结果，看到内部报错只会觉得这东西坏了。

## 找不到就直说

三层走完仍无可验证片源，直接说没找到，并给下一步建议（换片名写法、确认年份版本、或去正版平台）。不要为了凑结果输出没验证的链接或拼出来的地址——点开是死链比诚实说没有更伤信任。
