# 排版品味

SKILL.md 的硬规则保证“不丑”，这份文档负责“好看”。规则可以被检查器判定，品味不能——
它是一堆判断方法。**做正式交付、封面、对外汇报、或用户说“要精致好看”时，读这一份。**

总纲三条：**克制**（少即是贵）、**一致**（同类同形）、**呼吸**（留白是结构）。
下面每一节都是这三条的展开。

---

## 一、怎么判断做得好不好：眯眼测试

把渲染出的 PNG 缩到 25%，眯起眼睛看。这时看不清字，只看得见灰度块——

- **应该看到**：3 个层次的深浅（标题最重、正文中等、图注最轻），以及稳定的页面骨架。
- **一旦跳出来的是**表格的黑网格、大面积色块、或某张图，说明视觉层级排错了：
  装饰的重量压过了内容。

三个距离各看一次：

| 距离 | 看什么 |
|---|---|
| 缩略图（25%） | 结构、每页视觉重心是否一致、有没有异常的黑块 |
| 100% | 行长、行距、段间节奏、对齐、孤行寡行 |
| 黑白打印 | 只靠颜色区分的信息，去掉颜色后还分得清吗 |

## 二、留白是结构，不是剩下的地方

人靠距离判断从属关系（邻近原则）。间距用错，层级就是错的——哪怕字号全对。

- **标题的段前 ≈ 段后 × 2**。标题要贴近它管辖的内容，而不是漂在两段中间。
  H1: 18pt / 8pt，H2: 14pt / 6pt。这一条错了，全文读起来就“散”。
- **段间距至少是行距的 0.4 倍**才读得出分段。正文 12pt / 1.5 倍行距 → 段后 8pt 起。
- **图与图注 4pt，图注与下一段 12pt**。图注贴图，不贴正文。
- **表格上下各留 10-12pt**，不要让表格直接顶着正文。
- **封面留白 ≥ 页面的 1/3**，且标题落在**上三分线**而不是垂直居中——
  视觉中心比几何中心高约 5%，正中间看起来是偏低的。

留白靠 `space_before / space_after` 造，**不靠空行**。空行是不可控的：字号一变全乱。

---

## 三、层级只用两把刀

制造层级有四把刀：**字号、字重、颜色、留白**。同时用两把，层级清楚；四把全上，廉价。

```
H1 = 大 + 粗            （不改颜色也完全成立，公文就该这样）
H2 = 粗 + 强调色        （不必再加大字号）
H3 = 粗                 （和正文同号，靠字重和段前距区分）
```

- 相邻层级字号比 **1.15–1.25** 最稳（12 → 14 → 16 → 20）。差得太少看不出，太多显得吵。
- 层级超过三级说明结构该重组了，不是该加第四种字号。
- **同一层级永远同一形态**。文档里出现两种 H2 长相，读者就会当成两种东西。

---

## 四、色彩：一个强调色的纪律

- **60-30-10**：白底 60，中性文字 30，强调色 ≤10。强调色只允许落在三处：
  **标题文字、表头底色、分隔细线**。多出一处就要问“能不能删”。
- **灰度也是颜色**。正文 `1F2937`、次要 `595959`、线 `D9D9D9`——
  三级灰足以表达所有次要层级，绝大多数“想再加个颜色”的场合，答案是加一级灰。
- **浅底 tint**（如 `EAF1F8`）用于信息框、表头的克制版本，永远配深色字，不配白字。
- 禁：每级标题一个颜色；彩虹表格；饱和度过高的纯色大面积铺；渐变填充；
  AI 味的紫（`#7C3AED` 一类）；纯红纯绿并置。
- 强调色**深一点总比浅一点安全**：深色配白字对比度够，浅色配白字在打印时直接消失。

---

## 五、表格：删线，不是加线

数据墨水比原则——**能删的线都删掉，剩下的每条线都得有理由**。

- **竖线几乎都能删**。留：表头下一条线、表格外框（可选）、合计行上一条线。
- 内框线 0.5pt `D9D9D9`；**黑色粗网格是最典型的“Excel 味”**。
- **数字列右对齐 + 千分位**，单位提到表头（“收入（万元）”），不要每格重复“万元”。
- 表内字号比正文小一档，行距 1.15，单元格上下内边距 ≥3pt——**文字贴边是最容易被忽略的廉价点**。
- \>7 行加斑马纹 `F7F8FA`；跨页表设表头重复。
- **合计行**：上一条细线 + 加粗，不要整行反白，也不要再上一层底色。
- 表格宽度对齐版心，不要比正文窄一点点——那点差值看起来像没对齐。

---

## 六、图：一图一结论

- **图注写结论，不写编号**。“图 3 收入构成”是废话；“核心业务贡献 54% 收入，新兴业务增速最快”
  才有价值。编号和来源跟在结论后面。
- **全文所有图统一宽度**（版心宽，或版心的 2/3 居中）。宽度不一是页面凌乱的主要来源。
- 图的配色跟文档主题色一致：强调色 + 2-3 级灰。**要突出的那一根用强调色，其余全灰**——
  这比给每根柱子一个颜色更专业。
- 系列超过 5 个就换图形（分组条形、小倍数），不要靠颜色硬撑。
- 图片不拉伸变形（只锁宽，让高自适应）；截图先裁掉无关的浏览器边框。

## 七、中文排版的细节

- **中英混排**不要手动加空格，靠 `w:hint="eastAsia"` 和字体搭配处理；
  数字和西文用西文字体（Times New Roman / Arial——Segoe UI 是 Windows 独有的，
  macOS 上会静默回退），中文用中文字体。
- **首行缩进 2 字符**与**段间距**二选一：公文用缩进，现代商务文档用段间距。两个都做会松垮。
- **不要用斜体强调中文**——中文没有真正的斜体，Word 是把字硬倾斜，很难看。用加粗或强调色。
- **不要用下划线做强调**，会被当成超链接。
- 标题设 `keep_with_next`，正文开 `widow_control`——标题落在页底、段落只剩一行翻页，
  是“看起来不专业”里最常见的一条。
- 行长 35-45 个中文字最舒适；表格内的窄栏可以短到 15-20 字。

### 标点与特殊字符

中文标点是**全角**的，它自带半个字宽的留白——这就是为什么全角标点后面不用再敲空格，
也是为什么混进一个半角逗号会让整行的节奏塌一下。字号、颜色、留白都调对了，
一行里蹦出个 `"` 或 `,`，观感照样掉一档。

| 用途 | 用 | 不要用 | 为什么 |
|---|---|---|---|
| 引号 | “ ”，内层嵌 ‘ ’ | `"` `'` | 直引号不分左右，中文字体里常显示成两根竖棍；它也是生成脚本 SyntaxError 的同一个源头 |
| 逗号 / 分号 / 冒号 | ，；： | `,` `;` `:` | 半角标点少了半个字宽，行内节奏发挤 |
| 并列词之间 | 、 | `,` `/` | 顿号是中文特有的：“苹果、梨、桃”不写成“苹果,梨,桃” |
| 破折号 | ——（两个 U+2014，占两格） | `-`、`--`、单个 `—` | 单个 — 在中文里是连接号不是破折号，长度也不对 |
| 省略号 | ……（两个 U+2026，占两格） | `...`、`。。。` | 六个点是一个标点，不是六个句号 |
| 数值 / 日期区间 | `-` 或 ～ | `–`(U+2013)、`‑`(U+2011) | 国标写作一字线，但它和这两个字符一样，不少中文字体缺字会渲染成方块或宽度错乱；`check_docx.py` 报 `UNICODE_HYPHEN` |
| 括号 | 中文内容用（），纯西文内容用 () | （English) 这类混用 | 一句里两种括号形态，是最容易被一眼看出的不整齐 |
| 书名 / 文件名 | 《XX 管理办法》 | “XX 管理办法” | 公文里书名号是硬要求，不是风格选择 |
| 公文日期的零 | 二〇二六年（〇 = U+3007） | 二○二六（○ = 圆圈 U+25CB）、二0二六 | 三个字符长得几乎一样，但只有 U+3007 是汉字数字零——字体、检索、朗读都认它 |

几条最常犯的：

- **标题末尾不加句号**。问号、叹号可以留，句号一律删。
- **中英之间不要手动敲空格**：Word 的 `autoSpaceDE/DN` 会自动补一小段间隙，
  手动再加就是双倍空隙（helper 生成的样式没关这两项）。
- **避头尾保持默认开启**：`，。！？》）` 不该落在行首，`《（“` 不该落在行尾。Word 默认开，别关。
- **数字与百分号、单位之间不加空格**（`54%`、`12.5cm`）。统计数值用阿拉伯数字，
  只有公文的成文日期与序数词用汉字数字。
- **表格里“无数据”与“数值为零”要分开**：无数据统一写 `—`，零就写 `0`，全表一致，
  比逐格加注省事。
- **序号层级按 `一、` → `（一）` → `1.` → `（1）`**，同一层级里别混用 `1、` 和 `1.`。

**转换类任务不适用这一节**：源文件里是直引号、半角逗号，成品里就照旧——保真优先于排版，
不要顺手“修”原文。`check_docx.py` 的 `STRAIGHT_QUOTE` / `HALF_PUNCT` 定成 WARN 而不是 ERROR，
就是给这种情况留的确认位；只有 `MOJIBAKE`（乱码、替换字符）是 ERROR，那不是风格问题，是坏字符。

## 八、廉价感清单（命中一条就改）

1. 满页强调色块、彩色页眉横幅
2. 每级标题一个颜色，或彩虹色表格
3. 艺术字、阴影、外发光、渐变、圆角花边
4. 三种以上字族；或用**宋体加粗**当标题（宋体没有真粗体，是合成的，糊）
5. 所有东西都居中（正文居中是最伤可读性的一种“美化”）
6. 空行排版
7. Table Grid 黑网格 / 表头不着色
8. 图片被拉伸变形、多图宽度不一
9. 正文纯黑 + 12pt + 单倍行距（一眼默认模板）
10. 正式文档里的 emoji 项目符号
11. 页脚写“本文档由 AI 生成”之类的自我声明（用户没要求就别加）
12. 中文里混着 ASCII 直引号 `"` 与半角逗号，或标题末尾拖着一个句号

## 九、气质映射：拿到需求先选这一行

| 场景 | preset | theme | 关键动作 |
|---|---|---|---|
| 公文 / 红头文件 | `gongwen` | `navy` | 严格 GB/T 9704，零装饰，无斑马纹无图 |
| 政企汇报 / 年度报告 | `business` | `navy` | 封面 + 目录 + 页眉页码，图表齐全 |
| 金融 / 审计 / ESG | `academic` | `green` | 表格为主、图少而准，来源标注到每张表 |
| 科技 / 产品文档 | `modern` | `teal` | 无首行缩进、留白大、小标题多、代码块等宽字体 |
| 文化 / 教育 / 消费 | `business` | `ochre` | 正文宋体，图片大而少，引文用浅底块 |
| 庆典 / 品牌发布 | `business` | `claret` | 封面重（大留白 + 细线），内页反而更克制 |
| 合同 / 协议 | `academic` | `navy` | 零强调色、条款编号严格、无斑马纹无配图 |

**合同类要特别克制**：任何装饰都会削弱严肃性，唯一允许的“设计”是清晰的编号层级和充足行距。

## 十、交付前的最后一问

看着渲染出的第一页，问：“**如果这是一家咨询公司交来的，我会觉得贵还是便宜？**”

答案是“便宜”时，八成不是缺东西，而是**多了东西**——先删颜色、删线、删装饰，
再考虑加留白。**减法几乎总是对的。**
