# 用户素材处理指南 (Upload Process Mode)

**注意：** 这是一个从零创建 PPT 的优先分支。
如果用户上传了任何参考素材（PDF、Word、Excel、图片、文本），**必须优先使用这些素材**，然后执行本指南的处理流程。基于这些素材，后续应当生成包含具体数据的调研报告 `research.md`。

> ## ⚡ 总原则：解析在本地做，MCP 只用来看图
>
> **文字、表格、图片抽取一律用本技能自带的本地脚本完成，不要调云端 MCP 去"解析 PDF"。**
> MCP 只保留一个用途——**识图**（给图片一句话描述、读扫描件里的字）。
>
> 为什么：解析这件事本地几秒就能做完且结果可复现；把整份 PDF 丢给云端 MCP 既慢、
> 又占用紧张的 MCP 配额，而且一份 30 页的 PDF 里页眉 logo 会被抽出 30 份重复图，
> 全送识图纯属浪费。脚本已经替你把该去的重复和装饰件去掉了。

---

## 1. 本地解析（默认，不调 MCP）

```bash
python <技能根>/scripts/process_upload.py --input <用户素材目录> --output <处理后的目标目录>
```

支持 `.pdf` / `.docx` / `.xlsx` / `.txt` / `.md` / `.csv` / 图片，输入目录会递归扫描。

**依赖（都是"没有也能跑"）**：解析 PDF 需要 PyMuPDF。**Lite 的安装器只装一个干净的 Python，
不带任何第三方包**，所以第一次跑到 PDF 时脚本会自己 `pip install pymupdf`
（默认源失败会换清华镜像重试一次）。装不上也不会中断——PDF 跳过、其余素材照常处理，
并在结尾明确告诉你缺什么、怎么补。docx / xlsx 分别需要 python-docx / openpyxl，同样是缺了只跳过那类文件。

- 离线环境加 `--no-install`，脚本就不会尝试联网安装。
- 看到"部分完成：N 个 PDF 因缺 PyMuPDF 未解析"就 `pip install pymupdf` 后重跑一次，别绕去调 MCP。

产物（全部落在 `--output` 下）：

| 产物 | 内容 |
| --- | --- |
| `<名>.md` | 提取出的正文，**含表格**（已转成 markdown）、图片以 `![](路径)` 占位 |
| `image/<名>/*.png` | 去重、过滤后的图片 |
| `image_<名>.json` | 图片描述清单，等你回填 `description` |
| **`manifest.json`** | **总清单 + `needs_vision`——唯一需要调识图的列表** |

脚本自动做掉的三件事（所以你不用再操心）：

- **去重**：同一张图（页眉 logo、水印、母版装饰）不管出现在多少页，只留一份。
  实测一份 18 页的 PDF 抽出 270 张图，去重后剩 15 张。
- **过滤装饰件**：分隔线、小图标、间隔条按**版面摆放尺寸**判断后剔除，不进识图队列。
- **认出扫描件**：某页提取不到文字（纯图排版/扫描件）时，把**整页**渲染成 PNG 并标进
  `needs_vision`，标记 `priority: high`——这才是该动用识图的场合。

**先 `cat <输出目录>/manifest.json` 看一眼**，里面 `files[]` 会告诉你每个文件抽到多少字、
几张表、留了几张图、哪几页是扫描件。

> 如果这一步真的跑不起来（环境缺 PyMuPDF 且装不上），再考虑其它办法；
> 但**不要**因为"MCP 更省事"就跳过本地解析。

## 2. 识图（只处理 `needs_vision` 里的那几张）

`manifest.json` 的 `needs_vision` 就是**完整且唯一**的识图清单，别再自己去目录里扫图片。

```jsonc
"needs_vision": [
  { "path": "image/年报/page-007-scan.png", "priority": "high",
    "reason": "该页提取不到文字（扫描件/纯图排版），需要识图读出内容" },
  { "path": "image/年报/p3_i1.png", "priority": "normal",
    "reason": "内容图（图表/照片/示意图），需要一句话描述才能用进 PPT" }
]
```

- **先做 `priority: high`**（扫描页、用户直接上传的图），这些不看就没法用。
- `normal` 的可以按需，图多的时候挑要放进 PPT 的那几张看就行。
- **能一次批量调就别一张一张调**，MCP 配额很紧张。
- 结论**一句话**记进 `image_*.json` 的 `description`，别把识图工具的长输出留在上下文里。

**🚨 严禁用 Read 工具读图片**：agent 自身没有视觉能力，产线环境读图会造成不可逆的系统错误。
必须走视觉 MCP。若环境**没有**视觉 MCP：跳过识图，在 `research.md` 里注明"图片未识别"，
正文照常用本地抽出来的文字——**不要**因此卡住整个流程。

## 3. 回填 `image.json`

把描述写回对应的 json，格式：

```json
[
  {
    "local_rel_path": "image/example.png",
    "description": "柱状图，2023 年各季度销售额，Q4 最高 9.5 亿"
  }
]
```

## 4. 生成报告

素材处理完毕（文字已提取、该识的图已识）后，综合内容生成一份带具体数据的调研报告
`research.md`，为后续大纲做准备。**表格里的数字直接引用本地抽出来的那份**，不要凭印象重写。
