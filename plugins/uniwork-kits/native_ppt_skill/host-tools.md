# 常规创作与材料任务分流

普通主题和报告提炼沿用WorkBuddy workbuddy-pptx v20261013的原生DSL逐页路线：先做内容结构与视觉设计，每页write-page写入并检查，模型读取结果、修好当前页再制作下一页。精确重建或要求带编辑数据的图表，使用Hermes材料适配路线material-info→自由页面JSON或已有公共函数脚本→build-material。各页构图、字体、配色与留白保持自由，不限制模板。

只有build-material材料路线按review_batch核对待确认页：数据稿可用review_contact_sheet逐页给结论；有原图的保真重建逐页看SOURCE/SAVED对照，不能用总览代替精细核对。检查有问题只修对应页，无问题就review-material并finalize。普通DSL路线执行下方逐页调用桥，不叠加材料路线的预览核对流程。布局检查不能证明原文、数值或图片主体正确，内容准备时仍须核对来源。

材料稿最后一批review-material全部通过后，宿主自动执行最终交付，返回auto_finalized和真实delivery回执；此时简要回复结果，不重复发布附件。仍有缺陷或未确认页时不自动交付。若preview-material用于恢复任务，先review-preview取得本版本核对图，读取review_batch中的review_image；不要拿普通page预览替代SOURCE/SAVED核对图。

真实照片fetch-assets后先一次看contact_sheet，编号对应images里的contact_label。信息不足的个别图再放大；不要给每张已确认照片都再做裁剪、去水印和重复识图。保留原图及来源，默认contain防止裁掉主体。失败主体最多补一轮来源，用户允许示意图时明确标注示意；不能冒用错误照片。

# Hermes素材工具适配

普通创作适配素材来源、宿主工具与文件路径，叙事设计、视觉规范、DSL组件、逐页写入和原生lint保持原流程。材料重建和带编辑数据的图表属于单独的Hermes适配路线，不混称为WorkBuddy原生DSL流程。

| 素材需求 | 当前宿主调用方式 |
| --- | --- |
| 用户上传图片、文档抽取图片 | 用常规文件工具读取/抽取，复制需要的素材到当前项目 assets；保留原件 |
| 景区、品牌、具体产品、真实人物等事实展示 | 用已加载的 image_search 搜图，核对来源并下载原图到 assets；不生成仿真图充当实景证据 |
| 创意插画、气氛背景、虚构场景 | 用 tool_search 查找当前实际可用的 image generation 生图工具，并按其真实参数调用 |
| 图片内容核对 | 模型支持图片时用desktop_read_image直接加载原图；纯文本模型使用已加载的analyze_image。核对主体、比例、清晰度及水印；不要求从外观猜出具体景点 |
| 最新数据、事实来源 | 使用Hermes现有 WebSearch/WebFetch 或已加载搜索工具 |
| 插入图片与排版 | 素材保存为本地文件后，按原生 Image DSL 引用，由 slidep/SDK 处理 |

- 文档中的 ImageGen 是能力名称，不是当前宿主的工具或 CLI 命令。工具 MCP 前缀可能变化，使用 tool_search 返回的实际工具名，不把素材任务发给 editor_sdk 的 /mcp。
- 生图描述继续遵守原生规范：主体、场景、构图、风格、色彩和禁忌。原有“优先生图”规则适用于创意视觉，真实照片需求按上表执行。
- 搜图返回 URL 不等于已经取得文件。取得候选原图后，用`TencentPpt(action="fetch-assets",arguments={"images":[{"url":"原图URL","source_page":"来源页","title":"主体名称"},...]})`一次保存1至8张。宿主最多4路并行、单次读取超时6秒，逐图返回成功路径、像素及失败原因；相同已成功URL复用。不要临时写串行curl、重装下载库或反复探测网络。成功项直接引用path，用图前仍核对主体与清晰度；失败项换来源。保留来源链接，不用搜索结果页截图替代原图。
- 在已有 DESIGN.md 配图清单记录本地文件、来源/提示词、尺寸、核对结论和使用页。未变化的同一素材跨页复用核对记录；不因再次引用就再识图。存在疑点时只查相关新图或区域。
- 宿主生图结果会自动保存并返回images[].localPath及实际尺寸；看到本地路径即直接引用，不再调用terminal下载或重复生图。部分保存失败时只处理缺失项，保留已保存文件。比例参数由宿主转换为当前工具支持的像素档位。
- 当前模型支持图片时，用desktop_read_image(path=图片绝对路径)加载本地原图完成首次核对；消息已有原图时直接分析，无须再次读取。不要为同一已明确问题再调用外部analyze_image。仅有具体疑点时追加分析，并在prompt明确待确认的问题。本会话完全相同图片和相同分析问题可复用结果；换图或换问题仍重新分析。
- 材料转换任务按用户要求保留原内容；未经要求不额外搜图、生图或扩写。
- 右侧进度由实际工具事件生成，无须为更新进度增加 todo、识图或复检调用。

## 逐页调用桥

- 原生每页的upsert-dsl→lint通过TencentPpt(action="write-page", file_path=working_file, dsl_file=页面源文件)一次执行，顺序和诊断保持原生行为。两步之间不请求模型；检查失败直接返回诊断，不自动修页或重复检查。
- 默认逐页生成并使用write-page。仅在用户明确要求批量或对照测试时，阅读[批量实验](batch-experiment.md)，使用write-pages串行提交独立页面；它不是并发写入，也不是默认创作路线。
- 首次追加不传page_index，工具返回实际下标。修复时仅修改对应.slide，再以同一page_index调用write-page替换并检查；通过后进入下一页，不再额外调用lint。
- 普通PPT写完计划页数，全部页面lint通过后直接finalize。逐页lint是自动排版检查，交付前无需额外截图或全稿复检。
- create返回working_file、assets_dir、slides_dir，后续持续使用这些路径，不通过terminal删除或移动正在打开的工作稿。

## 按要求选择工具（宿主适配）

以下材料脚本路径仅在当前TencentPpt的action列表包含build-material时使用。已运行的旧会话沿用其已加载能力，不为换工具推翻现有稿件。

| 要求 | 首选路径 |
| --- | --- |
| 普通主题图文、品牌/景区介绍、文字报告提炼 | 原生DSL与write-page逐页写入检查，保留自主设计、CSS/SVG和素材流程 |
| 数据复盘、统计汇报，明确要求图表带可编辑数据 | prepare-material提取原始数据→material-info页面JSON→build-material；其原生图表带嵌入Excel。不要用无工作簿的DSL图表缓存或用形状画柱子来代替 |
| 上传材料需要重建流程、表格、组织结构等，要求对象可编辑且精确排版 | prepare-material一次取原文/原图 → material-info取得页面JSON格式 → write_file页面数据 → build-material(page_file=...) |
| 已有PPT少量对象修改 | SDK增量编辑；不要因一个对象改动重新生成整稿 |
| 已有稿件必须整页调整且SDK能力不便表达 | 已验证的材料脚本配合edit_pages，拒绝修改范围外页面 |
| 用户明确接受整图、不可编辑 | 保留原图；不能默认以整图代替可编辑文字和图形 |

- 先判断是否编辑已有稿，再判断是否精确还原，再判断是否要求图表数据可编辑，其余走普通DSL创作。仅有附件不代表重建；Word/PDF报告提炼仍走DSL。意图明确直接执行，只有提炼与还原无法区分时才询问。混合任务以必要的保真/数据编辑要求选择路线，已完成页不为切换路线重做。旧会话沿用已加载流程。
- `prepare-material(source_files=[本次附件实际路径,...])`提取Word/PPT/文字数据的原文及Word内原图，保留文档引用顺序，返回manifest_file、blocks、images及尺寸/主要颜色。相同材料重复准备复用已有结果，不做OCR。PDF等未支持格式继续用已有文档工具，不安装新环境。普通报告提炼不因上传附件就切成重建路径。
- 仅有局部文字或箭头疑点时，可以对原始图片调用`prepare-material(source_files=[图片],arguments={"crops":[{"source":0,"box":[left,top,right,bottom]}]})`取得二倍局部放大图；坐标是源图像素。无需临时写裁图、测色或路径探测脚本。
- material-info返回自由排版JSON示例（原生文字、形状、富文本、表格、图表、折线），接口查询不启动依赖环境，实际构建才验证导入。优先直接写数据，版式由本任务自行设计。只有现有对象确实无法表达时才读取script_guide，用build(prs)完整API。不为同一稿同时写两套等价生成器。
- 材料中的行列表格使用原生table，保留直接编辑单元格和增删行列的能力，不用许多文本框和直线拼成表格。表格JSON的`borders:{"bottom":{"color":"CFDFEF","width":1}}`可保留只有浅色横线的样式，未指定边为无边框；单元格可单独覆盖borders、fill和富文本runs。不要为追求横线样式放弃原生表格。
- 数据稿先一次计算并保存附件原值、单位、合计、比率和计算口径，再写页面。区分已知事实、推断和建议：订单数不能当独立客户数，客单均值稳定不能推断每笔订单未涨价；情景目标明确写“建议/假设”，不写成附件事实。不同单位或不同数量级的系列分图呈现，除非用户明确要求且轴标注清楚；不要无意堆叠或让客单价随订单数一起上升。
- 先取得material-info，再做生成脚本；文字、节点与连接关系已明确时开始制作。不为已确定的字形、颜色或像素反复写探测脚本。tool_call包装本地TencentPpt时一次只放一个调用，不与识图或其它本地工具合批；被拒绝的调用视为尚未执行。
- 新材料脚本无需create空稿；build-material已保存、结构检查并用随应用SDK返回待核对页的预览。不使用LibreOffice作为前置条件。
- 截图重建的页面JSON填写source_image原图路径；Python返回的metadata填写reference_images原图绝对路径数组，与页面一一对应。宿主集中提供待核对页，每批最多4页；用现有视觉工具看review_previews或review-preview返回previews（纯文本模型使用已加载的analyze_image）。比较图顶部SOURCE是原材料，底部SAVED PPT是成品；直接核对原文、数字、直角/圆角、局部强调和箭头，不能只检查成品与先前识图记录是否一致。通过单次读图取得该页完整核对结果。用review-material一次提交本批通过页、具体问题或无法确认的原因。结构通过不等于文字正确。
- 材料稿全部确认后才finalize。确认有问题只修相关页面，重新构建会复用未改页的检查；预览出错仅用preview-material，不重跑生成。相同JSON/素材重试自动复用已保存工作稿。不要在没有实际缺陷时反复调整微小字号或色值。
- review-material不会仅凭“已核对”放行：必须实际读取当前review_previews的核对图。支持图片的主模型用desktop_read_image直接加载原图，不调用外部识图；纯文本模型用既有analyze_image或vision_analyze。只有实际图片部件才计入直接读图，文字路径或未加载成功不算。读原图、读旧预览或上传失败均不计入。一次完整比较该页SOURCE与SAVED PPT的原文、遗漏标注、直角/圆角、局部强调、表格和连线；不逐行重读。纯文本模型调用识图时，tool_call的calls直接传数组，例如`{"calls":[{"name":"实际识图工具名","arguments":{"image_url_or_oss_path":"核对图绝对路径","prompt":"完整比较SOURCE与SAVED PPT的文字、遗漏标注、框形、强调、表格与连线；只列实际差异"}}]}`，不要把数组再序列化为字符串。
- 内部探测稿如确有必要，create/build-material必须传purpose="internal"，不进入用户产物列表；不能通过文件名猜用途。禁止把脚本、裁剪图或测试稿当作成品交付。

## 简单SDK批量页（兼容已有任务）

- 本节只用于继续已有write-editable-page任务，不作为新任务默认入口。普通图文与报告提炼用DSL→write-page；新材料重建或带编辑数据图表用上方material-info→build-material。
- 已用`write-editable-page`完成的简单页可以继续按原JSON改稿。它只提供SDK批量基本字段，不能据此假定支持文本对齐等完整排版；复杂材料新建按上方material-info路径，不反复查询不存在的字段。内联SVG不能替代原生可编辑节点与箭头。
- 首次调用`TencentPpt(action="schema", tool_name="write-editable-page")`取得示例。用write_file写`slides/01.page.json`，只包含`shapes`、`texts`、`lines`数组。字段沿用原生批量工具定义，坐标单位为**pt**，不要混用px。形状、文字、线条分别批量提交，宿主依次保存并检查，中间不请求模型。
- `TencentPpt(action="write-editable-page", file_path=working_file, page_file=页面JSON)`一次完成该页；成功后再下一页。同一源文件重复提交复用原页，改内容仍使用同一源文件和返回的page_index，不另建整稿。只替换本工具创建的页，不覆盖上传原件或其它来源的页。
- 能力边界：文字、框、直线箭头为原生可编辑对象。折线用连续原生线段，只有末段带箭头；不是一个整体折线路径，不自动绑定节点。不得声称移动节点时线会自动跟随。当前不支持的原生样式按需查单个schema，不靠SVG假装完全可编辑。
- 识别材料时先确定文字、节点、分支和连接关系，沿用已有核对结果。看不清时只补查具体疑点区域；不为无关色值反复裁图，不强制限制必要识图次数。保留原文，不新增事实或未经要求的解释文字。
- 当前宿主通过本地代理注册元景工具，tool_call一次只接受一个调用，包括analyze_image；不要把多个请求塞进同一个calls数组。每个识图请求同时取得该页原文、框形、强调和连线，已读清部分直接复用。疑点集中为有上下文的区域核对，不逐行请求、不反复换提示词重读完整页。
- 样式复原保留直角/圆角、主色和强调范围，不反复采样抗锯齿边缘的RGB或研究数像素的色差。若关键原文仍看不清，标记具体未确认项，不用常识替换专业词。
- SDK提交返回的是**结构检查**，包括保存后的文字、箭头数量、对象类型及明确越界，不是DSL lint，也不是视觉或语义正确性的保证。失败只处理当前页诊断；不要为满足DSL lint改走SVG或反复复检全稿。

## 避免准备阶段停滞

- 一次确定页数、内容和素材需求；有材料先提取，无材料按主题设计。每个阶段产生可复用文件，再进入下一阶段。
- 已有原文、可用图片或通过的页面不重复读取/下载/识图。补查必须指出哪个字、数值、关系或实际排版有疑问。
- 每次失败只处理该失败：下载失败换可用来源，脚本失败修对象字段，预览失败恢复预览。不要因为一个步骤失败重启整个流程、重新安装依赖或重复同一环境探测。
- 真实照片批量检索并保存后推进内容与布局；同一来源持续报429/503时不要sleep+curl反复试探。更换可靠来源并保留已有素材；不能用错误图片或仿真图冒充实景。
- 内容和语义错误必须修复；没有具体问题，不额外做整稿重复识图或逐像素字体校准。检查未完成时如实报告，不能用缩减内容、截图铺页或跳过检查来提速。
- 同一具体故障最多补修两轮；如果仍无新证据或仍被同一外部服务阻塞，说明失败位置与待确认页，结束本轮，不查宿主源码、不反复识图或重建整稿。桌面会保留本轮工具已登记、可读取且非空的已保存PPT，作为“待核对稿”在回复底部提供下载。它不是最终验收通过，不要称为成品；损坏、空白或内部试验文件不交付。下一轮继续修原工作稿。
- 最终交付工具返回成功后直接简要回复，不再用终端校验压缩包、哈希或删除临时文件；保存与交付检查已由宿主完成。同轮只显示最新正式版，不再另发工作稿。
