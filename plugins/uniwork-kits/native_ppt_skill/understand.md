# 理解已有 PPT / 回答 PPT 相关问题

用于读取已有 PPT 并回答问题，不修改源文件。用户要求修改内容时，转到 [edit-existing.md](edit-existing.md)。

## 读取 PPT

先 prepare，把用户指定文件复制到 outputs 的独立目录，保留原件。TencentPpt(action="inspect", file_path=复制稿, out=新空目录) 读取，再 read_file 读取输出的 slides.md。不要运行系统 slidep 或端口探测。

Markdown 按页提供文字、表格、图表数据和形状坐标。`### 结构` 只包含能够确定的关系；未提供的关系和视觉细节按信息不足处理。

先阅读与问题相关的页面。用户指定多份文件时，在回答中注明信息来自哪个文件和哪一页。

## 信息不足时

关系和方向以明确的连线、箭头或分组为准。需要图片内容、连线方向、空间关系或实际布局，但 `slides.md` 未提供可靠信息时，直接说明无法从当前文件结构确认，不根据位置或颜色作确定结论。

## 需要其他结构化信息时

仅当用户明确询问讲者备注、批注、章节、动画、母版、主题或精确对象属性，且 `slides.md` 未提供所需数据时，才按 [slide-tools.md](references/cli/slide-tools.md) 使用对应的只读 `slide_get_*` 工具。普通内容、布局和图片问题不调用 EDSDK；不得调用写工具。

## 读取失败时

根据命令报错检查文件路径、输出目录和服务状态。仍无法读取时，说明哪些问题无法回答；不要修改源 PPT。

## 回答要求

- 直接回答用户的问题，不复述工具调用过程。
- 区分 PPT 中明确写出的内容和推断；材料不足时直接说明。
- 核对页码、数字、单位、时间和关系方向。
- 面向用户的页码使用 1-based；`--page-index` 使用 0-based。
