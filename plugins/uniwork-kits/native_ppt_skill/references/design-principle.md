## 一、结构原则（视觉层）

### 1.1 画布与安全区

画布 1280×720；页面 padding **上下 60px / 左右 60px（均为硬下限，只能更大，不能更小）**；内容区 **1160×600**（上下左右各让出 60px 后的标准值；padding 加大则内容区同比缩小）。同类内容页之间的标题位置、页码位置必须保持稳定，封面 / 章节过渡 / 结束页允许自定义版式。

**页尾（页脚）落位**：页尾可以放在**下 padding 的 60px 带内**（y 660–720），这块不属于内容区，页尾放这里不占用 600px 内容高度。具体落位：

- 页尾**顶边距页面底部 50px**（即顶边固定 **y = 670**）
- 页尾内容底部仍距页面底边 **≥ 20px**（即不超过 y = 700）
- 左右仍受 60px 安全区约束：页尾左端 x ≥ 60、右端 x ≤ 1220
- 页尾字号 14–16px、行高按 §1.7；位置全篇固定，不逐页漂移
- **封面页 / 目录页 / 章节页（`type: section` 扉页）/ 封底页（结束页）禁止出现页尾**——页码、Source / Footnote、装饰条一律不加，**除非用户明确要求**。注意：这条管的是"全篇统一的页尾条"，不是封面自身的信息层（时间 / 汇报人 / 单位等，见 §1.8 第 4 条）——信息层仍按封面版式排布，不套用 y = 670 的页尾条

### 1.2 画布分区与构图

每一页是一张画布，先把它划成若干**区域**（圈地），每个区域承载一个内容块。构图方式自由（左右分、上下分、非对称、满版、错落），但**四件事必须做到**：

**① 圈地：先划区，再填内容**

动手之前先定——这页分几块、每块放什么、彼此是什么关系。不要边做边加块。

**② 区内自洽：一块地里只装一件事**

一块地里的所有元素（标题、正文、配图、结论）必须互相归属——它们一起说明同一件事。不相关的内容不塞进同一块地。

**③ 区有主次：一眼看出谁是主角**

一页里必须有一个"视觉主角"——通常是最大的图、最大的数字、最醒目的表。其余区域降权，服务于主角。自检：**读者第一眼看到的是什么？那就是主角。**

**④ 外框整齐，内部自由**

- 分区外框应有视觉上的对齐基准（顶 / 底 / 左右），不必像素级吻合
- 两区内容量差异大时，可用「锚点对齐」（标题基线、结论条）或让小区整体居中——禁止靠拉伸间距硬撑

**配套禁令**：

- **一页只有一个"总结"性质的块**——两个总结平级会让读者抓不住重点
- **区域数不要超过 4 块**——5 块以上几乎不可能有主次

### 1.3 内容密度与留白

以下为最低质量线：

1. **内容区铺满**：正文页内容区累计高度 ≥ 540px（内容区 600px 的 90%），但"铺满"必须靠**加内容**实现——补数据、补解读、补口径、补证据，**不许靠拉开间距或拉高容器**。
2. **撑不满就合并或走留白版式**：内容真的少到撑不满，优先合并到相邻页；只有不能合并时，才允许走留白版式（居中聚焦、大字 + 大留白），**不要把元素撑开**。
3. **禁止元素居中聚集**：内容不得全挤在页面中央 60% 区域、四周空一圈。
4. **底部空白过大的两种补救（第 1 条仍不满足时）**：所有核心内容排版结束、确实无法占满版面，导致**内容块底边到安全区底线 y = 660 的空白过大**时，对**主标题组以下的内容**做二选一调整：

   ⚠️ **禁止改动主标题组**：**主标题组（页面主标题 + 其下的贯通细线 / 分割线）的位置、字号、间距一律锁死**——主标题顶边固定贴安全区上沿（y = 60），细线紧随标题底线（见 §1.5）。**不得为了"腾空间"而把主标题下移、放大或缩小标题字号、拉开标题与分割线的距离**。本条的居中与加大间距，**只作用于主标题组以下的内容块**。

   - **整体垂直居中**：把主标题组以下的内容在剩余空间内**上下居中**，让上、下留白大致相等，消掉"下方一条大空白"。注意这不是第 3 条禁止的"居中聚集"——居中聚集是把内容缩在页面中央、四周空一圈；这里是**保持内容横向铺开、宽度不变**，只做垂直方向的均衡
   - **适度加大分区间距**：把分区间距 G 适度放大，让内容纵向铺开吃掉底部空白——但 **G 的放大必须保持 §1.5 / §1.7 的比例关系**（仍是 G > L、G ≥ 2T 时加线），且**只调间距、不许拉高卡片/容器**，容器仍须 hug content（§1.4）

   两者都必须先确认：**不是靠加装饰、不是靠放大字号、不是靠撑高容器**实现的；若居中后上下留白仍显空洞，说明内容本身不够 → 回到第 2 条合并或拆页。

5. **密度不够补内容，不补装饰**：缺数据补数据、缺解读补解读；严禁靠放大留白、加色块、加装饰图形把版面撑开。
6. **容器填充率 ≥ 85%**：卡片 / 容器内实际内容（文字 + 引文 + 装饰）垂直占用应 ≥ 容器高度的 85%。容器越高要求字数越多——高 ≥ 380px 的卡片正文 ≥ 100 字；高 ≥ 480px 的卡片正文 ≥ 130 字。
7. **焦点留白 ≥ 40px**：每个视觉锚点（巨型数字、核心图、大标题）周围留出 ≥ 40px 呼吸空间。
8. **Hero 页允许 40-50% 留白**，但必须围绕核心元素聚焦，不能均匀散布。
9. **禁"均匀稀薄"**：留白不围绕焦点、而是每两个元素之间都有差不多大小的空白 → 必须返工（补内容或合并页面）。
10. **常规内容页留白上限 35%**（封面 / 章节过渡 / 结束页 / 显式声明的"留白型"页不受此限）。

### 1.4 容器、对齐与间距

3. **区块对齐**：见 §1.2 第 ④ 条「外框整齐，内部自由」。
4. **容器高度贴合内容（hug content）**：卡片、框、竖线的高度 = 内容高度，随内容收缩。**禁止固定高度导致装饰超过内容**——竖线超长、框里空半截都是典型反例。
5. **间距两档制**：块间距只用 24px（紧密）和 32px（宽松）两档；同层级用同一档，禁止 16/20/28 随手混用。
6. **横向兄弟卡 y 轴等高对齐**：同一行多张卡片，其内部"标题块 / 正文块 / 底部元素"三段在 y 轴上必须等高对齐。任意两卡的尾部元素 y 坐标差 > 16px → 返工。
7. **禁止元素叠放**：文本不得与文本、文本与容器/装饰相互重叠或溢出容器。出现文本重叠时，**先检查相关分区之间的间距是否被压缩**，通过调大分区间距、让容器 hug content 解决。

### 1.5 分区与母题

**分区手段优先级**：细线 / 留白 / 对齐 > 浅色底块。浅色底块是最后手段，不是默认手段。

**分区形式按具体内容与分区间距选择**：间距大 → 用细线，间距小 → 用留白（详见下方选型表）。

| 分区间距 | 选用形式 | 理由 |
| :-- | :-- | :-- |
| **间距大（≥ 32px）** | **细线（1px）** | 空白已够宽，光靠留白读者仍会把两块读成一条流，需补一条线钉住边界 |
| **间距小（< 32px）** | **留白 + 对齐** | 靠拉开间距、对齐来分区即可；此时再加线会让版面变碎，反而更乱 |
| 需要标示真实分组 / 状态 | 浅色底块（最后手段） | 只有「当前步骤」「异常项」这类真实语义才用；"怕读者看不出"不是理由 |

**竖排小分区的间距层级与分区形式**（01 / 02 / 03 这类竖向堆叠的小分区）：

记 **T = 该分区内部标题与正文的间距**、**L = 正文行间距**、**G = 两个分区之间的间距**。

| 条件 | 分区形式 | 理由 |
| :-- | :-- | :-- |
| **G ≥ 2T**（且 G > L） | **1px 细线区分** | 分区间空隙已足够大，补一条线把边界钉住，两块不会被读成一块 |
| **G < 2T** | **留白区分** | 间距不足以支撑一条线，靠拉开间距 + 对齐分区即可；此时加线会让版面变碎 |

- **硬性下限**：G 必须 **> 正文行间距 L**，否则两块会被读成同一块
- 竖排分区叠满时优先删内容或拆页，**禁止靠压缩 G 硬塞**，也禁止 G < 2T 时仍加线

**例外——唯一直接使用细线的竖排情形**：**没有小标题、没有分区，只有几行同层级条目竖排**（条目清单 / 术语对照 / 编号列表；典型样式为左列条目名 + 右列同层级说明）。此时：

- **每行之间直接加 1px 细线**，不受上面的 2T 判据约束——因为各行是**同层级的行**，不是"区"，没有"区内标题-正文间距"可作基准
- 细线在此承担**行分隔**功能：一行一条线、线贯通内容区宽度、线的上下间距一致，形成整齐的横向节奏；线用浅灰（如 `#E5E7EB`）等中性色，不用主色
- 行内版式固定：左列条目名 + 右列同层级说明，两列 y 基线逐行对齐
- 前提是各行**行高一致、左边界对齐**；行高不一致时先统一行高，再加线
- 若每行各自带小标题 + 正文（即已成为"分区"），则退回上面的 G vs 2T 规则

**细线交叉成格（表格化）时的落位规则**：横竖细线交叉、形成类似表格的网格时，**每个格内的内容块必须在"上下两条横线划出的横向带"内垂直居中**——即到上、下两条横线的距离相等，**不得贴着上一条线的下沿顶部对齐**（那样会在格底留下一条明显空带）。

- **同一行各格**的内容垂直中心线必须落在同一条水平线上（行内居中基准一致）
- **横向落位**仍按列的对齐基准（通常左对齐），居中只作用于**垂直方向**
- 格内若含小标题 + 说明，先按 §1.7 的 T 规则排好标题与正文，再把整块一起在带内居中
- 线仍为 1px 浅灰中性色、横竖贯通，构成真正的网格；**不得因居中而让某格内容贴线**

**配套纪律**：

- **一页最多 2-3 个浅色底容器**：需要更多分区时改用 **1px 细线或留白**
- **每个底色块必须有理由**：标示真实分组或状态（如"当前步骤"、"异常项"）；"怕读者看不出"不是理由，无理由的底块一律删掉改用留白
- **主色必须主导**：主色使用量 > 任何中性色使用量；如果浅灰 / 浅蓝底块比主色更显眼，说明页面被中性色淹没，主次不成立

**贯通细线 > 短装饰线**：分区细线应**贯通内容区宽度**、**线宽 1px**，承担结构功能。标题下方只有标题 1/8 宽的短装饰线不承担任何功能，是典型 AI 痕迹——**禁用**。

**细线与装饰严禁遮挡文本（硬）**：分区细线、图表内装饰线/装饰元素只做分区或装饰，位置必须避开所有文字——压住正文（如横线穿过时间轴条目）即返工；调整装饰位置，不动文本。

**视觉母题**：全篇应确定**一个贯穿性结构元素**（如标题下的贯通细线、固定位置的章节眉标、统一的编号块），每页复用。它比每页新增装饰更能建立设计感。

### 1.6 字号与尺度

**同页文字样式组合上限 4 种（硬性）**：

一页内「字体 + 字号 + 字重 / 加粗」的**不同出现形式**不得超过 **4 种**——同一组合在一页里重复出现只算 1 种（如所有卡片小标都用同一组合）。

- **highlight 不计入**：为强调关键词而做的提亮、变色、局部加粗，属于强调层，**不算进 4 种组合内**；但提亮后不得因此产生新的层级（见下方尺度跳跃要求）
- 超 4 种 → 合并层级或删内容，**禁止靠新增样式制造层次感**

**字号硬下限**（1280×720 画布，违反必须返工）：

| 用途                | 硬下限            |
| ------------------- | ----------------- |
| 页面主标题          | **≥ 32px** |
| 卡片小标题          | **≥ 22px** |
| 正文 / 卡片正文     | **≥ 18px** |
| 图表标签 / 表格内容 | **≥ 16px** |
| 脚注 / 来源 / 页码  | **≥ 14px** |
| 任意可见文本        | **≥ 14px** |

**正文字号不宜过大**：正文是承载量最大的层级，过大只会把版面撑爆、逼出拆页——常规正文取 **18-20px**，只有"大字阅读型"页面（Hero 金句、执行摘要）才允许上探到 22px；正文 > 24px 需有明确理由。

**例外——大字列点页（允许正文 22px）**：整页走「**列点举例**」结构、每条正文都很短（一句说明，**每条约 15-35 字**）时，字号可以整体上调一档：

- **正文/条目说明：22px**（而非常规 18-20px）
- 若每条带小标题，**小标题：30px**
- 适用形态：2 列 × N 行 / 3 列 × N 行的编号条目清单（如 `01 标题 + 一句说明`），每格留白均匀、无长段落
- 反之不成立：**只要有一格出现两行以上连续段落（单条 > 40 字），就退回常规 18-20px**，否则字数与字号叠加必然撑爆版面

**尺度跳跃要求**：

- 相邻层级字号差 **≥ 4px**
- 锚点数字（巨型数据）与正文的尺度差 **≥ 2 级**

**强调数字的单位 / 辅助文字落位（硬性）**：

巨型数字、锚点数字（如 `68`、`80.9%`、`1,239 万`）所带的**单位或辅助文字**，位置固定：

- **默认：数字右下角，底部对齐**——单位 / 辅助文字放在数字**右侧偏下**，与数字**底边（基线）对齐**；不得悬在数字顶部（上标位），也不得垂直居中漂在数字右侧中部
- **唯一特例：度数符号 `°` 放数字右上角**（上标位，如 `36.5°`）
- 辅助说明是一句较长文字（口径 / 注释，如「移动 422.8 万 + 联通 28.4 万」）时，**不挤在数字同一行**，换行放到**数字下方**，按正文 / 脚注层级排
- 字号：单位约为数字字号的 **1/4–1/3**；辅助文字按正文或脚注层级（≥ 14px）

**强调卡片层级 ≤ 3 层（硬）**：用于强调的卡片（深色大数卡、焦点卡）内**只放一个主要强调层级**（巨型数字 / 核心词），其余全是辅助信息；卡片内层级 **≤ 3 层**（如：辅助标签 → 主数字 → 一行说明）。往强调卡里塞时间范围、分式、多条正文会稀释强调——放不下就移到旁边的正文区。

**禁靠缩字号塞内容**：字号不足时**减少内容、重组或拆页**，不许缩字号去凑字数。"大字优先级 > 字数下限"——内容塞不下就精简文案或合并页面。

### 1.7 行间距与段间距

**行间距定义**（`line-height`，以倍数计，实际行高 = 字号 × 倍数）：

| 文本类型 | 行间距倍数 | 示例 |
| :-- | :-- | :-- |
| 正文 / 卡片正文 | **1.4–1.6** | 18px → 25-29px；20px → 28-32px；22px → 31-35px |
| 卡片小标题 / 短标题 | **1.2–1.35** | 22px → 26-30px |
| 页面主标题（多行时） | **1.1–1.25** | 32px → 35-40px |
| 脚注 / 来源 / 页码 | **1.3–1.5** | 14px → 18-21px |

- **硬下限**：任意文本行高 **≥ 字号 × 1.2**，低于此值中英混排、上下伸笔画会挤在一起
- **同段一致**：一个段落内所有行的行高必须相同，**禁止逐行微调行高**

**段间距定义**（同一内容块内相邻两段之间的空白，**不含行高自带的行内行距**；行内行距 = 行高 − 字号）：

| 场景 | 段间距（= 字号 × 0.5–1.0） | 示例 |
| :-- | :-- | :-- |
| 正文 18px | 9–18px | 行高 27px 时，两段间再空 9-18px |
| 正文 20px | 10–20px | 行高 30px 时，两段间再空 10-20px |
| 正文 22px | 11–22px | 行高 33px 时，两段间再空 11-22px |
| 脚注 / 来源多行 | 7–14px | 14px 字、行高 20px 时 |

- **硬下限**：段间距必须 **> 该段的行内行距（行高 − 字号）**，否则两段在视觉上会被读成一段
- **同块统一**：同一内容块内所有段间距取同一值，**禁止逐段随手调整**
- **段间距永远小于分区间距**：段间距是"区内"间距，分区间距 G（§1.5）是"区间"间距，二者混淆即视为分区失败

**区内标题与正文的间距 T（硬性）**：**T 必须 > 正文行间距 L**——否则标题与它下面的正文会被读成同一段文字，标题失去统领作用。

- 取值区间：**L < T ≤ 2L**（例：正文 18px、行高 27px → T 取 **28-54px**，常规用 28-36px）
- 三级间距必须严格递增：**段间距 < T < 分区间距 G**，任何一级被压缩到与下一级持平，层级即失效
- 与 §1.5 联动：T 同时是竖排分区选型的基准（G ≥ 2T 用 1px 细线，G < 2T 用留白）

### 1.8 封面页信息层级（硬）

封面只做一件事：**3 秒内讲清这份 PPT 是什么**。信息层级**最多 4 层**，且字号逐层递减：

1. **主标题（必须有）**：讲清这份 PPT 的主题
2. **副标题（按需）**：**按用户需求合理使用**——一句话点出视角 / 范围；用户没有这个需求就不加，不留空占位
3. **说明层（可选）**：一行简短说明文字或 2-4 个关键词，与主题同属一件事
4. **信息层（按 PPT 类型确定）**：时间、汇报人、汇报对象、单位等，用封面底部小字（14-16px）承载——**这是封面自身的信息区，不是全篇页尾条**（封面默认不加页尾，见 §1.1）

**禁止出现数据与数据说明**：封面不得出现任何数据指标（达成率、任务额、销售额、增幅等）、数据看板 / 巨型数字，以及"口径""数据来源""同比说明"这类数据注释——**数据和它的判断属于正文页**（见 §2.1），提前放到封面只会泄露结论、徒增阅读负担。典型反例：封面底部一排"61.2% 全月预估达成率 / 2500 万任务 / 1530 万预估 / 970 万缺口"。

**自检**：封面除主标题、可选的副标题与一行说明、页脚信息外**再无其他文字块**；层级 ≤ 4 且逐层递减（封面主标 60-96 / 副标·说明 20-30 / 页脚 14-16，字号细节见 §1.6 与 scenario 字号表）；副标与说明合计 ≤ 2 行。

### 1.9 目录页（硬）

**目录↔章节扉页契约**：目录（catalog）里声明了 N 个章节，全篇就**必须有且仅有 N 个 `type: section` 章节扉页**，一一对应，不允许合并、跳过或缺失。每个扉页的**编号（01..N 连续）、标题文字、页码区间**都必须与目录对应条目**逐字一致**。

**目录页只保留**：**目录标识（"目录 / CONTENTS"）与章节清单（编号 + 章节名 + 页码）**，最多允许一条副标 / 汇报人等基本信息。以下三类"废话块"一律禁止出现：

- **统计装饰块**：「N 个章节 / 全篇共 N 页」这类巨型幽灵数字 + 数量统计——章节数和页数读者自己看得到，纯属凑数装饰
- **"阅读顺序"条**：把目录复述一遍的导航条（如「阅读顺序：01 看XX → 02 看XX → 03 看XX → 04 看XX」）——目录本身就是阅读顺序，再复述一遍等于废话
- **"全篇主线"预告**：一句话剧透全篇结构 / 主线的说明行（如「全篇主线：Q1 拆能力，Q2 接对话」）——这是执行摘要 / 开场的事，不是目录的事

自检：删掉统计块、阅读顺序条、主线预告后目录信息零损失 → 这些块本来就不该存在。

### 1.10 章节页（硬）

章节页的作用：内容页很多时给观众一个提示，并对本章内容做精简总结。

- **信息精简**：只放**章节数（01 / 02…）+ 章节名**，最多加一句简单章节总结或几个关键词。禁止大段导语、"看点一 / 二 / 三"列表、"本章结论"条——这些是章节内正文页的事
- **全篇同版式**：同一份 PPT 里所有章节页必须用同一版式（构图、编号位置、字号、装饰完全一致），禁止逐章换样式
- **按需生成**：**大部分章节只有 1 页、或超过一半的章节只有 1 页时，不生成章节页**——篇幅撑不起提示页，用目录页提示即可，不要为凑结构加冗长页

### 1.11 结尾页（硬）

可以没有结尾页，但**禁止把结尾内容塞进内容页**——内容页内不得出现收尾性质的块：致谢条（"谢谢，请指正"）、金句横幅、"汇报人 + 日期"落款块等。内容页只放本页内容；需要收尾就单独做封底页。

## 二、写作原则（内容层）

### 2.1 数据必须落判断

STORY 阶段做的是「观点组织」，不是「信息摘录」。关键数值 / 比例 / 排名 / 年份 / 实验结果后，必须补一句判断——三选一：

- **含义解释**：这个数字说明技术/行业处于什么状态（`14nm → 沟道栅长被压缩到必须精确管理的尺度`）
- **业务影响**：这个数字对业务/决策意味着什么（`增长 16.3% → 行业仍在增长，但高基数后增速转温和`）
- **管理启示**：据此该做什么判断（`不能只用总量增长判断机会，必须看细分结构和商业质量`）

反例：只写 `2026 年销量预计增长 16.3%` 就收尾——这是信息板，不是汇报稿。

### 2.2 每一块都要有一眼可见的结论

无论页面密度如何、被分成多少个板块，读者扫到任何一块，不用读完正文也能看出这块想说什么。可参考的方法：

- **结论句前置**：块的顶部一句话标题就是结论（"用户规模增长已放缓"，而不是"用户规模分析"）
- **数据提亮**：块里的关键数字 / 关键词改大字号或改色，让眼睛直接被吸过去
- **结论条锚底**：块的底部压一条浅底横条或细色条，里面一句结论——这是整块的最终 takeaway

块内每个数据点的判断（见 1.1），最终要收口成这一句块级结论——**数据判断是素材，块级结论是成品**。

禁止：一块只有图表 / 表格 / 数据罗列，却没有说明"这想说明什么"；结论句是中性陈述（"XXX 分析"是目录，不是结论）；整页信息很多，但读完说不出每块的要点。

### 2.3 图表 vs 表格分工

**图表用于看关系与趋势，表格用于查数值与比较**。二者同时出现时分工要明确；突出关键系列、目标公司或基准情景，避免所有元素同等醒目。

## 三、通用禁止项（硬）

### 3.1 禁止均分构图

- 等宽多栏、等大卡片网格 → 看起来"整齐"，实际是放弃设计
- 内容天然不等分（主/次、大/小、前/后），布局就不该等分
- 具体版式级约束（如非对称 ≥40%、Hero 禁等宽横排）见 scenario / `general.md`

### 3.2 禁止 AI 味儿的表达

具体指四类：

- **形容词堆砌的"卖点式"标题**（"卓越表现"、"行业领先"、"重大突破"）——用具体动词和数字替代
- **对称罗列的 SWOT / 三大优势 / 五大趋势**——研究报告不做名词罗列，只做比较和推断
- **万能句式**（"随着 XX 的发展，YY 面临新的机遇与挑战"）——这种句子拿掉专有名词到哪都能用，等于没说
- **emoji、感叹号、装饰性 icon 堆砌**——icon 跟 emoji 一样，承担不了信息量，只承担"想让这里显得活泼"的意图；严肃 deck 里一出现就像 AI 写的。**例外**：流程节点、设置齿轮等有明确功能语义的 icon 允许。

### 3.3 禁止空容器

任何卡片 / 面板 / 分区框都必须有内容。渲染出来是空的就删掉——**空白容器比没有更难看**。`anti_pattern` 字段写得空泛（如"避免单调"）也不合格。

## 四、页面叙事通用框架

> 以下为通用审美偏好，**scenario 有明确要求（如投研的"高密度阅读型"、发布会的"全页高潮"、政务的"对称庄重"等），以 scenario 为准，可适当参考本部分的审美建议**

### 4.1 起伏节奏（页面角色与 rhythm 字段）

如场景无特殊要求，建议 deck 有起伏节奏——重要页视觉张力大、次要页克制、章节间过渡；避免全篇同一密度让读者疲劳。

**页面角色**（DESIGN.md 的 `role` 字段）与**叙事节奏**（DESIGN.md 的 `rhythm` 字段）映射：

- **Hero（视觉高潮）/ peak**：视觉爆发，允许更大留白，强调色占比可达 15-20%。**封面和结束页默认 Hero**。
- **Supporting（信息承载）/ valley**：信息密度高，颜色更克制，为下一个高潮蓄势。
- **Transition（章节过渡）/ transition**：章节切换，极简大字 + 简单视觉。

**通用建议配额**（scenario 未定义时参考）：

- Hero 页占整份 PPT 的 **20-30%**（10 页中 2-3 页，15 页中 3-4 页）
- Hero 页不宜相邻，两个 Hero 页之间至少间隔 1 个 Supporting 页
- 连续 ≥ 3 页同为 valley → 建议插入一个 peak 或 transition 打破沉闷

⚠️ **例外**：高密度阅读型（投研、学术）可以全篇克制、Hero 更少甚至没有；发布会 / keynote 类可以反过来，Hero 占比 40%+。

### 4.2 视觉锚点配置（visual_role）

逐页确定 `visual_role`，决定该页"图"的叙事身份：

- **anchor**：图是这页的主角（通常对应 Hero 页或视觉冲击页，至少占 B 区 ≥ 40% 或配 ≥ 48px 锚点数字）
- **atmosphere**：图做背景烘托（适用于章节过渡、全幅图骑线文字页）
- **evidence**：图证观点（数据图、流程图、产品对比图，从属于文字论述）

`visual_role` 应与 `role` 协同：**Hero 页的 `visual_role` 默认是 `anchor`——如果一个 Hero 页的 `visual_role` 不是 `anchor`，说明这个 Hero 不成立**，要么升级视觉（换成大图/大数字/整屏视觉冲击），要么把它降级为 supporting。

### 4.3 配图分级与规划（visual 字段）

每页 `visual` 应给出 **L1 / L2 / L3** 中至少一项；纯结构页（目录、对照表）允许仅 L3。

| 等级                     | 用途             | 尺寸硬下限                                                 | 位置规则                                             |
| ------------------------ | ---------------- | ---------------------------------------------------------- | ---------------------------------------------------- |
| **L1 · 主视觉**   | 承担页面主要叙事 | **占内容区 ≥ 40%**；常见 560×420 / 640×480 / 半屏 | 卡片整体背景、一栏铺底、引文卡叠层                   |
| **L2 · 支撑图**   | 强化某个段落     | **≥ 280×180**                                      | 段落旁、卡片头部、与正文并排                         |
| **L3 · 母版徽标** | 全篇统一角标     | **≤ 64×64**                                        | **全篇位置必须一致**（页脚左或页眉某角，不换） |

**铁律**：

- **禁装饰小贴片**：200×70 等小尺寸图片塞标题块右侧——不承担叙事只占空间，典型 AI 痕迹
- **全篇 L1 风格统一**：同一份 deck 的 L1 要么全摄影、要么全插画、要么全 3D，禁混用（刻意混搭需显式声明）
- **L3 位置全篇一致**：不能一页在左下、另一页跳到右上
- **底图上的蒙层只为让文字可识别**：底图细节多、色彩杂（文字压在杂乱画面上）时，文本区的蒙层不透明度**必须 > 80%**；底图本身干净（大面积天空 / 纯色 / 简洁构图）可放宽。文字压图看不清 = 直接返工

**其他标注类型**：

| 标注示例            | 含义                                   |
| ------------------- | -------------------------------------- |
| `Chart(柱状图)`   | 数据图表，注明类型                     |
| `Diagram(时间轴)` | 图示组件，注明类型                     |
| `FAIcon列表`      | 图标化要点卡片                         |
| `大数字`          | 关键数据极大化呈现——必须标注最小字号 |

---

### 4.4 anti_pattern 约束

每页应显式写出 `anti_pattern`——不是抽象的"避免 AI 味"，而是基于本页 `role / rhythm / layout` 写出**具体禁止项**。例如：

- Hero 数据冲击页：`anti_pattern: 禁止等宽卡片横排；禁止把核心数字塞进图表卡角落`
- 章节过渡页：`anti_pattern: 禁止四卡片预览；禁止铺满正文段落`
- 产品展示页：`anti_pattern: 禁止 50:50 等分双栏`

**与 §4.3 的协同**：涉及 L1/L2/L3 配图分级的禁令（如禁 200×70、L3 位置漂移、L1 风格混用）已在 §4.3 列明，不需在 anti_pattern 字段重复——anti_pattern 应补充本页特有的禁区。

## 五、构建 DESIGN.md

### 5.1 总的输出：全局视觉约定

写在 DESIGN.md 文件开头，作为所有页面的统一基准——**一次定好、全篇不换**。

#### ① 画布与安全区

- 画布尺寸（默认 1280×720）
- 页面 padding：上下 60px / 左右 60px（硬下限，不可更小）
- 内容区 1160×600（padding 加大则内容区同比缩小）

#### ② 配色方案（来自 scenario，选定一套）

| 槽位   | Hex      | 用途                           |
| ------ | -------- | ------------------------------ |
| 主色   | `#XXX` | 顶条 / 编号 / 强调             |

| 强调色 | `#XXX` | 关键数字 / 核心标注            |
| 底色   | `#XXX` | 主背景                         |
| 正文色 | `#XXX` | 主文字                         |

**色彩面积纪律**：主色 ≤60% / 辅色 ≤30% / 强调色 ≤10%（详见 scenario 的色彩节奏规则）

#### ③ 字体系统（来自 scenario，选定一组）

- 中文字体：XXX
- 西文字体：XXX
- 字号阶梯：封面主标 / 章节大字 / 巨型数据 / 页面主标 / 卡片小标 / 正文 / 注释（具体 px 值）

**铁律**：全篇只用这一组，不引入第三族；字号硬下限见 §1.6。

**数字不单独换字体**：同一句话 / 同一段里的数字跟随该句的文本字体，不允许给数字配独立字体；**只有刻意强调该数字时**（巨型数字、锚点数字）才允许换字体或放大。

- "标题下 1px 贯通细线"

L1/L2/L3 分级与尺寸规则见 §4.3；生图操作细节见 `references/dsl/image.md`。

### 5.2 每一页的输出：字段表

每页按以下字段规范展开：

| 字段             | 说明                                                                                                               | 示例                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------- |
| `title`        | 页面标题                                                                                                           | 市场规模与增长                      |

### 5.3 构建顺序

1. **先列页面总数与分章**
2. **定全局视觉约定**（5.1 的 5 块）—— 关键步骤，先定好再逐页，不要边做边改
3. **定节奏预算**：按 §四 定 Hero 配比、相邻不重复
4. **逐页填字段**（5.2）：
   - 骨架：`type / role / rhythm`
   - 视觉：`layout / visual / visual_role`
   - 内容：`description`（按字段表说明，写清楚本页具体会讲什么）、`density`、`anti_pattern`

## 六、完成检查

- ❌ 含关键数据的页只摆数字、不给判断（信息板而非汇报稿）
- ❌ 任意页缺少 `role` / `rhythm` / `visual_role` / `anti_pattern` 字段
- ❌ 任意 `type: content` 页的 `description` 停留在"行业现状""未来展望"这类抽象层面，未带本页实际会讲到的具体名词 / 数值 / 实例
- ❌ 出现均分构图
- ❌ 出现 AI 味标题 / 万能句式 / emoji
- ❌ 空容器 / 内容区高度 < 540px
- ❌ **封面信息层级 > 4 层，或封面出现数据指标 / 数据说明（数据看板、巨型数字、口径与来源注释等）**（§1.8）
- ❌ **封面页 / 目录页 / 章节页 / 封底页出现页尾（页码、Source / Footnote、装饰条）**，且用户未明确要求（§1.1）
- ❌ **底部空白 > 60px 且未做补救**：内容块底边到页尾顶边（y = 670）的空白 **> 60px** 时，必须检查**除主标题组以外的全部内容**是否做了 §1.3 第 4 条的处理——① 整体在内容区（y 60–660）内垂直居中，或 ② 适度加大分区间距 G（仍满足 G > L、G ≥ 2T，且未拉高容器）。**两者都没做 → 返工**；做了其中之一 → 通过，但需确认不是靠加装饰 / 放大字号 / 撑高容器实现的
- ❌ 页面 padding 上下或左右 < 60px，或内容区宽 > 1160px / 高 > 600px
- ❌ `type: section` 章节扉页的数量 ≠ 目录声明的章节数
