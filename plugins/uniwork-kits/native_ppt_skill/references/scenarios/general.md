# 通用（兜底方案）

> 定位：需求**未命中任何具体场景**时的兜底方案——产品介绍、工作总结、技术分享、项目提案、述职报告等大多数日常场景。
> 触发：路由表全表无命中时，使用本文件。

---

## 一、整体理念

通用场景是最容易做得平庸的场景——因为没有明确的视觉文化可依，AI 容易退化成"居中标题 + 上下分栏"的流水线。所以：

- **视觉与文字并重，优先图说关系**。PPT 是演示，不是文档——该用图就用图，该用大字就用大字，不要凡事都用卡片堆文字。判断标准：**凡是能用图形结构表达的关系（层级 / 流程 / 对比 / 分布 / 转化），优先用图而不是卡片**；但一句关键结论、一段金句、一个大数字，让文字自己说话同样好——它们是"视觉"的另一种形态
- **配图很重要，且要承担叙事**。通用场景尤其容易退化成"通篇文字卡片"——那是最没视觉说服力的形态。判断标准：适当用**配图或图表**叙事；具象场景（人物、产品、城市、办公）优先用真实生图，SVG 只用于结构化图形。**生图的主体 / 场景 / 色彩必须与内容贴合**
- **不规则 > 规则**。错落、重叠、非对称、尺度跳跃——比规整排版好看
- **组件复杂 > 组件单一**。图 + 文 + 数据 + 标签 + 结论条组合，比单一元素居中好看

**色彩面积分配**（整页）：

| 色彩角色         | 面积占比 | 用途                         |
| ---------------- | -------- | ---------------------------- |
| **主色**   | ≤ 60%   | 背景、大色块、标题栏底色     |
| **辅色**   | ≤ 30%   | 卡片底、图表第二系列、分隔线 |
| **强调色** | ≤ 10%   | 关键数据、CTA、核心标注      |
| 中性色           | 剩余     | 文本、页脚、边框             |

**色彩节奏规则**（防止全篇色彩比例雷同）：

- **Hero 页**：强调色可提到 **15-20%**，色彩爆发
- **Supporting 页**：强调色 **≤ 5%**、辅色 **≤ 20%**，为下一个高潮蓄势
- **禁止全篇每页色彩比例雷同**：至少 2 页的色彩比例应与其他页显著不同

**其他纪律**：

- 主色用于背景大色块、标题栏、主要图形；辅色用于卡片底、图表第二系列、分隔线；强调色**只用于视觉焦点**（巨型数字、核心结论、CTA）
- 强调色是稀缺资源，**一页最多 2-3 处**；**一份 deck 只用一个高饱和强调色**（accent），不并立第二个（图表多系列色是例外）
- **深色大块每页 ≤ 1**：装最重的那条信息
- **文字色全页 ≤ 4 种**（标题 / 正文 / muted / accent）
- **禁用阴影**：任何元素都不写 boxShadow，层次靠底色 + 1px 线 + 留白
- 禁用：彩虹渐变、荧光色、高饱和撞色铺满 1/3 以上页面、同一页出现两套主色板
- **禁"全系统默认无衬线"**——必须明确具体字体名
- 背景图上要压文字时，用 `rgba(0,0,0,0.35~0.5)` 蒙版保证对比度 ≥ 4.5:1

**图表规则**：

- 多类别图（堆积柱、簇状柱、环形）用**色板的不同系列色**，不用单一 accent；数据只有 1 个类别才用 accent
- 类别数超过色板区分度时**先合并类别**（如"小米 7% + OPPO 6% + vivo 5%"合并为"国产第二梯队 18%"），不靠相近色硬区分
- **数据点 > 3 的柱图关闭数据标签**，把关键数值写在图表旁的读数条里

| **活力亲和** | 雅黑 / 黑体             | Futura / Avenir                | 教育、消费、儿童、生活     |

| **极简设计** | 黑体                        | Helvetica Neue / Arial         | 设计、建筑、时尚、摄影     |

**规则**：

- 整篇**不超过两种字体家族**。标题和正文可以用不同个性（如宋体标题 + 黑体正文）
- **禁用腾讯体（W3 / W7）、苹方**：授权 / 跨平台原因不可用，同类需求一律用**雅黑 / 黑体**替代
- 巨型数字 / 锚点数字必须用与正文不同的字重或字号，让眼睛被吸过去
- **数字不单独换字体**：同一句话 / 同一段里的数字跟随该句文本的字体；只有刻意强调的数字（巨型数字 / 锚点数字）才允许换字体或放大
- 用户自带字体（哪怕楷体、仿宋）要尊重——那是他的表达

## 四、容器图鉴（词汇表）

**定位**：以下是常见的容器形态，供 AI 借鉴与启发。**只列思路，不规定做法**——描边粗细、颜色、圆角、阴影强度等具体视觉参数，由模型根据配色、风格气质、整体节奏自由发挥。清单也不是穷举，鼓励按需组合、变形、创造新款式。组件容器的存在能够让内容显得视觉上更规整。 **

> **原则 1（圆润度）**：所有矩形容器、色块、强调块、装饰方块**都要带一定的圆角**（常规 4-8px，大色块可到 12-16px），**禁止 0 圆角的直角方块**——纯直角会显得生硬、过时、"PPT 感"很重。小装饰方块（如 10-20px 的色点、标记块）也要做成圆点或圆角方块，不要留尖角。全篇**圆角档位统一**（选一个值全篇用），不要同页混 2px / 8px / 16px。
>
> **原则 2（禁止裸露表格）**：**对比表、多列数据表、多行多列的文字清单，必须有视觉容器承载**——外层包一个描边卡 / 浅底填充卡，或至少有贯通内容区的顶线+底线把表格框起来。**禁止纯行列文字直接飘在页面底色上**，哪怕有行间细线也不算——这会让表格看起来像从 Word 里直接贴过来的"裸表"，严重缺乏设计感。<br>**判断标准**：如果你把这张表移到页面任意位置，看起来还像是"浮在白纸上的文字"，就是裸露表格，必须补容器。<br>**提示**：这条和"表格 cell 不填色/行不填色"不冲突——表格本体可以透明，但**外层容器必须存在**。

| - | -------------- | ------------------------------------------------------------------------------ |
| 1 | 描边卡         | 用边框线勾勒容器轮廓                                                           |
| 2 | 浅底填充卡     | 用浅色背景块承载内容                                                           |
| 3 | 带 icon 分段卡 | 图标 + 文字组合，形成要素化段落                                                |
| 4 | 深色强调卡     | 深色底 + 浅色字，形成反色突出                                                  |

## 五、布局候选池（**核心**）

下面按**页面功能**分组，共 27 个风格差异明显的候选布局。AI 根据**内容性质 + 素材情况 + 整体节奏**自主决定每页用哪个。

**鼓励挑复杂 / 不规则的那几个**——除非本页承担的是信息密集的查读任务。

**版式使用的硬约束**（整篇都要遵守）：

- 相邻页面必须用不同版式
- 非对称版式占比 ≥ 40%
- 对称版式全篇最多 2 页
- 连续 ≥ 2 页对称 → 第 2 页必须改为非对称
- Hero 页禁用等宽卡片横排
- 等宽卡片横排全篇最多 2 次
- 非对称版式内部也要多样——「左图右文（§5.2 a）」与「对比式（§5.2 h）」合计 ≤ 全篇页数的 40%
- **相邻两页至少变 2 个维度**（构图轴 / 图像占比 / 锚点 / 密度 / 明暗 中变 2 个）；**连续 3 页同构**（版式 + 密度 + 锚点类型全一样）→ 硬失败必须拆

⚠️ **例外**：儿童教学、政务、庆典、悼念等场景可能天然对称/居中——以 scenario 为准。

### 5.1 封面类（5 个候选）

封面页不需要承担太多的文字信息，适当简洁即可。封面信息层级（≤ 4 层、主标题必有 / 副标题按需）、禁止数据与数据说明、封面不加页尾等硬性要求**统一见 `design-principle.md §1.8` 与 §1.1**，本文件不重复。

| #           | 名字              | 风格描述                                                                                                                                                                                                                       |
| ----------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **a** | 满版图 + 渐变蒙层 | 一张主视觉图铺满整页，上压由底向上渐变的深色蒙层（底部深 → 中部透明）。标题大字叠在蒙层下部，可加柔和阴影增强层次。**仅非严肃场景**（科技 / 创意 / 发布会类）；学术、投研、政务不用。像纪录片片头、Netflix 人物专题海报 |
| **b** | 大字报式          | 超大标题（80-120px）占据画面主体，配一行小副标，四周大面积留白。**没有图也能做得很有力**                                                                                                                                 |
| **c** | 杂志对页式        | 左 2/3 主视觉出血，右 1/3 浅色文字区（刊头小字 → 大字标题 → 副标 → 底部一行目录提示）                                                                                                                                       |

### 5.2 内容页类（13 个候选）

**选哪个候选，先看内容性质**（这一步决定成败）：

| 内容性质                                             | 优先选                                                     | 不要选          |
| ---------------------------------------------------- | ---------------------------------------------------------- | --------------- |
| **层级 / 分层结构**（如"四层栈""三阶结构"）    | 金字塔 / 层级（j）、分层架构图（SVG）                      | 并列卡片        |
| **流程 / 阶段 / 时序**（如"5 个步骤""三阶段"） | 流程链（g）、横/纵时间轴（e/f）                            | 并列卡片        |
| **转化 / 筛选**（如"从 1000 到 100"）          | 漏斗（k）                                                  | 卡片组          |
| **对比**（A vs B、Before / After）             | 对比式（h）、2×2 矩阵（i）                                | 卡片组          |
| **数据展示 / 图表洞察**                        | 数据展示（l）                                              | 卡片组          |
| **数据密集列表 / 长 KPI 清单 / 特征详述**      | 左标题色块 + 右内容（m）                                   | 等宽多栏        |
| **真正并列的独立要点**（彼此无递进、无从属）   | 卡片组 + 底部结论条（d）、三栏非均分（c）                  | —              |
| **观点 / 金句**                                | 一句独白（见 §5.3 c）、巨型数字+洞察（见 §5.3 a）        | 装进引言卡片    |
| **视觉叙事 / Hero**                            | 全屏图+一句话（见 §5.3 b）、满版图+渐变蒙层（见 §5.1 a） | 标题 + 装饰小图 |

| **e** | 横向时间轴                       | 水平时间线贯穿，事件节点交替挂在上下方（上-下-上-下），配小图                                                                                                                                                                                                                                                                                                                                                                         | 发展历程、项目阶段                                |
| **f** | 纵向时间轴                       | 中轴线或左轴贯穿，节点均匀挂在轴侧，每节点跟事件卡                                                                                                                                                                                                                                                                                                                                                                                    | 长历程、详细年表                                  |
| **g** | 流程链                           | 3-6 个阶段横向排列，中间用箭头 / 曲线连接；下方一条"阶段输出条"；可用虚线表示循环或反馈                                                                                                                                                                                                                                                                                                                                               | 流程、机制、技术路线                              |
| **h** | 对比式                           | 左右两区（A vs B、Before / After、现状 / 目标），中间用竖线或 VS 分隔，两区高度严格对齐                                                                                                                                                                                                                                                                                                                                               | 方案对比、改造前后                                |
| **i** | 2×2 四象限矩阵                  | 横纵两条轴线切出四个象限，每象限一个标签 + 内容。或 2×3 扩展                                                                                                                                                                                                                                                                                                                                                                         | 分类框架、策略矩阵                                |
| **j** | 金字塔 / 层级                    | 底层宽、顶层窄的层级堆叠，每层一个标签 + 说明（也可以是阶梯式或同心圆）                                                                                                                                                                                                                                                                                                                                                               | 层级结构、递进关系                                |
| **k** | 漏斗                             | 上宽下窄的梯形分段，每段标转化率 / 数量                                                                                                                                                                                                                                                                                                                                                                                               | 转化流程、筛选过程                                |
| **l** | 数据展示（单图主图 或 多图看板） | 两种常用变体：①**单图主图 + 洞察文字**——一张主图占画面 55-65%，旁边或下方跟一段洞察，洞察里把关键数据加粗或改色。 但这里注意，尽量不要将一个多列多行表格占满一页，否则信息量太大，用户阅读困难且不美观。可考虑更美观的样式 ② **多图看板**——2-4 个图表 / KPI 组合排布（可大小不一），配简短洞察文字。主图占 50% 以上。**禁止**：所有图表同等大小均分（看不出主次）；图表旁没有一句洞察（这是信息板，不是分析） | 数据汇报、经营分析、研报数据页                    |
| **m** | 左标题色块 + 右内容              | 左侧窄栏（30-35% 宽）放主色色块 + 大标题 / 章节号 + 一行副标；右侧宽栏放主体内容——可以是长 KPI 列表、特征详述、分点说明、密集表格。两栏严格顶底对齐。有视觉主心骨，避免长列表无主次                                                                                                                                                                                                                                                 | 数据密集列表、财务报表、产品特征详述、长 KPI 列表 |

### 5.3 高潮页类（3 个候选，10 页以上至少 2 页）

| #           | 名字            | 风格描述                                                                                     |
| ----------- | --------------- | -------------------------------------------------------------------------------------------- |
| **a** | 巨型数字 + 洞察 | 一个巨大数字（72-120px 以上）占据主要位置，下跟一行说明。数字可微微错位。 其他区域可适当布局 |
| **b** | 全屏图 + 一句话 | 一张真实照片铺满，叠一行短句（衬线或手写字体），字下加微阴影                                 |
| **c** | 一句独白        | 整页纯色底 + 一段 2-3 行大字（40-60px），居中或偏一侧。像宣言、像结论                        |

### 5.4 过渡 / 章节页（3 个候选）

过渡页和章节页是"呼吸口"，不是内容页。

**硬约束：视觉要素 ≤ 3 个**，只保留：
① 章节编号 + 章节名
② 一段简洁概述（≤ 2 行 / 50 字内）
③（可选）一个纯装饰元素（细线 / 暗化大编号 / 一张主视觉图）

| #           | 名字            | 风格描述                                                             |
| ----------- | --------------- | -------------------------------------------------------------------- |
| **a** | 章节大字        | 超大章节序号（120-280px）占据画面，旁配章节名 + 一行简短说明。仪式感强 |
| **b** | 全屏图 + 章节名 | 一张相关主视觉铺满，章节名压在留白处或底部横条上                     |
| **c** | 极简章节条      | 浅色底 + 居中的章节编号 + 章节名 + 一条细分隔线。克制、快节奏        |

### 5.5 结尾页（3 个候选）

除非用户明令禁止，不然ppt 一般都需要有结尾页

| # | 名字                  | 风格描述                                                                                       |
| - | --------------------- | ---------------------------------------------------------------------------------------------- |
| a | 满版图 + 渐变蒙层收尾 | 整页一张收尾图 + 由底向上的深色渐变蒙层，底部放一行告别文字 / 联系方式。有电影片尾式的告别感。 |
| b | 收束金句 + 落款       | 一句总结性大字居中，下方落款（单位 / 汇报人 / 日期）。周围留白                                 |
| c | 名片式                | 左半"Thanks" / "Q&A" 大字，右半列联系方式（邮箱、电话、二维码）                                |

**禁止**：只写"谢谢"占一整页——浪费。

### 5.6 目录页类（5 个候选）

| # | 名字                  | 风格描述                                                                                                                                                                                                                           |
| - | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **a** | 经典纵排              | 左上大字 "目录 / CONTENTS" + 一条贯通内容区的细线。章节清单竖排：编号 + 章节名 + 页码三列对齐。整页以一条线作为视觉锚点，大量留白                                                                                                     |
| **b** | 左右不对称杂志式      | 左 1/3 大字 "目录 CONTENTS" + 篇名 / 日期小字；右 2/3 竖排章节清单                                                                                                                                                                   |
| **c** | 大编号主导            | 超大编号（80-120px Bold）横排 3-5 个，下方跟小字章节名                                                                                                                                                                               |

**目录页通用倾向**：

- 只列章节清单（编号 + 章节名 + 页码），不写每章简述
- 章节数 ≥ 4 时才做独立目录页，≤ 3 章可并入封面或省略
- 留白主导，不堆箱子（不用卡片容器 / 行底色填充）

## 六、怎么选与组合

一份 deck 的页面从上面的候选池里挑，不是每组都必须用。

**几条原则**：

1. **至少 1-2 页高潮**。10 页以上建议 2-3 页。高潮页（§5.3）是全篇的记忆点，位置建议：中段 1 页 + 结尾前 1 页
2. **避免同类布局连用**。两页内容不要都用"左图右文"，两页数据不要都用"数据看板"——节奏感来自对比
3. **优先挑复杂 / 不规则候选**。除非本页是信息密集的查读任务（长表格、详细清单）
4. **素材决定上限**。有真实大照片 → 用全屏视觉、拼贴、左图右文；没照片 → 走大字报、巨型数字、极简章节条
5. **母版要稳定**。封面 / 章节过渡 / 结尾页可以自由发挥，但**内容页之间**的标题位置、页码位置、配色、字体必须保持一致

**配图规则**（兜底场景同样适用）：

- 承担叙事的**主视觉（L1）按宿主规则获取：真实对象用真实照片，创意场景优先生图**，不要用 SVG 代替具象场景（城市、办公室、人物、产品）
- **允许 SVG**：流程图、时间轴、矩阵、漏斗、架构图、关系网络、巨型数字、图表底图等结构化 / 低语义元素
- 全篇视觉类型统一（同为摄影 / 同为插画 / 同为 3D），禁止混用
- 素材落到 `assets/` 后首次核对并记录再引用，未变化的同图复用已有核对记录（返回顺序常与 prompt 顺序错位）

## 七、完成检查

- 全篇是不是**同一套配色、同一套字体**？有没有中途换风格？
- 有没有**至少 1-2 页高潮页**？整篇是否有起伏节奏？
- 每页有没有**视觉锚点**（超大字号 / 大图 / 大色块）？还是所有元素趋近中间大小？
- 相邻两页有没有重复用同一类布局？
- 内容页的标题位置、页码位置是否稳定？
- **每块有没有一眼可见的结论**（见 `design-principle.md` §1.2）？
- 有没有陷入均分构图（等宽三栏、等大卡片网格）？
- 有没有配图位置错乱、文字溢出、对比度不足？
- **非对称版式占比**是否 ≥ 40%？整篇是否有足够的视觉张力？
