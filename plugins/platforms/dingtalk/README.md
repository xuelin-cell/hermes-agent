# 钉钉插件：本地图片和文件发送

本轮是消息平台阶段三的钉钉交付。代码、测试与本说明全部位于 `plugins/platforms/dingtalk/`；不修改 Hermes 核心、其它平台、桌面 UI 或目录外的总计划。

## 当前能力

- `send_image_file` 上传本地图片，以 `sampleImageMsg` 投递；`send_document` 以 `sampleFile` 投递原文件。
- 复用本适配器已有的 HTTP 客户端、机器人配置及 Stream SDK 缓存 Token，不新增凭据表、全局 Token 缓存、SDK 依赖或上传地址设置。
- 单聊使用原始入站消息的 `senderStaffId`；群聊使用 `conversationId` 作为 `openConversationId`。上下文缺失或不匹配时先拒绝，不拿桌面会话 ID、加密 `senderId` 或页面传入的元数据猜测目标。
- 复用原版附件路径安全策略。文件在线程中有界读取，单个文件保守限制为 **20,000,000 字节**，不执行、不改写源文件；不自动压缩、改格式或伪造扩展名。平台自身的格式和大小限制仍可能更严格。
- `file_name` 仅改变附件显示名，去掉目录部分；中文名称保留。图片、文件附带的说明文字继续走现有文字发送，附件失败不因此丢弃说明。附件成功但说明失败时明确报告部分成功，不重传附件。
- 取 Token 等待上限 15 秒，上传和投递分别使用 60 秒、20 秒 HTTP 超时。不跟随重定向、不在异常后自动重复投递，也不切换其它消息类型或外部云存储作为隐式回退。
- 同时检查 HTTP 状态、业务错误、无效／限流员工列表和 `processQueryKey` 回执。上传得到 `media_id` 不等于发送完成；缺少回执、权限拒绝及超时均不会报告成功。返回错误不包含原始响应正文、Token 或本机路径，日志继续使用 Hermes 原有脱敏机制。

原有 Stream 接收、文字、远程图片链接、AI 卡片、等待反馈与会话行为保留。此能力用于**在线 Stream 适配器已收到消息的会话回复**；没有新增重启后持久化收件人映射，也没有扩展独立静态 Webhook 的附件能力。

**桌面 `send_message` 工具的跨平台主动附件发送不在本轮接通范围。** 原版 `tools/send_message_tool.py` 将钉钉放在文本发送路由，附件会被拒绝或明确省略；只替换钉钉适配器方法不会改变该路由。本轮没有修改核心白名单、注入猴子补丁或声称这一工具入口已经支持附件。钉钉入站消息所触发的普通回复走原版网关附件分发，不经过这条独立工具路由。

## 协议依据与实测边界

- [钉钉媒体上传接口](https://open.dingtalk.com/document/orgapp/upload-media-files)：multipart 字段 `media`，返回的 `media_id` 原样用于后续投递。
- 已核对仓库锁定的 `dingtalk-stream 0.24.3` 与 `alibabacloud-dingtalk 2.2.42`：复用前者的 Token 获取／缓存；后者的 `BatchSendOTO`、`OrgGroupSend` 请求及响应模型用于核对消息字段、发送地址和回执，不要求配置 AI 卡片。
- 用户指定的参考分支 `feat/postgresql-multitenant @ a0f5c5c` 同样采用媒体上传后通过单聊／群聊接口投递的路线；不搬入其 worker、调度或会话实现。

图片使用 `sampleImageMsg` 的 `photoURL` 字段承载上传返回的媒体 ID，与上述参考分支一致。**受控测试只能证明请求格式、成功／失败传播和原文件上传，不能证明真实钉钉客户端已正确渲染图片，也不能证明某个企业应用的 Token 已获附件发送权限。** HTTP 回执表示平台接受请求，不等于用户已经收到或读取。

企业应用若实际返回机器人不存在、权限不足或格式拒绝，本插件会明确失败；本轮不宣称解决所有服务端授权限制。不自动把图片改成文件或上传到公共文件托管服务。

其它平台没有改动；企业微信现有语音转写路径保留，本轮没有真实平台语音验证，也不会因为缺少测试凭据就删掉它。

## 自动化检查

使用独立 PM 测试解释器，在仓库根目录执行：

```powershell
$env:HERMES_PYTHON='<独立测试环境>/Scripts/python.exe'
& 'X:/download/Git/bin/bash.exe' --noprofile --norc scripts/run_tests.sh `
  plugins/platforms/dingtalk/tests `
  tests/gateway/test_dingtalk.py `
  tests/gateway/test_dingtalk_reconnect_circuit_breaker.py `
  --file-timeout 180
```

测试按本轮目录限制随插件存放，因此需显式传入该目录；没有更改仓库默认 CI 测试发现范围。

新增检查先在旧实现上复现图片／文件不支持的失败，再核对正式发送入口、原版附件分发、插件发现、A→B→A 凭据隔离、文件限制、重定向、业务拒绝、超时与部分成功。真实本机 HTTP 检查实际经过 SDK 取 Token、缓存、multipart 字节传输和 JSON 投递；仅将固定官方地址替换成随机本地测试服务，不调用真实钉钉或模型。

2026-10-19 本机结果：新增 35 项、既有钉钉与断线恢复 31 项，合计 **66 项通过**。独立测试解释器由 PM 构建；Python 编译、Ruff 和 `git diff --check` 通过。没有真实短信、消息平台收发或付费模型调用。

## 用户实机验收

请先重启开发版，让旧网关退出并加载新版插件。使用测试私聊和测试群，不发送敏感文件；模型生成文件可能计费。

1. 从钉钉私聊机器人发送一句话，确认原有文字回复正常。
2. 明确让 Hermes 生成一个小 PDF／已有支持格式文件并以附件发回，确认收到可下载的文件，打开后内容正确，而不只是本机路径或“发送成功”的文字。
3. 让 Hermes 发回一张已生成的小 PNG／JPG，确认实际能显示／打开图片；不能以平台 HTTP 回执代替这一步。
4. 在已加入该机器人的测试群重复附件与图片检查，沿用原有 @ 设置，确认发送位置正确，私聊不串到群聊。
5. 附件带说明时检查文字是否保留；不要为了验收而修改有效 Secret。遇到超时先检查目标会话，不立即重复请求，避免用户手动制造重复附件。
6. 如有两个测试账号，使用不同机器人执行 A→B→A，核对附件归属；不让两个账号抢同一个机器人。

真实平台收发、图片渲染、企业权限、客户端文件格式及真实账号隔离尚待以上人工验证。未制作安装包，未修改官方对照版、用户历史或目录外源码。
