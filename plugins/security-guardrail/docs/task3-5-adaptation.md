## 关键实现决定

1. 宿主先运行原有参数改写和执行中间件，再给最终 Hook 只读快照。注册表兜底不能替代深层准备；文件、补丁、终端、网页规范化在各自准备位置检查。已知“pre_tool_call 后改路径”用例由 XFAIL 变为正常通过。
2. 文件写入跟随内容目标；删除/移动检查目录项，移动检查两端。整批补丁先判断全部目标，再进入编辑。普通文件 Move→Update 保留；Move 链接后再操作其影响路径不能从初始磁盘状态可靠授权，因此整批拒绝，拆为两次调用后各自重新解析。
3. cwd 是当前执行位置，workspace_root 是会话注册/配置工作区。持久 cwd 记录不改变工作区边界。最终执行目录单独传递，保留 workdir 原有“仅本次使用”的含义。
4. Windows Bash 的 `/c/...` 等盘符路径先通过宿主路径能力规范化；已有链接别名解析到真实目标。纯规则引擎不会自行读取宿主。未知远端、虚拟根等不猜测成本机。
5. 初始 env.env 不是 Bash 持久 snapshot 中的最终环境。当前终端检测不使用初始 HOME 等展开脚本，缺少事实即拒绝，字面路径仍可检查。此项是显式能力限制，不登记为已等价放行。
6. ASK 在最终 Hook 回调结束后进入 Hermes 原生审批，避免被策略回调超时截断。宿主再次把最终输入/作用域加入散列授权键；插件加入策略、模式及已读取脚本内容摘要。消息仅含规则 ID/静态原因，不含匹配到的秘密或原始命令。
7. web_extract 先使用宿主自己的 URL 规范化，再检查实际 URL；保留 WebBatchFetch 原批次用户规则，同时逐个 WebFetch 做硬拒绝检查。浏览器在本地/云路由前检查规范化 URL。重定向和其他浏览器交互不由此自动覆盖。
8. execute_code 不映射 Bash。按未知执行字段拒绝属于当前保守处理；不能计为 Python 分析能力。无等价宿主入口保留内部 API 并登记，不新造核心工具凑覆盖数。
